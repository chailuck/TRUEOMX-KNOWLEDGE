# Request_CCBS_RESOLVE_SOC_CODE

CCBS Offer Name → SOC Code Resolution with GoldenDB Dual-Path Dispatch

---

## §1 — Overview & Purpose

This rule fires when the order reaches `ActivityID = CCBS_RESOLVE_SOC_CODE` and status `WAITING`. It resolves offer **names** to SOC **codes** for any offer that has an `OfferName` set but a blank `Soc` field — across Agreement offers, SubscriberOffers, and RelatedOffersArrays at all hierarchy levels.

> **Key distinction from CCBS_GOD:** CCBS_GOD collects SOC codes (already known) to fetch product catalog details. CCBS_RESOLVE_SOC_CODE collects *offer names* where the code is still unknown and asks CCBS to return the matching SOC code. This step must run after CCBS_GOD has populated SocProperties to allow the NextPricePlan lookup.

> **Dual dispatch path — GoldenDB gate:**
> - **Path A (GoldenDB=Y):** Sends `CES_RESOLVE_SOC_CODE` event — routes to CES/GoldenDB service. The event element carries an `extId` attribute generated by `OMXUtils:generateTrackingID()`.
> - **Path B (standard):** Sends `CCBS_RESOLVE_SOC_CODE` event — routes to CCBS. No extId attribute on event element.
>
> Both paths use the same payload: `ns:ResolveSocCodeRequest` with N × `ns:SocName`.

> ⚠ **Resubmission awareness:** Before adding an offer to the batch, the rule checks `orderCurrentActivity.Response[]` for an existing entry with matching `ReferenceId` and `CompletionStatus==2`. If found, the offer is skipped (already resolved in a prior attempt).

## §5 — Execution Flow

1. **Init** — `isActResub = (RequestCount>0 && IsOrderResubmitted)`; init `arrLstSOCs = createArrayList()`
2. **ParentOU Agreement Offers** — filter: `!IsBlankOrStringNull(OfferName) && IsBlankOrStringNull(SocCode)`; run per-offer PreExecCheck via `GetXMLForAgreementOffer`; check resubmission guard; add `OfferName` to list. Then scan `RelatedOffersArray` with `GetXMLForAgreementRelatedOffer` + same guard. Then check NextPricePlan from SocProperties.
3. **ParentOU SubscriberOffers** — filter + PreExecCheck via `GetXMLForSubscriberOffer`; resubmission guard; add name. RelatedOffersArray via `GetXMLForSubscriberRelatedOffer`. NextPricePlan check.
4. **ChildOU Agreement + SubscriberOffers** — same as steps 2–3 using ChildOU helper variants
5. **GoldenDB Gate** — if `SocNames` list non-empty:
   - Path A (GoldenDB=Y): send `CES_RESOLVE_SOC_CODE` with event extId
   - Path B (standard): send `CCBS_RESOLVE_SOC_CODE` without event extId
6. **RequestCount** — if `!isActResub`: `RequestCount++` (always 1)
7. **Status** — if sent → IN_PROGRESS; if nothing collected → SKIPPED
8. **Exception** → HandleActivityException → ERROR

## §6 — Rule Action (THEN) — Key Logic

### Offer Collection Filter

```java
// Include only offers where name is known but code is missing
if(!BRMS.IsBlankOrStringNull(SocName) && BRMS.IsBlankOrStringNull(SocCode)) {
    // Agreement-level short-circuit:
    if(orderCurrentActivity.Response@length == 0) {
        if(!Collections.contains(arrLstSOCs, SocName)) Collections.add(arrLstSOCs, SocName);
    } else {
        // Check if this offer was already successfully resolved (resubmit guard)
        for(int iResp=0; iResp < orderCurrentActivity.Response@length; iResp++) {
            if(Response[iResp].ReferenceId == refId && Response[iResp].CompletionStatus == 2)
                reqSuccess = true;
            if(!reqSuccess) { Collections.add(arrLstSOCs, SocName); break; }
        }
    }
}
```

### NextPricePlan Inclusion

```java
// Run AFTER primary offer check (regardless of primary filter result)
String nxtPPName = RuleFunctions.Helpers.GetNextPricePlan(socProps);
if(!BRMS.IsBlankOrStringNull(nxtPPName)) {
    // Only include if GOD hasn't already returned the SocCode for this name
    if(BRMS.IsBlank(RuleFunctions.Helpers.GetSocCodeInGodBySocName(orderRequest, nxtPPName))) {
        if(!Collections.contains(arrLstSOCs, nxtPPName))
            Collections.add(arrLstSOCs, nxtPPName);
    }
}
```

### GoldenDB Dispatch Gate

```java
Object[] SocNames = Collections.toArray(arrLstSOCs);
if(SocNames != null && Collections.size(arrLstSOCs) > 0) {
    if(!BRMS.IsBlankOrStringNull(orderRequest.OrderData.GoldenDB)
       && String.equals("Y", orderRequest.OrderData.GoldenDB)) {
        // Path A — CES/GoldenDB (event has extId attribute)
        Events...CES_RESOLVE_SOC_CODE reqEvent = Event.createEvent("xslt://CES_RESOLVE_SOC_CODE"...);
    } else {
        // Path B — standard CCBS (no extId on event element)
        Events...CCBS_RESOLVE_SOC_CODE reqEvent = Event.createEvent("xslt://CCBS_RESOLVE_SOC_CODE"...);
    }
    Event.Ext.sendEventImmediate(reqEvent);
    isSkipped = false;
}
```

## §17 — Migration Notes & Recommendations

### Functional Requirements

- **R1** — Collect all offer names where `OfferName ≠ blank AND SocCode = blank`, across all hierarchy levels.
- **R2** — Run per-offer PreExecCheck including for related offers using new 4-param helper signatures.
- **R3** — Check resubmission guard: skip offers already in `Response[].ReferenceId` with `CompletionStatus=2`.
- **R4** — Include offer names for "next price plan" entries from SocProperties where GOD has no code.
- **R5** — Dispatch to CES (GoldenDB=Y) or CCBS (standard). CES request includes event-level extId.
- **R6** — Single batch dispatch; RequestCount always = 1.
- **R7** — Response: for each `ResolveSocCode[m]`, match offers by `OfferName == SocName` and write `Soc = SocCode`.
- **R8** — Response: inject `ServiceType` from `Parameter["SERVICE_TYPE"]` to matching subscriber/related offers (only when SocCode is not written — see continue).
- **R9** — Fan-in: `RequestCount == Response@length` — always 1:1.

### Design Risks

| Risk | Severity | Mitigation |
|------|----------|-----------|
| NextPricePlan depends on SocProperties already populated by CCBS_GOD | [HIGH] | Ensure CCBS_GOD always runs before CCBS_RESOLVE_SOC_CODE in ProcessConfig |
| GoldenDB path produces different event correlation (CES extId vs no extId in CCBS) | [MEDIUM] | Both paths use same CCBSResolveSocCodeRes concept — verify correlation |
| O(n²) write-back: for each of M resolved codes, scans all offers at all levels | [MEDIUM] | Build a name → positions map before write-back loop |
| Related offer PreExecCheck requires 4th param (relatedRefId) — new helper signature | [MEDIUM] | Port all 4 new helper functions with their additional parent-context parameter |
| `continue` after Soc write skips ServiceType for that offer (mutually exclusive per position) | [LOW] | Ensure migration preserves this mutual exclusivity behavior |
| `CompletionStatus==2` as success code — magic number | [LOW] | Document that CompletionStatus=2 means SUCCESS; verify against CCBS schema |

## §19 — Response Message Rule

### §19.1 — Overview

`RuleFunctions.OrderResponse.Response_CCBS_RESOLVE_SOC_CODE` receives the CCBS/CES response and:

1. Creates `CCBSResolveSocCodeRes` concept with base response fields + a `ResolveSocCode[]` array
2. Looks up `SERVICE_TYPE` from currActivity.Parameter
3. For each resolved pair (SocName → SocCode), scans ALL offer positions and writes `Soc` and optionally `ServiceType`
4. Sends response audit log
5. Returns `"true"` when `RequestCount == Response@length`

### §19.2 — Scope Variables

| Variable | Type | Role |
|----------|------|------|
| `orderRequest` | `Concepts.OrderRequest.OrderRequest` | Written back with resolved Soc codes and ServiceType |
| `eventResponse` | `Events.OMConsumers.OMXFM.Response.CCBS_RESOLVE_SOC_CODE` | Contains ResolveSocCodeResponse/ResolveSocCode[] array |
| `currActivity` | `Concepts.OM.ProcessConfig.Activity` | Response[] appended; Parameter["SERVICE_TYPE"] read |

### §19.4 — Response Completion Logic

```java
// Fan-in completion: always 1 request sent, 1 response expected
if(currActivity.RequestCount == currActivity.Response@length)
    return "true";  // always true after first response
else
    return "false";
```

### §19.5 — Write-back Scope (All Offer Levels)

| Offer Position | Match By | Writes Soc | Writes ServiceType |
|---------------|----------|-----------|------------------|
| ParentOU Agreement Offers | `OfferName == socName` | Yes | No |
| ParentOU Agreement RelatedOffers | `OfferName == socName` | Yes | No |
| ParentOU SubscriberOffers | `OfferName == socName` | Yes | If SERVICE_TYPE ≠ blank |
| ParentOU Sub. RelatedOffers | `OfferName == socName` | Yes | If SERVICE_TYPE ≠ blank |
| ChildOU Agreement Offers | `OfferName == socName` | Yes | No |
| ChildOU Agreement RelatedOffers | `OfferName == socName` | Yes | No |
| ChildOU SubscriberOffers | `OfferName == socName` | Yes | If SERVICE_TYPE ≠ blank |
| ChildOU Sub. RelatedOffers | `OfferName == socName` | Yes | If SERVICE_TYPE ≠ blank |

> ⚠ `continue` statement after Soc write skips the ServiceType write for that offer — they are mutually exclusive within the same block. ServiceType is only written if SocCode was not written (blank in the response entry).
