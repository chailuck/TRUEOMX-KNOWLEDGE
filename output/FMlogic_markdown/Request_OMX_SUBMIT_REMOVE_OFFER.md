# Request_OMX_SUBMIT_REMOVE_OFFER

> Submits a child remove-offer order to the OMX SubmitOrder service per subscriber, targeting IR offers (REMOVE_PACK). ORDER_TYPE and SERVICE_TYPE driven by activity parameters.

**Backend:** OMX SubmitOrder (Child Order — IR Remove) | **Fan-out:** POU + COU subscribers | **Event:** OMX_CREATE_CHILD_ORDER | **Author:** DESKTOP-995HR2V | **Lines:** 135 | **Step:** 84 | **forwardChain:** true

---

## §1 — Overview & Purpose

Submits a child order to the OMX SubmitOrder service to remove IR (International Roaming) offers per subscriber. Uses the same `OMX_CREATE_CHILD_ORDER` event and fan-out structure as `OMX_SUBMIT_POSTPAID_ADD_BENEFIT`, but targets FE offers with a non-empty `REMOVE_PACK` ExtendedInfo key, and takes two activity parameters: `ORDER_TYPE` and `SERVICE_TYPE`. Contains multiple copy-paste logger bugs where OPERATION_NAME references a different FM.

| Attribute | Value | Notes |
|-----------|-------|-------|
| Backend event | `Events.OMConsumers.OMXFM.Request.OMX_CREATE_CHILD_ORDER` | Internal OMX child order (IR remove) |
| Schema NS (ns) | `http://services.omx.truecorp.co.th/SubmitOrder` | SubmitOrder service payload |
| Payload root | `ns:submitOrderRequest` | |
| Fan-out | POU direct subscribers first, then COU subscribers | POU→Sub, then POU→COU→Sub |
| RefID | Subscriber RefId (bare) | Always emitted |
| childIndex | Monotonic counter (POU+COU combined) — increments before resub guard | Computed but NEVER used in orderId |
| orderId | `concat("IR_", OrderID)` | SAME for all subscribers — NOT unique |
| ORDER_TYPE | From activity parameter `ORDER_TYPE` | → `ns:orderType` |
| SERVICE_TYPE | From activity parameter `SERVICE_TYPE` | → `ns:serviceType` inside offer (overrides per-offer ServiceType) |
| channel | `Channel` (no "-OMX" suffix) | Different from OMX_SUBMIT_POSTPAID_ADD_BENEFIT |
| Offer filter | FE_OR_CCBS="FE" AND ExtendedInfo[REMOVE_PACK] != "" | IR removal offers |
| IR_DMC_TRX_ID | Conditional ExtendedInfo | Emitted when string-length > 0 |
| ns:subscriberGeneralInfo | Always emitted as empty element | No children |
| PurgePendingRequestsBeforeResubmit | ABSENT | |
| Response concept | `Concepts.FM.Response.OMX_CreateChildOrder` | Same as OMX_SUBMIT_POSTPAID_ADD_BENEFIT; captures childOmxTrackingId |
| Fan-in | RequestCount == successResponseCount (suffix "000") | Standard count-match |

> **[HIGH]** `orderId = concat("IR_", OrderID)` is IDENTICAL for all subscribers. `childIndex` is computed but never used. If multiple subscribers are processed, all child orders share the same orderId.

> **[HIGH]** Request audit logger `OPERATION_NAME = "OMX_SUBMIT_POSTPAID_ADD_IR"` (wrong — should be `"OMX_SUBMIT_REMOVE_OFFER"`). Both POU and COU logger blocks have this bug.

> **[HIGH]** Response audit logger `OPERATION_NAME = "OMX_SUBMIT_POSTPAID_ADD_BENEFIT"` (wrong — should be `"OMX_SUBMIT_REMOVE_OFFER"`).

> **[MEDIUM]** `PurgePendingRequestsBeforeResubmit` absent. Duplicate child orders on resubmit are possible.

## §5 — Execution Flow

1. **Init:** `isActResub` = (RequestCount > 0 && IsOrderResubmitted). Read `order_type` (ORDER_TYPE) and `service_type` (SERVICE_TYPE). `isSkipped = true`. `childIndex = 0`.
2. **POU subscriber loop** (POU p → Sub ps): `childIndex++` (before resub guard). Resub guard. PreExecCheck. Send `OMX_CREATE_CHILD_ORDER` with `orderId = concat("IR_", OrderID)`. RequestCount++ if !isActResub. Logger (wrong OPERATION_NAME). isSkipped = false.
3. **COU subscriber loop** (POU p → COU c → Sub cs): same — `childIndex++` first. PreExecCheck = GetXMLForSubscriberInChildOU. Same orderId = `concat("IR_", OrderID)`. Logger (same wrong OPERATION_NAME).
4. **Completion:** if (!isSkipped) → Status = GetActivityStatusString("1", false); SendDataToDB. Else → SkipActivity("4").
5. **Exception:** catch(Exception ae) → HandleActivityException(orderRequest, orderCurrentActivity, ae, "")

## §9 — Detailed Payload Build

### §9.1 Activity Parameters

| Parameter Key | Variable | Effect |
|---------------|----------|--------|
| ORDER_TYPE | `order_type` | → `ns:orderType` — the type of remove-offer child order |
| SERVICE_TYPE | `service_type` | → `ns:serviceType` inside every `ns:offers` block — overrides per-offer ServiceType |

### §9.2 orderId — Non-Unique Bug

```text
ns:orderId = concat("IR_", OrderID)
```

This is IDENTICAL for all subscribers. Example: three subscribers all get `IR_ORD-123`. `childIndex` is computed (0→1→2→…) but is unused in the orderId construction.

### §9.3 Offer Filtering & IR_DMC_TRX_ID

| Filter | Value |
|--------|-------|
| Offer selector | `SubscriberOffers[FE_OR_CCBS="FE" AND ExtendedInfo[REMOVE_PACK] != ""]` |
| ns:offerName | `ExtendedInfo[Name="REMOVE_PACK"]/Value` — the pack name to remove |
| ns:serviceType | `$service_type` (SERVICE_TYPE activity parameter) — same for all offers |
| ns:ExtendedInfo[IR_DMC_TRX_ID] | `ExtendedInfo[Name="IR_DMC_TRX_ID"]/Value` — only when string-length > 0 |

## §10 — XSLT Field Mapping — Output XML Tree Hierarchy

Two XSLT variants: POU (`psub`, `pSubRefId`) and COU (`csub`, `cSubRefId`). Identical structure; subscriber reference differs.

```text
createEvent
└── event
    ├── JMSPriority           ← $orderRequest/OrderPriority                             [Conditional]
    ├── JMSCorrelationID      ← $orderRequest/OrderData/OMXTrackingId                   [Conditional]
    ├── OrderID               ← $orderRequest/OrderData/OrderID                         [Conditional]
    ├── RefID                 ← $pSubRefId / $cSubRefId                                 [Always]
    ├── OrderType             ← $orderRequest/OrderData/OrderType                       [Conditional]
    └── payload
        └── ns:submitOrderRequest
            ├── ns:Order
            │   ├── ns:channel    ← $orderRequest/OrderData/Channel (raw — no "-OMX")  [Always]
            │   ├── ns:orderId    ← concat("IR_", OrderID)  [Always — SAME for all ⚠]
            │   └── ns:orderType  ← $order_type (ORDER_TYPE activity param)             [Always]
            └── ns:Customer
                └── ns:OU
                    └── ns:subscriber [for-each: $psub/$csub]
                        ├── ns:activityInfo
                        │   ├── ns:activityReason ← SubscriberActivityInfo/ActivityReason [Conditional]
                        │   └── ns:userText       ← SubscriberActivityInfo/UserText       [Conditional]
                        ├── ns:offers [FE_OR_CCBS="FE" AND REMOVE_PACK != "" — loop]
                        │   ├── ns:offerName  ← ExtendedInfo[REMOVE_PACK]/Value           [Conditional]
                        │   ├── ns:serviceType← $service_type (SERVICE_TYPE param)        [Always]
                        │   └── ns:ExtendedInfo [name="IR_DMC_TRX_ID" — string-length>0]
                        │       ├── ns:name  ← "IR_DMC_TRX_ID"                           [Always if block fires]
                        │       └── ns:value ← ExtendedInfo[IR_DMC_TRX_ID]/Value         [Always if block fires]
                        ├── ns:subscriberGeneralInfo                                       [Always — EMPTY]
                        └── ns:subscriberNumber ← MSISDN                                  [Conditional]
```

**Legend:** `[Always]` = unconditional | `[Conditional]` = inside `xsl:if` | ⚠ = Known bug

## §17 — Migration Notes & Recommendations

### Functional Requirements

| Ref | Requirement |
|-----|-------------|
| R1 | Fan-out: POU direct subscribers first, then COU. One child order per subscriber. |
| R2 | orderId = concat("IR_", OrderID) — as coded. Verify with SubmitOrder team; likely a bug (should include childIndex or RefId for uniqueness). |
| R3 | ORDER_TYPE and SERVICE_TYPE are both required activity parameters. |
| R4 | channel = raw Channel (no "-OMX" suffix). |
| R5 | Offer filter: FE_OR_CCBS="FE" AND ExtendedInfo[REMOVE_PACK] non-empty. offerName = REMOVE_PACK value. |
| R6 | serviceType in offers = SERVICE_TYPE activity parameter. |
| R7 | IR_DMC_TRX_ID ExtendedInfo emitted when non-empty. |
| R8 | ns:subscriberGeneralInfo always emitted as empty element. |
| R9 | Fan-in: RequestCount == successResponseCount (suffix "000"). |
| R10 | Response captures childOmxTrackingId from submitOrderResponse payload. |

### Design Risks

| Risk | Severity | Mitigation |
|------|----------|-----------|
| orderId = concat("IR_", OrderID) — same for all subscribers; childIndex unused | [HIGH] | Change to concat("IR_", OrderID, "-", childIndex); confirm with SubmitOrder team |
| Request logger OPERATION_NAME = "OMX_SUBMIT_POSTPAID_ADD_IR" (wrong) | [HIGH] | Fix both POU and COU logger to use "OMX_SUBMIT_REMOVE_OFFER" |
| Response logger OPERATION_NAME = "OMX_SUBMIT_POSTPAID_ADD_BENEFIT" (wrong) | [HIGH] | Fix response rulefunction logger |
| PurgePendingRequestsBeforeResubmit absent | [MEDIUM] | Add if SubmitOrder is not idempotent |
| childIndex increments before resub guard | [MEDIUM] | Move after resub guard, or derive orderId from RefId |

## §19 — Response Message Rule (Response_OMX_SUBMIT_REMOVE_OFFER)

### §19.1 Overview

Identical response concept and XSLT to `Response_OMX_SUBMIT_POSTPAID_ADD_BENEFIT`. Uses `Concepts.FM.Response.OMX_CreateChildOrder`. Captures `childOmxTrackingId`. The only difference is the logger bug: `OPERATION_NAME = "OMX_SUBMIT_POSTPAID_ADD_BENEFIT"` instead of `"OMX_SUBMIT_REMOVE_OFFER"`.
