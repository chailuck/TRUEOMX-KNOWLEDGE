📋 §1 Overview & Purpose

This rule handles the AA_ACTIVATE_SUBS_MSIM activity — a MultiSIM-specific variant of the AA subscriber activation flow. It iterates over each ParentOU/Subscriber pair in the order request and, for any subscriber carrying a MultiSIMInfo object, sends one AA_ACTIVATE_SUBS JMS request per SIM card (one for the Master SIM and one per Minor SIM), subject to provisioning eligibility checks.


The rule constructs the full ns:ActivateSubscriberRequest payload via an embedded XSLT stylesheet (two variants: Master and Minor), enriches it with MultiSIM AA feature tags (via ExtendAATagWithMultiSIM), and emits an audit log entry per message sent. After all messages are dispatched it advances the activity status to IN_PROGRESS. If no SIM qualifies (all skipped), the activity is moved to SKIPPED status.

🔍 §4 Rule Conditions (WHEN)

All four conditions must be true simultaneously for the rule to fire:


#Condition ExpressionMeaning
1orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityNameThe activity in working memory matches the next activity pointer in the order's process flow
2orderCurrentActivity.ActivityID == "AA_ACTIVATE_SUBS_MSIM"Selects only the MultiSIM activation activity (not generic AA_ACTIVATE_SUBS)
3orderRequest.ProcessFlow.NextActivityID == "AA_ACTIVATE_SUBS_MSIM"Double-checks the order's process flow pointer also targets this specific activity ID
4orderCurrentActivity.Status == "WAITING"Activity must be in WAITING state — prevents re-firing once IN_PROGRESS or completed

Conditions 2 and 3 together ensure no cross-firing with AA_ACTIVATE_SUBS (non-MultiSIM variant). Condition 4 is the idempotency gate.

⚡ §6 Rule Action (THEN) — Step-by-Step Logic
Phase 1 — Initialization
  1. Compute resub flag: isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted).
  2. Declare cleanup variables: swfRes (AA_SwitchFeatureRes), fListRes (AASwitchFeatureList).
  3. Open try block.
  4. Look up nextAct by orderRequest.ProcessFlow.NextActivityName extId from the ProcessConfig concept cache.
  5. Look up sfRes by OMXTrackingId + ":SWITCHFEATURELIST" extId (pre-fetched switch feature response).
Phase 2 — Parameter Validation & Extraction
  1. Guard: if Parameter@length < 2 throw DATA_ISSUE exception.
  2. Extract tp = String.left(Parameter[0], 3) — transaction type code (e.g., NAC, SSP, DSD).
  3. Extract action = Parameter[1] — ADD or REMOVE.
  4. Extract param = XPath.evalAsString("…$orderCurrentActivity/Parameter[3]…") — SOURCE or TARGET.
  5. Set isSkipped = true.
Phase 3 — Subscriber Iteration
  1. Outer loop: for p in 0..pOULen iterating orderRequest.OrderData.Customer.ParentOU.
  2. Inner loop: for ps in 0..pSubLen iterating ParentOU[p].Subscriber.
  3. If Subscriber[ps].MultiSIMInfo == null → continue.
  4. Bind local references: agreementInstance, subscriberInstance, multiSimInfo.
  5. Compute isCustomerHybrid via XPath: account AccountSubType starts with "HY" or equals "PHI" (checks both AgreementRefId and AccountRefId paths).
  6. Compute pp: current offer name from SubscriberOffers or Agreement/Offers where ServiceType=80 and FE_OR_CCBS=FE (fallback to CCBS).
  7. Compute prev_pp: offer name from CCBS offers only.
  8. Compute tmpBCN: if param=="SOURCE" and SOURCE_BILL_CYCLE ExtendedInfo exists, use it; else use BillCycleNo.
  9. Convert: billCycleNo = RuleFunctions.Helpers.ConvertBillCycleDate(tmpBCN).
  10. Compute provMaster = ProvMultiSIM(subscriberInstance, "MASTER", tp, action).
  11. Compute provMinor = ProvMultiSIM(subscriberInstance, "MINOR", tp, action).
Phase 4 — Master SIM Request
  1. If multiSimInfo.Master != null && provMaster: set refId = Master.IMSI.
  2. Scan Response[] for already-succeeded entry (CompletionStatus==2, ReferenceId==refId); if found skip.
  3. If PreExecCheck non-empty: evaluate conditional gate; if result != "true" skip.
  4. Call ProcessSwitchFeatures().
  5. Call ExtendAATagWithMultiSIM(aaXML, multiSimInfo, 0, "", orderType, tp, action).
  6. If tp=="SSP": update Master.IMSI = XPath(NEW_IMSI or IMSI resource).
  7. Create and send AA_ACTIVATE_SUBS event (XSLT Variant ①).
  8. Capture pid = System.nanoTime(); send ESB Logger event.
  9. If !isActResub: increment orderCurrentActivity.RequestCount.
  10. Set isSkipped = false.
Phase 5 — Minor SIM Loop
  1. If multiSimInfo.Minor != null && provMinor: loop for pmi in 0..pMinorLen.
  2. Set refId = Minor[pmi].IMSI; check idempotency against Response[] (same as Master).
  3. Evaluate PreExecCheck with "MINOR" filter context.
  4. If isActResub && action=="REMOVE": UpdateMinorStatus(…, true) resets to FE status.
  5. Lookup socName = XPath(SubscriberOffers[Soc==minor.RCOfferIn]/OfferName).
  6. Call ProcessSwitchFeatures() + ExtendAATagWithMultiSIM(aaXML, multiSimInfo, pmi, socName, …).
  7. Create and send AA_ACTIVATE_SUBS event (XSLT Variant ②). RefID = Minor.IMSI.
  8. Send ESB Logger audit event.
  9. Call UpdateMinorStatus(multiSimInfo, tp, action, imsi, pmi, false).
  10. Increment RequestCount; set isSkipped = false.
Phase 6 — Post-loop Status
  1. If !isSkipped: find activity with ID "AA_CHECK_CONFIRMATION" and matching Parameter[0], sync its RequestCount; set orderCurrentActivity.Status = GetActivityStatusString("1", false) → "IN_PROGRESS"; call SendDataToDB(orderRequest).
  2. Else: SkipActivity(orderRequest, orderCurrentActivity, "4").
