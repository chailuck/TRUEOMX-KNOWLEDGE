Request_SMDP_PLUS_CONFIRM_PUSH

Backend: SM-DP+ Pattern: Per-Subscriber Dispatch Priority: 5 ForwardChain: true Generated: 2026-09-14
§1 — Overview & Purpose

Sends an eSIM Confirm Order Request to the SM-DP+ server for each eSIM subscriber (SIM_TYPE="B"). One request is dispatched per subscriber across POU and COU structures. This is the second of two SM-DP+ push operations — Confirm signals the SM-DP+ server to finalize the eSIM profile download.

The payload is richer than DOWNLOAD: it adds releaseFlag (static "true"), matchingId (4-way selection including BULKESIM path), and smdsAddress. The PROJ=BULKESIM parameter activates a special NONTAG_MATCHINGID branch for matchingId.

[HIGH] Response RF — PMATCHID copy-paste bug: In Response_SMDP_PLUS_CONFIRM_PUSH.rulefunction, when updating an existing PMATCHID ResourceInfo, the code assigns the literal string "matchingId" instead of the variable matchingId (lines 44 and 80). This silently corrupts PMATCHID with the text "matchingId" for any subscriber that already has a PMATCHID entry.
[MEDIUM] COU eid unconditional emission: In the COU variant XSLT, the otherwise branch of the eid xsl:choose has no inner xsl:if guard — it unconditionally emits <eid> even when NEW_EID(Source=FE) is absent (an empty element). The POU variant has the correct guard. May cause SM-DP+ to reject the request with an unexpected empty <eid>.
[LOW] "SMDP_COMFIRMED" typo: The SubscriberExtendedInfo Name field is "SMDP_COMFIRMED" (missing "N") instead of "SMDP_CONFIRMED". Any downstream lookup by name will fail unless it also spells the typo.

§5 — Execution Flow Diagram
  1. Compute isActResub
  2. Read PROJ parameter via GetActivityParameterValueFromKey(activity, "PROJ")
  3. Loop POU subscribers: check reqSuccess (skip if already CompletionStatus=2)
  4. Evaluate PreExecCheck per subscriber via GetXMLForSubscriber
  5. If passes: create and send SMDP_PLUS_CONFIRM request event via XSLT (with $projValue)
  6. Set isSkipped=false; increment RequestCount (if not resubmit)
  7. Emit audit logger event
  8. Repeat steps 3–7 for COU subscribers (uses GetXMLForSubscriberInChildOU)
  9. After loops: if !isSkipped → Status="1" + SendDataToDB; else SkipActivity("4")

§19 — Response Message Rule

§19.1 Overview

Creates a ResponseBase concept from the SM-DP+ confirm response, appends to currActivity.Response, logs, then (if BULKESIM) extracts matchingId and writes it back to subscriber PMATCHID ResourceInfo. Creates SMDP_COMFIRMED (sic) SubscriberExtendedInfo with Value="Y". Fan-in is success-code-based.

[HIGH] Copy-paste bug — lines 44 & 80: Both POU and COU branches assign psub.ResourceInfo[rs].ValuesArray = "matchingId" (literal) instead of the variable matchingId. When PMATCHID already exists on a subscriber, its value is silently overwritten with the string "matchingId". Fix: remove quotes.
