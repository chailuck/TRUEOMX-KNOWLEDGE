Request_CCBS_SWAP_SIM_POSTPAID_SUB

Update postpaid subscriber SIM + IMSI on CCBS via UpdateSubscriberRequest; includes GetSequenceValue for SOC_SEQ_NO; uses pooling indicator logic; two XSLT variants (POU / ChildOU)
Rule Priority: 5 ForwardChain: true Backend: CCBS (UpdateSubscriber) Pattern: IntraActivitySequencing Author: TrueOM
⚠ Known Bug: Audit logger OPERATION_NAME in both POU and ChildOU request paths reads "CCBS_SPWAP_SIM_POSTPAID_SUB" (typo: "SPWAP" instead of "SWAP"). The response logger correctly uses "CCBS_SWAP_SIM_POSTPAID_SUB". Correct in migration target.
⚠ Dead Code: logicalDateRes and logicalDateVal are loaded from working memory but never passed to the XSLT or used anywhere. Same pattern as CCBS_RESTORE_SUBSCRIBERS.
§1 — Overview & Purpose

This rule updates a postpaid subscriber's SIM (physical) and IMSI (logical) in CCBS during a SIM swap operation. It fires for TARGET subscribers that have NOT already called CCBS_MSIM_SWAP_SIM (i.e., IS_CALLED_MSIM_SWAP_SIM count == 0 on the subscriber). Pre-processing builds three arrays: alSOCs (distinct SOC codes from POU+ChildOU subscribers excluding ServiceType=80), alPropVal (pooling indicator values), and alInstVal (pooling indicator instance values). The XSLT payload contains two nested requests: a GetSequenceValueRequest (for SOC_SEQ_NO, incrementBy = SubscriberOffers count + RelatedOffers count) and the UpdateSubscriberRequest with subscriber ID, IMSI change, SIM replacement, and ActivityInfo. The pattern is IntraActivitySequencing. Two XSLT variants exist for POU (includes RefID) and ChildOU (no RefID).
