Request_OMX_SEARCH_FUT_PP

Search Future Price Plan Orders — targeted 3-scope fan-out gated on ServiceType=80 (price plan)
Author: warawich-nb Priority: 5 forwardChain: true Type: OMXFM Request Backend: OMX FM (OMX_SEARCH_FUTURE) ServiceType gate: 80 Generated: 2026-08-20
§1 — Overview & Purpose

This rule searches the FM system for existing future orders related to price plans (ServiceType=80). It dispatches up to three OMX_SEARCH_FUTURE JMS events — one each for the first qualifying Subscriber, the first qualifying POU Agreement, and the first qualifying COU Agreement — each only if that entity has an offer with ServiceType=80. An activity-level PreExecCheck is evaluated first against the full OrderData; if it fails, nothing is dispatched. The orderType parameter is read from the ProcessConfig activity's Parameter[1], defaulting to 2 if empty.

Used in POSTPAID_UPDATE_PARAMETER step 22 to discover existing future price-plan orders before expiry/update operations proceed.

§6 — Rule Action (THEN) — Detailed Logic
Activity-Level PreExecCheck (gates all scopes)

Unlike FMs that apply PreExecCheck per offer, this rule applies it once at the activity level:

if(String.length(nextAct.PreExecCheck) > 0) {
    String sXML = Instance.serializeUsingDefaults(orderRequest.OrderData);
    chkRes = XPath.execute("/("+nextAct.PreExecCheck+")", sXML,
        "ns0=www.tibco.com/be/ontology/Concepts/OrderRequest/OrderRequest");
}
The evaluation document is orderRequest.OrderData (not the full orderRequest). PreExecCheck XPath must reference fields relative to OrderData — not the outer OrderRequest wrapper.
Scope A — Subscriber (nodeLevel=5)
  • Subject: first subscriber — XPath: tib:if-absent($orderRequest/OrderData/Customer/ParentOU[1]/Subscriber[1]/@extId, $orderRequest/OrderData/Customer/ParentOU[1]/ChildOU[1]/Subscriber[1]/@extId)
  • If subExtId == null → scope skipped entirely
  • Load concept: Instance.getByExtIdByUri(subExtId, "/Concepts/OrderRequest/OrderElements/Subscriber")
  • Gate: $subscriber/SubscriberOffers/ServiceType=80 — only dispatches if subscriber has a price plan
  • nodeId: number($subscriber/SubscriberId) — numeric conversion
  • RefID: $subscriber/RefId
  • No resubmit guard — request always re-sent (RequestCount only not incremented on resub)
Scope B — POU Agreement (nodeLevel=3)
  • Subject: $orderRequest/OrderData/Customer/ParentOU[OUId/text()][1]/@extId — first POU that has a non-empty OUId
  • If pOuExtId == null → scope skipped
  • Gate: $pOu/Agreement/Offers/ServiceType=80
  • nodeId: number($pOu/OUId)
  • RefID: $pOu/RefId
Scope C — COU Agreement (nodeLevel=3)
  • Subject: $orderRequest/OrderData/Customer/ParentOU[1]/ChildOU[OUId/text()][1]/@extId — first COU of POU[1] with non-empty OUId
  • If cOuExtId == null → scope skipped
  • Gate: $cOu/Agreement/Offers/ServiceType=80
  • nodeId: number($cOu/OUId)
  • RefID: $cOu/RefId

§17 — Migration Notes & Recommendations

Functional Requirements

IDRequirement
R1Search OMX FM for future price-plan orders for the first qualifying Subscriber, POU, and COU — each only if it has an offer with ServiceType=80
R2Activity-level PreExecCheck gates all dispatch; evaluated against serialized OrderData
R3orderType from Parameter[1], default 2 if empty; status always 1
R4Response captures full FutureOrders[] array for downstream processing (expiry/update)
R5Fan-in: declare complete when total response count equals RequestCount (not success-only)

Design Risks

RiskSeverityDetailMitigation
Non-standard fan-in — all responses vs success responses MEDIUM Fan-in condition is currActivity.RequestCount == currActivity.Response@length — returns "true" when all responses arrive regardless of ResponseCode. A failed search (non-"000" ResponseCode) still counts. The process may continue even if the FM search failed. Evaluate whether downstream steps depend on non-empty FutureOrders results; if so, add success-code check before proceeding
First-entity-only pattern may miss other entities MEDIUM Subscriber scope uses only the first subscriber (ParentOU[1]/Subscriber[1]); POU scope uses the first POU with OUId; COU scope uses the first COU of POU[1]. Orders belonging to other subscribers or OUs are not searched. Verify this is the intended behavior for POSTPAID_UPDATE_PARAMETER — if multi-subscriber orders exist, all relevant entities should be queried
No resubmit guard MEDIUM Unlike other FMs, there is no per-entity resubmit check — requests are always re-dispatched on resubmit (RequestCount not incremented, but event still sent). This may cause duplicate FM search calls. For read-only operations (search), this is relatively benign — however, duplicate responses could push response count above RequestCount and break the fan-in condition on resubmit
PreExecCheck uses OrderData (not full OrderRequest) LOW PreExecCheck is evaluated against Instance.serializeUsingDefaults(orderRequest.OrderData) — fields outside OrderData (like ProcessFlow, IsOrderResubmitted) are not accessible. Most other FMs evaluate per-offer PreExecCheck against a helper-constructed XML. Document that PreExecCheck XPath for this activity must reference only OrderData fields, not the outer OrderRequest
nodeId uses number() — potential NaN for non-numeric IDs LOW number($subscriber/SubscriberId) converts to numeric. If SubscriberId is non-numeric or empty, XPath number() returns NaN which serializes to "NaN" in the payload. Guard with string-length() > 0 check before conversion, or use raw string if FM accepts non-numeric nodeIds
§18 — Full Source Code
/**
 * @author warawich-nb
 */
rule Rules.OMConsumers.OMXFM.Request.Request_OMX_SEARCH_FUT_PP {
    attribute { priority = 5; forwardChain = true; }
    declare {
        Concepts.OrderRequest.OrderRequest orderRequest;
        Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
    }
    when {
        orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
        orderCurrentActivity.ActivityID == "OMX_SEARCH_FUT_PP";
        orderRequest.ProcessFlow.NextActivityID == "OMX_SEARCH_FUT_PP";
        orderCurrentActivity.Status == "WAITING";
    }
    then {
        boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
        boolean isSkipped = true;
        try {
            // Load LogicalDate (held but not passed in payload)
            Concepts.OM.LogicalDate logicalDateRes = Instance.getByExtIdByUri("LogicalDate", ...);
            String logicalDateVal = logicalDateRes.LogicalDate;

            // Activity-level PreExecCheck (against full OrderData)
            Concepts.OM.ProcessConfig.Activity nextAct = Instance.getByExtIdByUri(...);
            String chkRes = "true";
            if(String.length(nextAct.PreExecCheck) > 0) {
                String sXML = Instance.serializeUsingDefaults(orderRequest.OrderData);
                chkRes = XPath.execute("/("+nextAct.PreExecCheck+")", sXML, "ns0=...");
            }

            if(String.equals(chkRes,"true")) {
                // Read orderType from Parameter[1]
                String subExtId = XPath.evalAsString("tib:if-absent(ParentOU[1]/Subscriber[1]/@extId, ParentOU[1]/ChildOU[1]/Subscriber[1]/@extId)");
                String orderType = XPath.evalAsString("$orderCurrentActivity/Parameter[1]");

                // ── Scope A: Subscriber (nodeLevel=5) ─────────────────────────────────
                if(subExtId != null){
                    Subscriber subscriber = Instance.getByExtIdByUri(subExtId, ...);
                    boolean hasPricePlan = XPath.evalAsBoolean("$subscriber/SubscriberOffers/ServiceType=80");
                    if(hasPricePlan){
                        Events...OMX_SEARCH_FUTURE reqEvent = Event.createEvent("xslt://{{...}}");
                        /* XSLT: ns:futureOrder { status=1, orderType=Parameter[1]|2,
                           nodeLevel=5, nodeId=number(SubscriberId) }. See §9 for field mapping. */
                        Event.Ext.sendEventImmediate(reqEvent);
                        if(!isActResub) orderCurrentActivity.RequestCount++;
                        Event.Ext.sendEventImmediate(/* Logger: "Request Sent for OMX_SEARCH_FUT_PP" */);
                        isSkipped = false;
                    }
                }

                // ── Scope B: POU Agreement (nodeLevel=3) ──────────────────────────────
                String pOuExtId = XPath.evalAsString("ParentOU[OUId/text()][1]/@extId");
                if(pOuExtId != null){
                    ParentOU pOu = Instance.getByExtIdByUri(pOuExtId, ...);
                    if(XPath.evalAsBoolean("$pOu/Agreement/Offers/ServiceType=80")){
                        /* dispatch OMX_SEARCH_FUTURE: nodeLevel=3, nodeId=number(OUId) */
                        isSkipped = false;
                    }
                }

                // ── Scope C: COU Agreement (nodeLevel=3) ──────────────────────────────
                String cOuExtId = XPath.evalAsString("ParentOU[1]/ChildOU[OUId/text()][1]/@extId");
                if(cOuExtId != null){
                    ChildOU cOu = Instance.getByExtIdByUri(cOuExtId, ...);
                    if(XPath.evalAsBoolean("$cOu/Agreement/Offers/ServiceType=80")){
                        /* dispatch OMX_SEARCH_FUTURE: nodeLevel=3, nodeId=number(OUId) */
                        isSkipped = false;
                    }
                }
            }

            if(!isSkipped) {
                orderCurrentActivity.Status = GetActivityStatusString("1", false);
                RuleFunctions.Helpers.SendDataToDB(orderRequest);
            } else {
                RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
            }
        } catch (Exception ae){
            RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
        }
    }
}
