Request_CCBS_CHANGE_CUSTOMER_GENERAL_INFO

CCBS — Change Customer General Information (Identification / Contact / Grading)

Priority: 5 forwardChain: true Backend: CCBS Fan-in: IntraActivitySequencing Generated: 2026-09-23
§1 — Overview & Purpose

Invokes CCBS ChangeCustomerGeneralRequest to update customer personal information fields. Conditional fields include: BirthDate, contactLang, Grading, Identification, IdentificationExpDate, IdentificationType, and trueId. Uses IntraActivitySequencing fan-in (ActionRequestEvent + SendFirstRequestEvent).

Reads LogicalDate singleton from working memory for temporal context. Credential gate controlled by global variable IsEnableUserPass.

⚠ Dead code in response: The original IntraActivitySequencing completion check (ActionResponseEvent) is commented out in the response handler; current fan-in uses simple RequestCount == successResponseCount count. This is a regression risk if the activity ever issues multiple requests.

§5 — Execution Flow
  1. Read LogicalDate from working memory
  2. Evaluate PreExecCheck XPath against serialized orderRequest.OrderData
  3. If resubmit: call PurgePendingRequestsBeforeResubmit
  4. Build ChangeCustomerGeneralRequest event via XSLT with conditional fields
  5. Event.assertEvent(reqEvent) — adds to working memory for IntraActivitySequencing
  6. IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity)
  7. Send audit log
  8. IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity) — dispatches first pending request
  9. Set status to WAITING_RESPONSE; persist to DB
