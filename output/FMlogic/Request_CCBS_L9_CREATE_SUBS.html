Request_CCBS_L9_CREATE_SUBS

Creates a new postpaid subscriber in CCBS using the L9 (TNP) API — L9CreateNewActivateSubscriber. Handles full subscriber provisioning including name, address, resources, SOC offers, payment channels, BN resource ranges, and MNP fields.
Priority: 5 ForwardChain: true Pattern: IntraActivitySequencing Backend: CCBS (L9 API) Scope: ParentOU + ChildOU Subscribers
§1 — Overview & Purpose

Creates new postpaid subscribers for TNP (True Move H) order types via the CCBS L9CreateNewActivateSubscriber operation. Unlike the standard CCBS_CREATE_SUBS, this L9 variant sends enriched subscriber data in a single request — name (INDY/CORP), address, all resource types (MSISDN, IMSI, SIM, IMEI, BN ranges), SOC offers (contract + PP + dummy IMEI), payment channels, and MNP porting fields.

The rule iterates all ParentOU subscribers then all ChildOU subscribers. For each, it computes the sequence allocation count (GetSequenceValueRequest) based on the price plan offer (ServiceType=80) and contract SOC count before constructing the full request payload.

Uses IntraActivitySequencing (Event.assertEvent + ActionRequestEvent) for fan-in. Resubmit-safe via PurgePendingRequestsBeforeResubmit.

§5 — Execution Flow
  1. If resubmit: PurgePendingRequestsBeforeResubmit(orderCurrentActivity)
  2. Read LogicalDate singleton
  3. Loop ParentOU[i].Subscriber[j]:
  4. a. Skip if RefId already has CompletionStatus=2 in Response array
  5. b. Evaluate PreExecCheck via GetXMLForSubscriber(orderRequest, refId)
  6. c. Find PP offer (ServiceType=80), compute imeiExists, dummySocCount, contractSocCount, addRangeArray
  7. d. Build and assert CCBS_L9_CREATE_SUBS event
  8. e. IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity)
  9. f. Fire audit logger
  10. g. isSkipped = false
  11. Loop ChildOU[m].Subscriber[j]: same logic via GetXMLForSubscriberInChildOU
  12. If not isSkipped: SendFirstRequestEvent + set IN_PROGRESS; else: SkipActivity("4")

§19 — Response Message Rule

§19.1 Overview

Parses the L9CreateSubscriberResponse, writes the new SubscriberId back to each matched subscriber (ParentOU and ChildOU by RefId), creates a CCBSCreateSubsRes concept, logs audit, and drives fan-in completion.

§19.4 Fan-in Completion Logic

successResponseCount = count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = "000"])
if(currActivity.RequestCount == successResponseCount) → return "true"
else → return "false"

Success = last 3 characters of ResponseCode are "000". All subscribers must succeed before "true" is returned.
