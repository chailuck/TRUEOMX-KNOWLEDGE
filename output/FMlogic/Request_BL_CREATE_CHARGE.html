Request_BL_CREATE_CHARGE

Billing system charge creation — iterates all subscriber offers carrying a charge amount and dispatches Amdocs BL3G CreateCharge requests via throttled sequential fan-out
Author: RS33-BANDIT Namespace: Rules.OMConsumers.OMXFM.Request Priority: 5 ForwardChain: true Target: OMX_FM (Amdocs BL3G) Generated: 2026-08-03
§1 Overview & Purpose

BL_CREATE_CHARGE is the billing-charge dispatch step in the ACTIVATION_CREATE_SUBSCRIBER flow. Its primary job is to iterate over all SubscriberOffers that carry an AMOUNT ExtendedInfo value and send a CreateCharge request to the Amdocs BL3G billing system for each one.

Upstream dependency: The SubscriberOffers with ServiceType="79" and AMOUNT ExtendedInfo that trigger this FM are dynamically injected into working memory by the SBM_BUY_DATA_PACK response handler when its featureCode field is non-blank. BL_CREATE_CHARGE is therefore a downstream billing confirmation for data pack purchases — it does not independently query for offers.
Two dispatch variants are selected based on the offer's REVENUE_CODE ExtendedInfo:
  • REVENUE_CODE = "UC" → Full charge record: includes ChargeOrigin="ML", ChargeType (DBT/CRD), and attribute "Carry over status" = "N"
  • All other / no REVENUE_CODE → Simplified charge: attribute "Activity code" = "45"; dispatched only when amount > 0
Fan-out uses IntraActivitySequencing (throttled sequential dispatch), identical to SBM_BUY_DATA_PACK. Each charge request fires one at a time; the response handler's ActionResponseEvent advances the queue.

If RequestCount > 0 AND IsOrderResubmitted → call PurgePendingRequestsBeforeResubmit(orderCurrentActivity) to clean up leftover requests from prior attempt.
2
LogicalDate load (vestigial)
Load LogicalDate concept from working memory. Value is not used downstream — retained from template.
3
POU iteration
Loop over Customer.ParentOU[i].Subscriber[p].SubscriberOffers[q]. For each offer, compute refId = sub.RefId + ":" + subOff.OfferName. Check Response[] for prior success. If not yet successful and PreExecCheck passes → extract amount/description/revenueCode and branch on revenueCode.
4
POU branch: REVENUE_CODE == "UC"

5

6
COU iteration

8

If no dispatchable offers found (isSkipped still true): SkipActivity(orderRequest, orderCurrentActivity, "4").
9
Exception

§6 Rule Action (THEN) — Key Logic Detail

RefID Construction

// Same for both POU and COU
String refId = sub.RefId + ":" + subOff.OfferName;
Simpler than SBM: BL_CREATE_CHARGE uses a 2-segment RefID (subRefId:OfferName), whereas SBM_BUY_DATA_PACK uses a 4-segment pattern (pOuRefId::subRefId:soc). These are not interchangeable.

FE_OR_CCBS Filter

String filter = XPath.evalAsString("$subOff/ExtendedInfo[Name=\"FE_OR_CCBS\"]/Value");

The filter value is passed to GetXMLForSubscriberOfferFilterWithExtendedInfo() when building the PreExecCheck XML context. This ensures the PreExecCheck XPath evaluates against the same filtered offer view that was set up by upstream steps (SBM response injected FE_OR_CCBS ExtendedInfo on ServiceType="79" offers).

Amount / Description Resolution — POU vs COU

FieldPOU lookup orderCOU lookup order
amountsubOff/ExtendedInfo[AMOUNT] → sub/ExtendedInfo[AMOUNT] → "0"sub/ExtendedInfo[AMOUNT] → subOff/ExtendedInfo[AMOUNT]
descriptionsubOff/ExtendedInfo[DESCRIPTION] → sub/ExtendedInfo[DESCRIPTION] → ""sub/ExtendedInfo[DESCRIPTION] only
revenueCodesubOff/ExtendedInfo[REVENUE_CODE] → ""Not evaluated (no UC branch for COU)
Design inconsistency: Amount lookup order is reversed between POU and COU. This may cause different charge amounts for the same subscriber appearing under POU vs COU when both sub and offer have AMOUNT ExtendedInfo.

REVENUE_CODE == "UC" Branch (POU Only)

Triggered when subOff/ExtendedInfo[Name='REVENUE_CODE']/Value == "UC". Sends BL_CREATE_CHARGE with full billing classification — ChargeType is computed as if(amount > 0) then "DBT" else "CRD". This branch dispatches even when amount ≤ 0 (credit entries are valid). COU subscribers never follow this branch.

Standard Branch (amount > 0 guard)

Used when REVENUE_CODE ≠ "UC" (POU) or always (COU). Dispatches only when amount > 0. Uses AttributeName="Activity code" / Value="45". No ChargeOrigin or ChargeType fields emitted.

COU ServiceType="80" Exclusion

if(!String.equals(subOff.ServiceType, "80")) { ... }

ServiceType "80" offers under COU are excluded from charge dispatch. This guards against double-billing of certain base-plan offer types that are handled by a different FM.

§19 Response Message Rule — Response_BL_CREATE_CHARGE

§19.1 Overview

A lean response rulefunction. Its sole job is to: (1) construct a BL_CreateChargeRes concept from the incoming FM response event, (2) append it to currActivity.Response[], (3) emit a response audit log entry, and (4) call ActionResponseEvent to advance the IntraActivitySequencing queue.

Unlike SBM_BUY_DATA_PACK, this response handler has no fan-in success counting — it relies entirely on IntraActivitySequencing.ActionResponseEvent() to determine when all charges are complete and the next sequential event should fire.

§19.4 Response Completion Logic

No explicit fan-in count or ResponseCode success check. IntraActivitySequencing.ActionResponseEvent(currActivity) returns true when all enqueued charge requests have received responses — at that point this rulefunction returns "true" and the caller (the response event router) advances the activity.

/**
 * @description
 * @author RS33-BANDIT
 */
rule Rules.OMConsumers.OMXFM.Request.Request_BL_CREATE_CHARGE {
  attribute {
    priority = 5;
    forwardChain = true;
  }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "BL_CREATE_CHARGE";
    orderRequest.ProcessFlow.NextActivityID == "BL_CREATE_CHARGE";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    try {
      // LogicalDate loaded but not used in payload (vestigial)
      Concepts.OM.LogicalDate logicalDateRes = Instance.getByExtIdByUri("LogicalDate", "/Concepts/OM/LogicalDate");
      Concepts.OM.ProcessConfig.Activity nextAct = Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName, "/Concepts/OM/ProcessConfig/Activity");

      if(isActResub) {
        RuleFunctions.Helpers.IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity);
      }

      boolean isSkipped = true;
      /* ── POU Subscriber loop ── */
      for(int i = 0; i < orderRequest.OrderData.Customer.ParentOU@length; i++) {
        for(int p = 0; p < orderRequest.OrderData.Customer.ParentOU[i].Subscriber@length; p++) {
          Concepts.OrderRequest.OrderElements.Subscriber sub = ...ParentOU[i].Subscriber[p];
          for(int q = 0; q < sub.SubscriberOffers@length; q++) {
            Concepts.OrderRequest.OrderElements.SubscriberOffers subOff = ...Subscriber[p].SubscriberOffers[q];
            String refId = sub.RefId + ":" + subOff.OfferName;
            String filter = XPath.evalAsString("$subOff/ExtendedInfo[Name=\"FE_OR_CCBS\"]/Value");
            /* reqSuccess check against Response[] ... */
            if(!reqSuccess) {
              /* PreExecCheck gate ... */
              double amount = XPath.evalAsDouble("subOff/ExtendedInfo[AMOUNT] → sub/ExtendedInfo[AMOUNT] → 0");
              String description = XPath.evalAsString("subOff/ExtendedInfo[DESCRIPTION] → sub → ''");
              String revenueCode = XPath.evalAsString("subOff/ExtendedInfo[REVENUE_CODE] → ''");

              if(revenueCode == "UC") {
                /* UC path: ChargeOrigin="ML", ChargeType=DBT/CRD, AttributeName="Carry over status"/N
                   → See §9 for full XSLT (BL_CREATE_CHARGE UC variant) */
                Events.OMConsumers.OMXFM.Request.BL_CREATE_CHARGE createChargeEvent = Event.createEvent(/* UC XSLT */);
                Event.assertEvent(createChargeEvent);
                RuleFunctions.Helpers.IntraActivitySequencing.ActionRequestEvent(createChargeEvent, orderCurrentActivity);
                Event.Ext.sendEventImmediate(/* Logger audit */);
                isSkipped = false;
              } else if(amount > 0) {
                /* Standard path: AttributeName="Activity code"/45
                   → See §9 for full XSLT (BL_CREATE_CHARGE standard POU variant) */
                Events.OMConsumers.OMXFM.Request.BL_CREATE_CHARGE createChargeEvent = Event.createEvent(/* Std XSLT */);
                Event.assertEvent(createChargeEvent);
                RuleFunctions.Helpers.IntraActivitySequencing.ActionRequestEvent(createChargeEvent, orderCurrentActivity);
                Event.Ext.sendEventImmediate(/* Logger audit */);
                isSkipped = false;
              }
            }
          }
        }
        /* ── COU Subscriber loop (excludes ServiceType="80") ── */
        for(int u = 0; u < orderRequest.OrderData.Customer.ParentOU[i].ChildOU@length; u++) {
          /* amount: sub first → subOff; no revenueCode check; amount > 0 guard only
             → See §9 for full XSLT (BL_CREATE_CHARGE COU variant) */
          if(amount > 0) {
            /* dispatch COU charge */
            isSkipped = false;
          }
        }
      }

      if(!isSkipped) {
        RuleFunctions.Helpers.IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch (Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
