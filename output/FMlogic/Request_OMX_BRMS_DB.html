Request_OMX_BRMS_DB

TIBCO BusinessEvents FM Logic — OMX Business Rules Engine (BRMS from DB)
Target: BRMS / Internal DB Fan-out: Classic Parallel + Resubmit Guard forwardChain: true Author: boony14 Generated: 2026-08-04
§1 — Overview & Purpose

This FM is the BRMS decision engine for order processing. It sends each subscriber's contextual data (propositions, offer names, company codes, extended flags) to the Business Rules Management System (BRMS) — formerly implemented as decision tables, now stored in a database. BRMS returns a set of actions (AddOffer, RemoveOffer, etc.) that the response handler dynamically executes to modify the OrderRequest working memory.


This FM is significantly more complex than other FMs because it branches on order type, constructs a large pipe-delimited ListInput string from dozens of subscriber/account/extended-info fields, handles resubmit detection (avoids double-incrementing RequestCount), and supports a testBRMS_DB mode that suppresses audit logging.

forwardChain = true: Unique among OMXFM rules. After this rule fires, TIBCO BE immediately re-evaluates all rule conditions in working memory. This allows downstream rules to respond to the BRMS actions without waiting for an external event cycle.
Resubmit guard: If orderRequest.IsOrderResubmitted == true AND orderCurrentActivity.RequestCount > 0, the resubmit path skips incrementing RequestCount — preventing duplicate fan-in counting when reprocessing an already-in-flight activity.

§4 — Rule Conditions (WHEN)

    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "OMX_BRMS_DB";
    orderRequest.ProcessFlow.NextActivityID == "OMX_BRMS_DB";
    orderCurrentActivity.Status == "WAITING";

§5 — Execution Flow Diagram
Resubmit detection — isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted)
PreExecCheck gate — evaluate XPath against serialized orderRequest. If chkRes != "true" → SkipActivity("4")
Audit log start — if AllowWriteLog(OrderType): send Logger event "OMX-OM BRMS started."
Order type classification:
  • IsChangePricePlanOrderType = OrderType == "2"
  • IsPostpaidAddOfferSubOrderType = OrderType IN ("3","4","69","11018")
  • IsShareplanOrderType = OrderType == "11002"
POU Subscriber loop — for each ParentOU[i].Subscriber[j]:
  • Resubmit check: if Response already contains success for this refId → skip
  • Find matching Account by AccountRefId
  • Extract companyCode, accSubType, custInfoType, effectiveDate, identification
  • Extract XPath fields: relaxBlacklist, orgChannel, oldPaymentMethod, newPaymentMethod, pricePlan, subType, callverStatus, redZone, verifyResult, faceRec, ccbs_topping_group, final_bill, cancel_type
  • Branch A (PostpaidAddOfferSub): loop over SubscriberOffers[pso], skip if FE_OR_CCBS=CCBS/CRM, build ListInput with 22+ fields + conditional RELATED_PROPOSITION/FINAL_BILL/CANCEL_TYPE, fire GET_BRMS_ACTIONS event with mainOffer
  • Branch B (other types): single event per subscriber, different proposition/offerName logic per IsChangePricePlanOrderType, build ListInput with different set of fields, fire GET_BRMS_ACTIONS event without mainOffer
  • If !isActResub: RequestCount++
COU Subscriber loop — ParentOU[i].ChildOU[n].Subscriber[j]: identical logic to POU loop but uses 3-index path ($i, $n, $j in XSLT)
Post-loop: if !isSkipped → GetActivityStatusString("1", false) + SendDataToDB(orderRequest); else → SkipActivity(orderRequest, orderCurrentActivity, "4")
Exception handler (catch block) → HandleActivityException(orderRequest, orderCurrentActivity, ae, "")
§6 — Rule Action (THEN) — Annotated Logic
try {
    // PreExecCheck
    String chkXPath = orderCurrentActivity.PreExecCheck;
    String chkRes   = "true";
    boolean isSkipped = true;

    if(String.length(chkXPath) > 0) {
        String sXML = Instance.serializeUsingDefaults(orderRequest);
        chkRes = XPath.execute("/(" + chkXPath + ")", sXML, "ns0=www.tibco.com/be/ontology/...");
    }

    if(String.equals(chkRes, "true")) {
        // Optional audit log: "OMX-OM BRMS started."
        if(RuleFunctions.Helpers.AllowWriteLog(orderRequest.OrderData.OrderType)) { ... }

        // Order type flags
        boolean IsChangePricePlanOrderType       = String.equals("2",  orderRequest.OrderData.OrderType);
        boolean IsPostpaidAddOfferSubOrderType   = String.equals("3",  orderRequest.OrderData.OrderType)
                                                  || String.equals("4",  orderRequest.OrderData.OrderType)
                                                  || String.equals("69", orderRequest.OrderData.OrderType)
                                                  || String.equals("11018", orderRequest.OrderData.OrderType);
        boolean IsShareplanOrderType             = String.equals("11002", orderRequest.OrderData.OrderType);

        // POU Subscriber loop
        for (int i = 0; i < orderRequest.OrderData.Customer.ParentOU@length; i++) {
            for (int j = 0; j < orderRequest.OrderData.Customer.ParentOU[i].Subscriber@length; j++) {
                String refId = orderRequest.OrderData.Customer.ParentOU[i].Subscriber[j].RefId;

                // Resubmit guard
                boolean reqSuccess = false;
                for(int iResp = 0; iResp < orderCurrentActivity.Response@length; iResp++)
                    if(String.equals(orderCurrentActivity.Response[iResp].ReferenceId, refId)
                       && orderCurrentActivity.Response[iResp].CompletionStatus == 2)
                        reqSuccess = true;
                if(!reqSuccess) {
                    // Find matching Account
                    Concepts.OrderRequest.OrderElements.Account acc = null;
                    for (int k = 0; k < orderRequest.OrderData.Customer.Account@length; k++) {
                        if(String.equals(acc[k].RefId, subscriber.AccountRefId))
                            acc = orderRequest.OrderData.Customer.Account[k];
                    }

                    // Extract BRMS context fields (see §7 for full list)
                    String companyCode = ...; String accSubType = ...;
                    String custInfoType = ...; String effectiveDate = ...;
                    String identification = ...; String relaxBlacklist = ...;
                    // ... many more XPath extractions ...

                    if (IsPostpaidAddOfferSubOrderType) {
                        // Branch A: loop over SubscriberOffers, one event per FE offer
                        for(int pso = 0; ...) {
                            if(FE_OR_CCBS == "CCBS" || "CRM") { continue; }
                            String listInput = "COMPANY_CODE=" + companyCode
                                + "|ACC_SUB_TYPE=" + accSubType + "|...";
                            Events.OMConsumers.OMXFM.Request.GET_BRMS_ACTIONS reqEvent =
                                Event.createEvent("xslt://..." /* POU+Offer XSLT, see §9.8 */);
                            Event.Ext.sendEventImmediate(reqEvent);
                            if(!isActResub) orderCurrentActivity.RequestCount++;
                            isSkipped = false;
                        }
                    } else {
                        // Branch B: single event per subscriber, different proposition logic
                        String listInput = "COMPANY_CODE=" + companyCode + "|...";
                        Events.OMConsumers.OMXFM.Request.GET_BRMS_ACTIONS reqEvent =
                            Event.createEvent("xslt://..." /* POU-only XSLT, see §9.8 */);
                        Event.Ext.sendEventImmediate(reqEvent);
                        if(!isActResub) orderCurrentActivity.RequestCount++;
                        isSkipped = false;
                    }
                }
            }

            // COU Subscriber loop — identical logic with (i, n, j) indices
            for (int n = 0; n < ParentOU[i].ChildOU@length; n++) {
                for (int j = 0; j < ChildOU[n].Subscriber@length; j++) {
                    // ... same logic, XSLT includes $n (ChildOU index) additionally ...
                }
            }
        }

        if(!isSkipped) {
            orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
            RuleFunctions.Helpers.SendDataToDB(orderRequest);
        } else {
            RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
        }
    }
} catch (Exception ae) {
    RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
}

§13 — Exception / Error Handling

The entire THEN block is wrapped in a try/catch(Exception ae). On any exception:

RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");

The 4th argument (empty string) provides no additional context — any exception detail must be derived from the exception object itself inside HandleActivityException.

§17 — Migration Notes & Recommendations

Functional Requirements

#Requirement
R1Send BRMS query per subscriber (POU and COU) with order-type-specific pipe-delimited ListInput
R2For PostpaidAddOfferSub (type 3/4/69/11018): fire one BRMS request per FE SubscriberOffer (not per subscriber)
R3Resubmit guard: do not increment RequestCount if activity was previously in-flight
R4On response: parse BRMS Actions string, invoke the corresponding AddOffer/RemoveOffer helper for each action item
R5testBRMS_DB mode: suppress audit log when Actions contains "testBRMS_DB" token
R65G child shareplan gate: exclude fe_pp_group, accSubType, discount, topping from BRMS input
R7EffectiveDate: translate to Asia/Bangkok timezone then format as yyyy-MM-dd; fall back to current date if blank

§19 — Response Message Rule
§19.1 — Overview

Response_OMX_BRMS_DB is the most action-rich response handler in the OMXFM suite. It: (1) detects and strips the testBRMS_DB test flag; (2) if Actions are present, calls GetBrmsItems to parse the BRMS response into typed action objects, then dynamically invokes the appropriate helper rulefunction for each action (AddOffer, RemoveOffer, etc.) to modify the OrderRequest in working memory; (3) constructs a GetBRMSActionsRes concept; (4) fires conditional audit log; (5) evaluates fan-in completion.
