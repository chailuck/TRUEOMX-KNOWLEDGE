Request_PSA_UPDATE_DEVICE

Updates device registration record in PSA per material item (IMEI-ID + MAT_CODE). Fan-out is per Material under MaterialInfo — not per offer. Param-name resolved by priority: PARTNER ExtendedInfo → IoT (CLOUD-SERVICE) → Knox (KNOX) → TPC-ASURION.
Backend: PSA (UpdateDevice) Pattern: Per-material fan-out RefID: subRefId:MatCode (2-part) forwardChain: true Used in step: 70 Generated: 2026-08-11
§1 — Overview & Purpose

Sends one PSA UpdateDeviceReq per material item in the subscriber's MaterialInfo.Material[] array. This is the only FM in the Knox/PSA cluster that fans out per material rather than per offer. The 2-part RefID (subRefId:MatCode) is used throughout for request correlation and resubmit guard. deviceStatus and srType are read from ProcessConfig Parameters.

  • Fan-out: per psub.MaterialInfo.Material[] (guarded: if (psub.MaterialInfo != null))
  • RefID: subRefId + ":" + material.MatCode (2-part)
  • Payload root: ns8:UpdateDeviceReq — PSA UpdateDevice schema
  • Key identifiers: IMEI-ID = MatSerial, MAT_CODE = MatCode
  • param-name priority: PARTNER > CLOUD-SERVICE > KNOX > TPC-ASURION (see §7)
  • SR-TYPE priority: sub.ExtendedInfo[SR_TYPE] > ProcessConfig srType Parameter
  • Response: standard ResponseBase only — no write-back
[MEDIUM] param-name may be empty: If none of the four priority conditions match (no PARTNER, no IOTBU offer, no IMEI_KNOX, no TPC_REFNO), ns8:param-name is omitted entirely — the fallback xsl:otherwise contains only the inner xsl:choose with no final default. PSA behaviour with a missing param-name is untested.
[LOW] No explicit Parameter guard: Unlike Knox FMs, there is no upfront Parameter@length == 0 check. If ProcessConfig has no Parameters, deviceStatus and srType will be empty strings — ns8:DEVICE-STATUS is conditional so absent is safe; ns8:SR-TYPE may be omitted if both sources are empty.
[INFO] Both POU and COU RefIDs are correct: POU sends $pMatRefId, COU sends $cMatRefId — both match the resub guard check. No RefID bug here.

§7 — param-name Priority Logic (ns8:param-name)

The ns8:param-name value determines which partner/service category PSA routes the update to. Resolution follows a strict priority cascade:

PriorityConditionparam-name value
1 (highest)string-length(sub.ExtendedInfo[PARTNER]/Value) > 0sub.ExtendedInfo[PARTNER]/Value (subscriber-level explicit partner)
2SubscriberOffers[SocProperties contains "TR_SPECIAL_OFFER_IND=IOTBU"]/RelatedOffersArray[MatSerialRefId == $material/MatSerial]"CLOUD-SERVICE" (IoT/IOTBU offer with matching serial)
3string-length(SubscriberOffers/ExtendedInfo[IMEI_KNOX]/Value) > 0"KNOX" (any offer has Knox IMEI)
4string-length(OrderData/ExtendedInfo[TPC_REFNO]/Value) > 0"TPC-ASURION" (TPC reference number present)
5 (default)None of the above matchns8:param-name omitted entirely [MEDIUM]
The IOTBU check (priority 2) cross-references both the offer's SocProperties and the offer's RelatedOffersArray[MatSerialRefId == material.MatSerial] — the material being updated must appear in a related-offer entry under an IOTBU offer.

§17 — Migration Notes & Recommendations

Functional Requirements

RefRequirement
R1Per-material fan-out across POU and COU. One PSA UpdateDeviceReq per Material[] entry where MaterialInfo != null.
R2RefID = subRefId + ":" + material.MatCode (2-part). Both POU and COU correct.
R3Key identifiers: IMEI-ID = material.MatSerial; MAT_CODE = material.MatCode (always sent).
R4param-name priority: PARTNER ExtendedInfo (1) → "CLOUD-SERVICE" if IOTBU offer match (2) → "KNOX" if any IMEI_KNOX (3) → "TPC-ASURION" if TPC_REFNO (4) → omitted.
R5SR-TYPE priority: sub.ExtendedInfo[SR_TYPE] if not blank; else ProcessConfig srType Parameter.
R6REF-NUMBER priority: TPC_REFNO if present; else OMXTrackingId.
R7SR-COMPLETION-DATE = SubmissionDate formatted as "dd/MM/yyyy HH:mm:ss" (always sent).
R8DEVICE-STATUS from ProcessConfig Parameter[deviceStatus] (conditional on non-empty).
R9NEW-IMEI-ID from sub.ExtendedInfo[NEW_MAT_SERIAL] (device swap scenario).
R10PreExecCheck uses material-level context: MatCode (preferred) or MatSerial if MatCode blank.
R11Response: standard ResponseBase — no write-back. Fan-in: RequestCount == successResponseCount.
