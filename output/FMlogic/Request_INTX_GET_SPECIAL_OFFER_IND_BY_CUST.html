INTX — Get Special Offer Indicator List by Customer (Paginated)

Priority: 5 forwardChain: true Backend: INTX Fan-in: Count("000") == RequestCount Pattern: Paginated loop Generated: 2026-09-23
§1 — Overview & Purpose

Fetches the complete list of special offer indicator records for a customer from INTX, using a paginated approach. The total number of records (TOTAL_OU ExtendedInfo) is divided by PAGE_SIZE parameter, and one JMS request is sent per page.

💡 Dual usage in CHANGE_CUSTOMER_GENERAL_INFO: This FM is called twice in the same order flow:
Step 6 (extId: INTX_GET_TOTAL_OU_BY_CUST): PAGE_SIZE=1 — quick probe to see if TOTAL_OU > 0
Step 7 (extId: INTX_GET_SPECIAL_OFFER_IND_BY_CUST): PAGE_SIZE=50 — full fetch to populate ParentOU list
⚠ extId/ActivityID mismatch at step 6: The ProcessConfig extId is INTX_GET_TOTAL_OU_BY_CUST but ActivityID is INTX_GET_SPECIAL_OFFER_IND_BY_CUST. The same rule fires for both steps.

Key response side-effect: The response handler populates orderRequest.OrderData.Customer.ParentOU with OU objects built from the INTX response — this is the input for the subsequent SBM_FUP_UPDATE_OU_INFO step.

§5 — Execution Flow
  1. Check resubmit; if so: PurgePendingRequestsBeforeResubmit
  2. Read parameters: SPECIAL_OFFER_IND (required), PAGE_SIZE (default "50" if blank)
  3. Validate SPECIAL_OFFER_IND — throw DATA_ISSUE if missing
  4. If PreExecCheck passes: read TOTAL_OU ExtendedInfo value from orderRequest
  5. Compute iteration = ceil(TOTAL_OU / PAGE_SIZE)
  6. For each page i = 1..iteration:
    • Build refId = OMXTrackingId + ":PAGE:" + i
    • Check if this page already succeeded (resubmit guard)
    • If not succeeded: send `GetSpecialOfferIndListByCustomerReq` for this page
    • Increment RequestCount; send audit log
  7. Set WAITING_RESPONSE; persist to DB

§19 — Response Message Rule

§19.1 — Overview

Response_INTX_GET_SPECIAL_OFFER_IND_BY_CUST: Parses paginated response. For each ouSpecialOfferArray entry, creates a ParentOU concept and appends to orderRequest.OrderData.Customer.ParentOU. This populates the OU list consumed by SBM_FUP_UPDATE_OU_INFO.
