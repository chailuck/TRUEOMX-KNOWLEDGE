Request_OMX_UPDATE_SUBID_FUTORDER

Backend: OMX Internal (Future Order Update) Pattern: Fire-and-Forget (Event.sendEvent) Author: warawich-nb Generated: 2026-09-23
§1 — Overview & Purpose

Updates the future order record in OMX after CCBS_MOVE_SUB has assigned a new SubscriberId to the moved subscriber. Loads the new subscriber (by subExtId) and the old subscriber (by subExtId + "_src") from working memory. Updates the future order's nodeId to the new subscriber ID and adds OLD_SUBID extended info with the previous subscriber ID. Only sends if future orders exist (count(futureOrder) > 0 guard). Uses GetBillCycle helper for bill cycle information.

Unique Pattern: This FM uses Event.sendEvent (not sendEventImmediate) — a rare pattern in OMX FMs. The logger event also uses Event.sendEvent. This means the event is subject to TIBCO BE engine routing rules rather than immediate dispatch. Exercise caution in migration — do NOT replace with async HTTP/REST unless you verify the engine routing semantics are preserved.

§4 — Rule Conditions (WHEN)
  1. orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName
  2. orderCurrentActivity.ActivityID == "OMX_UPDATE_SUBID_FUTORDER"
  3. orderRequest.ProcessFlow.NextActivityID == "OMX_UPDATE_SUBID_FUTORDER"
  4. orderCurrentActivity.Status == "WAITING"
§5 — Execution Flow
  1. Derive subExtId = tib:if-absent(POU[1]/Sub[1]/@extId, ChildOU[1]/Sub[1]/@extId)
  2. Load newSub from working memory by subExtId
  3. Load oldSub from working memory by subExtId + "_src"
  4. Get billCycleNo via GetBillCycle(orderRequest)
  5. Guard: if count(futureOrder) == 0 → SkipActivity; else proceed
  6. Build ns:futureOrders/futureOrder payload per future order
  7. Event.sendEvent(reqEvent) (note: NOT sendEventImmediate)
  8. Set IN_PROGRESS; send audit log (also via Event.sendEvent)
