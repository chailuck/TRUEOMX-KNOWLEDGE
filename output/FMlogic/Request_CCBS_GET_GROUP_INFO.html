Request_CCBS_GET_GROUP_INFO

CCBS — Get CUG (Closed User Group) Information
Backend: CCBS Pattern: Fan-out per CUG-bearing entity (sendEventImmediate) Priority: 5 Author: awalia-t420 Generated: 2026-09-21
§1 — Overview & Purpose

CCBS_GET_GROUP_INFO retrieves Closed User Group (CUG) information from CCBS for each offer entity in the order that carries a CUG ID parameter. Used during ACTIVATION to populate CUG details (GroupId, GroupName, GroupType, GroupDescription) for subscribers or agreement offers that request group membership.

Unlike most OMXFM rules, this rule fans out per entity with a CUG ID rather than per OU. It traverses four nested scopes:

  1. ParentOU → Subscriber → SubscriberOffers with CUG ID param
  2. ParentOU → ChildOU → Subscriber → SubscriberOffers with CUG ID param
  3. ParentOU → Agreement → Offers with CUG ID param
  4. ParentOU → ChildOU → Agreement → Offers with CUG ID param
Fan-in note: Response rulefunction uses RequestCount == Response@length (response count), NOT the standard successResponseCount ("000" suffix check). A failed response still counts toward completion.

§5 — Execution Flow
  1. Check resubmit flag; capture chkXPath = orderCurrentActivity.PreExecCheck
  2. Loop 1: for each ParentOU[i] → Subscriber[j] → SubscriberOffers[k]: if CUG ID count > 0, evaluate per-subscriber PreExecCheck via GetXMLForSubscriber; if not already completed (CompletionStatus=2): send request, RequestCount++, isSkipped=false
  3. Loop 2: for each ParentOU[i] → ChildOU[x] → Subscriber[y] → SubscriberOffers[z]: same CUG ID check; PreExecCheck via GetXMLForSubscriberInChildOU; skip if completed
  4. Loop 3: for each ParentOU[i] → Agreement → Offers[m]: CUG ID check; PreExecCheck via GetXMLForAgreement; skip if completed
  5. Loop 4: for each ParentOU[i] → ChildOU[m] → Agreement → Offers[l]: CUG ID check; PreExecCheck via GetXMLForAgreementInChildOU
  6. SendDataToDB(orderRequest) after all loops
  7. If any sent: Status = GetActivityStatusString("1", false) + SendDataToDB
  8. If none sent: SkipActivity("4")
Each loop uses sendEventImmediate — all qualifying requests are dispatched immediately (no sequencing). The CUG ID is read from ParameterInfo[ParamName = "CUG ID"]/ValuesArray.

§19 — Response Message Rule

§19.1 Overview

Receives CCBS response, creates CCBS_GetGroupInfoRes concept with CUG details, appends to activity response array, then checks if all responses received (RequestCount == Response@length).

§19.3 Response Concept Tree

  • createObject (CCBS_GetGroupInfoRes)
    • @extId←OMXUtils:generateTrackingID()Always
    • ResponseCode←$eventResponse/ResponseCodeConditional
    • ResponseMessage←$eventResponse/ResponseMsgConditional
    • CompletionStatus←$eventResponse/CompletionStatusConditional
    • ReferenceId←$eventResponse/RefIDConditional
    • GroupDescription←payload/ns1:getGroupInfoResponse/ns1:getGroupInfoReturn/ns:GroupDescriptionConditional
    • GroupId←payload/.../ns:GroupIdConditional
    • GroupName←payload/.../ns:GroupNameConditional
    • GroupType←payload/.../ns:GroupTypeConditional

§19.4 Response Completion Logic

Fan-in: currActivity.RequestCount == currActivity.Response@length → return "true"

Does NOT use successResponseCount ("000" check). Any response (success or error) increments Response@length and may trigger completion.
