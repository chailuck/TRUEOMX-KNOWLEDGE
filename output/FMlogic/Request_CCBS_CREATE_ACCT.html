Request_CCBS_CREATE_ACCT

CCBS — Create New Account with Billing Arrangement, Charge Distribution, and Payment Channel
Backend: CCBS Pattern: assertEvent + IntraActivitySequencing (per Account) Priority: 5 Author: awalia-t420 Generated: 2026-09-21
§1 — Overview & Purpose

CCBS_CREATE_ACCT creates one CCBS Account per Customer.Account[] entry. It is the most comprehensive Account-level creation call in the ACTIVATION flow, building a full CreateNewAccountRequest payload that includes AccountNameInfo (CORP/INDY/other), AccountAddressInfo, AccountingManagementInfo, BillingArrangementInfo, PayChannel details, and ActivityInfo.

Iteration scope: Loops Customer.Account[] (not POU/ChildOU). Each Account corresponds to a billing cycle. The XSLT resolves the linked Agreement ID from POU or ChildOU agreements via the Account's AgreementRefId.
AccountNameInfo dispatch: 3-way branch on Account.AccountNames.NameType: CORP (nameType 66, 69, optional 67), INDY (nameType 73, 69, optional 67), or default (nameType 69 only + optional 67).
Response writes: AccountID, PayChannelId, BillingArrangementId written back per Account. After success, appends omxCreatedAccountInd="Y" to orderRequest.OrderData.ExtendedInfo[].
OrderType=31 special logic: On success, writes ParentOU[0].Subscriber[0].PayChannelIdSecondary = Account[0].AccountID.
Old fan-in commented out: Original logic counted pending accounts with empty AccountID; replaced with IntraActivitySequencing.ActionResponseEvent.
