Request_CCBS_UPD_CREDIT_LIMIT

CCBS Credit Limit Update — compound 3-sub-request payload with calCRFlag-aware activityReason
Backend: CCBS Author: awalia-t420 Priority: 5 Pattern: IntraActivitySequencing Iteration: Account[]
§1 — Overview & Purpose
CCBS_UPD_CREDIT_LIMIT updates the credit limit on existing CCBS accounts. Sends a compound UpdateCreditLimitRequest containing three sub-operations to CCBS in a single message.
Standard IntraActivitySequencing pattern — unlike FM21/FM22/FM23/FM26, this FM uses Event.assertEvent + IntraActivitySequencing.ActionRequestEvent. Fan-in uses IntraActivitySequencing.ActionResponseEvent.
calCRFlag gate: Checks order ExtInfo for CAL_CR_FLG=Y via XPath boolean. If true AND CustomerType=73 → activityReason="G158" (unique to FM25). Normal Type=73 → "CREQ"; else → "G142".
Two XSLT variants (OMX-2748): Old XSLT (commented out) lacked CES field and had L9CreditLimitWaiverInd condition for Type=66/67. Active XSLT adds CES and changed condition to Type!=73 (for non-individual).

§7 — Key Logic Patterns
PatternDetail
calCRFlagXPath.evalAsBoolean on order ExtInfo[Name='CAL_CR_FLG' and Value='Y']. Changes activityReason for Type=73: false → "CREQ", true → "G158".
L9CreditLimitWaiverInd logic (OMX-2748 change)Active XSLT: if CreditLimitWaiverInd non-empty → use it; else if Type!=73 AND (TOP OR PREMIUM) → "U". Old XSLT used Type=66 or 67 instead of Type!=73.
Compound payloadSingle CCBS call contains 3 sub-requests: GetAccountHeaderRequest + I9GetAccountCreditHistoryRequest + ChangeAccountingManagementInfoRequest.
L9PrsnlCreditLimitOnly included if PersonalCreditLimit non-empty (string-length check). Not all accounts have a personal credit limit.
activityReason 3-wayType=73 + calCRFlag=true → "G158"; Type=73 + calCRFlag=false → "CREQ"; else → "G142".

§17 — Migration Notes & Recommendations

Pagination hardcoded to pageSize/numberOfRows=1000 — may miss results if an account has >1000 credit history records LOW Review CCBS credit history volume; implement pagination if needed
