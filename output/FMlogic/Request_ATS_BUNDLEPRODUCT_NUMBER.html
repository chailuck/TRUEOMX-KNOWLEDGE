🇧🇹 0. Program Objective — วัตถุประสงค์ของโปรแกรม

ภาษาไทย วัตถุประสงค์

กฎ (Rule) นี้เป็นส่วนหนึ่งของระบบ TRUE OMX Order Management (OMX-OM) ซึ่งทำงานบนเครื่องมือ TIBCO BusinessEvents มีหน้าที่ ส่งคำขอยืนยันหมายเลขสินค้าประเภท Bundle ไปยังระบบ ATS (Activation & Transaction System) เมื่อกระบวนการสั่งซื้อ (Order) ถึงขั้นตอน ATS_BUNDLEPRODUCT_NUMBER กฎนี้จะดึงข้อมูลผลิตภัณฑ์จากฟิลด์ GROUP ของคำสั่งซื้อ ซึ่งบันทึกในรูปแบบ FAMILY_TYPE=…|PRODUCT_ID=…|COMPANY_CODE=… จากนั้นสร้างและส่ง Event ชนิด ATS_SUBMIT_CAMPAIGN ผ่านช่องทาง JMS ไปยัง ATS เพื่อลงทะเบียนหมายเลขสินค้า Bundle สำหรับการเปิดใช้งานบริการ Prepaid ของ TRUE Move (TMV) ในกรณีที่เงื่อนไขเบื้องต้น (PreExecCheck) ไม่ผ่าน กฎจะข้ามขั้นตอนนี้ไปโดยอัตโนมัติ และในกรณีที่เกิดข้อผิดพลาด จะมีกระบวนการจัดการ Exception เพื่อบันทึกสถานะและแจ้งเตือนทีมงาน

ENGLISH Objective

This rule is part of the TRUE OMX Order Management (OMX-OM) platform running on TIBCO BusinessEvents. Its purpose is to submit a Bundle Product Number registration request to the ATS (Activation & Transaction System) when an order workflow reaches the ATS_BUNDLEPRODUCT_NUMBER process step. The rule extracts the product identity — family type, product ID, and company code — from the GROUP extended info field of the order (encoded as a pipe-delimited string), then constructs and dispatches an ATS_SUBMIT_CAMPAIGN event via JMS to ATS for bundle product number resolution and activation under the TRUE Move (TMV) Prepaid line. If a configurable pre-execution condition is not satisfied, the activity is automatically skipped and the order flow advances to the next step. Any runtime exception triggers a structured error-handling flow that records the failure state, emits an error audit log, and optionally routes to a compensation activity.

✅ 4. Rule Conditions (WHEN) — All must be simultaneously true

C1 — Activity extId matches order's NextActivityName

orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName

Binds this specific activity instance to this specific order. Prevents cross-order misfires in multi-order working memory.

C2 — ActivityID == "ATS_BUNDLEPRODUCT_NUMBER"

orderCurrentActivity.ActivityID == "ATS_BUNDLEPRODUCT_NUMBER"

Primary discriminator — selects this rule over hundreds of other OMXFM request rules.

C3 — Order's NextActivityID matches

orderRequest.ProcessFlow.NextActivityID == "ATS_BUNDLEPRODUCT_NUMBER"

Redundant safety — verifies by ActivityID string (not just extId) to prevent misfire during concurrent process config updates.

C4 — Activity Status is WAITING

orderCurrentActivity.Status == "WAITING"

Only fires when ready to process. Once this rule sets Status to IN_PROGRESS, forward chaining prevents re-firing.

⚙ 6. Rule Action (THEN) — Step-by-Step Logic

Step 1 — Resubmission Detection

boolean isActResub = (orderCurrentActivity.RequestCount > 0
                        && orderRequest.IsOrderResubmitted);

True only when BOTH: prior request was sent (RequestCount > 0) AND order was explicitly resubmitted. Guards against double-counting retries.


Step 2 — Pre-Execution Check

Concepts.OM.ProcessConfig.Activity nextAct =
    Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName,
                             "/Concepts/OM/ProcessConfig/Activity");
String  chkXPath  = nextAct.PreExecCheck;
String  chkRes    = "true";    // default: proceed when blank
boolean isSkipped = true;   // pessimistic default

if (String.length(nextAct.PreExecCheck) > 0) {
    String sXML = Instance.serializeUsingDefaults(orderRequest);
    chkRes = XPath.execute("/(" + chkXPath + ")", sXML,
                "ns0=www.tibco.com/be/ontology/Concepts/OrderRequest/OrderRequest");
}

Step 3 — Post-Execution Branch

if (!isSkipped) {
    orderCurrentActivity.Status =
        RuleFunctions.Helpers.GetActivityStatusString("1", false); // → "IN_PROGRESS"
    RuleFunctions.Helpers.SendDataToDB(orderRequest);
} else {
    RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
}
📋 7. Data Extraction — GROUP ExtendedInfo Parsing

XPath: $orderRequest/OrderData/ExtendedInfo[Name='GROUP']/Value

Input Format

FAMILY_TYPE=<value>|PRODUCT_ID=<value>|COMPANY_CODE=<value>

Example: FAMILY_TYPE=POSTPAID_BUNDLE|PRODUCT_ID=P00123456|COMPANY_CODE=TMV

Parsing Steps

String[] parts = String.split(groupProductId, "\\|");

familyType  = parts[0]; if (String.contains(familyType,  "FAMILY_TYPE="))  familyType  = String.substringAfter(familyType,  "=");
productId   = parts[1]; if (String.contains(productId,   "PRODUCT_ID="))   productId   = String.substringAfter(productId,   "=");
companyCode = parts[2]; if (String.contains(companyCode, "COMPANY_CODE=")) companyCode = String.substringAfter(companyCode, "=");
IndexVariableKey PrefixExample Value
0familyTypeFAMILY_TYPE=POSTPAID_BUNDLE
1productIdPRODUCT_ID=P00123456
2companyCodeCOMPANY_CODE=TMV
Risk: No array length check. If GROUP has <3 tokens, an index-out-of-bounds exception is thrown (caught by outer try/catch → order enters ERROR state).

The rulefunction RuleFunctions.OrderResponse.Response_ATS_BUNDLEPRODUCT_NUMBER is invoked by the response rule when an ATS_SUBMIT_CAMPAIGN response event arrives. It performs:

🚀 18. Migration Notes & Recommendations

Functional Requirements

R1 — Pre-Execution Gate

Implement configurable condition check (SpEL/JSONPath/rule predicate). Default when absent: proceed.

R2 — GROUP Parser Utility

Reusable parser for pipe-delimited KEY=value|KEY=value|KEY=value format. Must include length guard (≥3 tokens) and return a structured object.

R3 — ATS Adapter (submitCampaignReq)

Externalise the XSLT mapping as a dedicated DTO/mapper class. Static values (channel="OMX", productType="TMV", paymentType="Prepaid") should be configurable. Optional fields use null-safe conditional mapping.

R4 — Resubmission Counter Guard

Do NOT increment counter when isResubmitted==true AND requestCount > 0.

R5 — Activity State Machine

After dispatch: Status → IN_PROGRESS, persist. Response handler sets SUCCESS/ERROR.

R6 — Structured Audit Logging

INFO log on dispatch, ERROR log on exception. Full payload toggle via config flag.

R7 — Exception Handling

try/catch all activity logic. On exception: ERROR status, standard response code, ExceptionActivity routing, persist.

/**
 * @description
 * @author DESKTOP-995HR2V
 */
rule Rules.OMConsumers.OMXFM.Request.Request_ATS_BUNDLEPRODUCT_NUMBER {

    attribute {
        priority = 5;
        forwardChain = true;
    }

    declare {
        Concepts.OrderRequest.OrderRequest  orderRequest;
        Concepts.OM.ProcessConfig.Activity  orderCurrentActivity;
    }

    when {
        orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
        orderCurrentActivity.ActivityID == "ATS_BUNDLEPRODUCT_NUMBER";
        orderRequest.ProcessFlow.NextActivityID == "ATS_BUNDLEPRODUCT_NUMBER";
        orderCurrentActivity.Status == "WAITING";
    }

    then {
        boolean isActResub = (orderCurrentActivity.RequestCount > 0
                             && orderRequest.IsOrderResubmitted);

        try {
            Concepts.OM.ProcessConfig.Activity nextAct =
                Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName,
                                         "/Concepts/OM/ProcessConfig/Activity");
            String  chkXPath  = nextAct.PreExecCheck;
            String  chkRes    = "true";
            boolean isSkipped = true;

            if (String.length(nextAct.PreExecCheck) > 0) {
                String sXML = Instance.serializeUsingDefaults(orderRequest);
                chkRes = XPath.execute("/(" + chkXPath + ")", sXML,
                    "ns0=www.tibco.com/be/ontology/Concepts/OrderRequest/OrderRequest");
            }

            if (String.equals(chkRes, "true")) {

                String familyType    = "";
                String productId     = "";
                String companyCode   = "";
                String groupProductId = XPath.evalAsString(
                    "xpath://... $orderRequest/OrderData/ExtendedInfo[Name='GROUP']/Value ...");

                if (!RuleFunctions.Helpers.BRMS.IsBlankOrStringNull(groupProductId)) {
                    String[] parts = String.split(groupProductId, "\\|");

                    familyType  = parts[0]; if(String.contains(familyType, "FAMILY_TYPE="))
                                               familyType  = String.substringAfter(familyType, "=");
                    productId   = parts[1]; if(String.contains(productId, "PRODUCT_ID="))
                                               productId   = String.substringAfter(productId, "=");
                    companyCode = parts[2]; if(String.contains(companyCode, "COMPANY_CODE="))
                                               companyCode = String.substringAfter(companyCode, "=");
                }

                Events.OMConsumers.OMXFM.Request.ATS_SUBMIT_CAMPAIGN reqEvent =
                    Event.createEvent("xslt://{{/Events/OMConsumers/OMXFM/Request/ATS_SUBMIT_CAMPAIGN}}"
                        /* inline XSLT: maps orderRequest fields + productId/companyCode/familyType
                           → submitCampaignReq payload — see Sections 9 and 10 */);

                Event.Ext.sendEventImmediate(reqEvent);

                if (!isActResub) {
                    orderCurrentActivity.RequestCount++;
                }

                long pid = System.nanoTime();
                Event.Ext.sendEventImmediate(Event.createEvent(
                    "xslt://{{/Events/OMConsumers/OMXESB/Logger}}"
                    /* INFO: "Request Sent for ATS_BUNDLEPRODUCT_NUMBER" */));

                isSkipped = false;
            }

            if (!isSkipped) {
                orderCurrentActivity.Status =
                    RuleFunctions.Helpers.GetActivityStatusString("1", false);
                RuleFunctions.Helpers.SendDataToDB(orderRequest);
            } else {
                RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
            }

        } catch (Exception ae) {
            RuleFunctions.Helpers.HandleActivityException(
                orderRequest, orderCurrentActivity, ae, "");
        }
    }
}
