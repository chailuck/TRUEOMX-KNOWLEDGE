Request_OMX_UPDATE_PENDING_PARTIAL_ORDER

Update the pending partial order record in OMX per subscriber; writes MSISDN, orderType, trackingID, channel, and ICCID (from ExtendedInfo ICC_ID or SIM ResourceInfo)
Rule Priority: 5 ForwardChain: true Backend: OMX Internal Pattern: Fire-and-Forget Author: (none)
§1 — Overview & Purpose

This rule fires when the process reaches OMX_UPDATE_PENDING_PARTIAL_ORDER (step 45 in SWAPSIM, only for TARGET subscribers). It sends one UpdatePendingPartialOrderReq message per subscriber (both POU and ChildOU). The pattern is fire-and-forget (sendEventImmediate + RequestCount++). The ICCID field uses an xsl:choose: prefers ExtendedInfo[ICC_ID]/Value if present, falls back to ResourceInfo[SIM]/ValuesArray. There is no credential gate and no CES field in this event. Fan-in: count "000" ResponseCodes == RequestCount.
