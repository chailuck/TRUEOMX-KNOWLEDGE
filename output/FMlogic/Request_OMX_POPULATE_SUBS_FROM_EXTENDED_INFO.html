Request_OMX_POPULATE_SUBS_FROM_EXTENDED_INFO

Internal OMX rule — reconstructs ParentOU + Subscriber concepts from EXISTING_SUB ExtInfo
Backend: None (internal) Namespace: OMXOM Priority: 5 Pattern: Inline — NextActivity direct No response handler
§1 — Overview & Purpose
OMX_POPULATE_SUBS_FROM_EXTENDED_INFO reconstructs working memory objects — a ParentOU concept with Subscriber children — from the pipe-delimited EXISTING_SUB ExtInfo stored in OrderData.ExtendedInfo. It is a data-hydration step: it restores subscriber structure that was serialized earlier in the order flow.
No backend call: Purely in-memory. Reads ExtInfo, creates concepts, appends to order, then calls NextActivity directly. There is no outbound event and no response rulefunction.
EXISTING_SUB format: Pipe-delimited string where each token is MSISDN=RefId (e.g., 0810001111=REF001|0820002222=REF002). MSISDN = substring-before(., "="); RefId/SubscriberId = substring-after(., "=").
Write-back (2 markers): New ParentOU gets ExtendedInfo Name="EXISTING_OU" Value="Y". Each new Subscriber gets ExtendedInfo Name="EXISTING_SUB" Value="Y". These markers signal to downstream rules that this OU/subscriber is an existing (not new) subscription.
