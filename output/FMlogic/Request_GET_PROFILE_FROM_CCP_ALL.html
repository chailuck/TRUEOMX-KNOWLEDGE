Request_GET_PROFILE_FROM_CCP_ALL

Retrieves subscriber profile and price plan information from CCP (ZTE BSS) for all subscribers in the order — ParentOU and ChildOU fan-out
Priority: 5 ForwardChain: true Backend: CCP (ZTE BSS) Pattern: Fan-out per subscriber Generated: 2026-08-13
§1 — Overview & Purpose

This rule fires when the order orchestrator reaches the GET_PROFILE_FROM_CCP_ALL activity. It iterates over every subscriber in the order — both direct subscribers of ParentOU and subscribers nested under ChildOU — and dispatches a GetPrepaidCreditInfoRequest to the CCP (ZTE BSS SmartBSS) system via JMS for each one that has not already responded successfully.

The response handler (Response_GET_PROFILE_FROM_CCP_ALL) receives the queryUserProfileResponse from CCP, extracts the subscriber's active price plans (PricePlanDtoList), and populates SubscriberOffers concepts in working memory — tagged with FE_OR_CCBS=CCP to mark them as CCP-sourced. This data is used downstream for offer validation and billing decisions.

Business Purpose: Determine what offers/price plans a subscriber currently has in CCP before executing a remove-offer or add-offer order. Ensures downstream activities have accurate offer state.

§5 — Execution Flow Diagram
1
Resub check: Determine if this is an order resubmission (isActResub = RequestCount > 0 && IsOrderResubmitted). If true, do not increment RequestCount again.
2
Load nextAct: Retrieve the current Activity concept from working memory by extId to access PreExecCheck.
3
ParentOU loop: Iterate all ParentOU[i] entries in the order.
4
Subscriber loop (POU): For each Subscriber[j] under ParentOU — check if already succeeded (Response with CompletionStatus==2 and matching RefId). Skip if so.
5
PreExecCheck (POU): If nextAct.PreExecCheck is non-empty, build subscriber XML via GetXMLForSubscriber() and evaluate XPath. Skip this subscriber if result ≠ "true".
6
Send request (POU Variant ①): Create and send GET_PROFILE_FROM_CCP event with MSISDN and OrderChannel. Log audit event. Increment RequestCount (if not resub).
7
ChildOU loop: For each ChildOU[p] under the same ParentOU — repeat subscriber loop for Subscriber[q] (ChildOU Variant ②).
8
Status update: If at least one request was sent → set activity Status to GetActivityStatusString("1", false) (REQUESTING) and persist via SendDataToDB(). If all skipped → call SkipActivity(..., "4").
9
Exception handling: Any exception → HandleActivityException(orderRequest, orderCurrentActivity, ae, "").

Functional Requirements

Design Risks

RiskSeverityMitigation
CCP (ZTE BSS) namespace couplingHIGHResponse handler hardcodes http://thaitrue.customization.ws.bss.zsmart.ztesoft.com — any CCP schema change breaks parsing. Add namespace version header.

§18 — Full Source Code
/**
 * @description
 * @author Chayatorn Pan.
 */
rule Rules.OMConsumers.OMXFM.Request.Request_GET_PROFILE_FROM_CCP_ALL {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "GET_PROFILE_FROM_CCP_ALL";
    orderRequest.ProcessFlow.NextActivityID == "GET_PROFILE_FROM_CCP_ALL";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
    try {
      Concepts.OM.ProcessConfig.Activity nextAct = Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName, "/Concepts/OM/ProcessConfig/Activity");
      int iPOULen = orderRequest.OrderData.Customer.ParentOU@length;
      String pouRefId = "";
      boolean isSkipped = true;
      for ( int i=0 ; i < iPOULen ; i++ ) {  // ParentOU Loop
        pouRefId = orderRequest.OrderData.Customer.ParentOU[i].RefId;
        int iSubscriberLen = orderRequest.OrderData.Customer.ParentOU[i].Subscriber@length;
        for( int j=0 ; j<iSubscriberLen ; j++ ) {  // POU Subscriber Loop
          String refId = orderRequest.OrderData.Customer.ParentOU[i].Subscriber[j].RefId;
          boolean reqSuccess = false;
          for(int iResp=0; iResp<orderCurrentActivity.Response@length; iResp++)
            if(String.equals(orderCurrentActivity.Response[iResp].ReferenceId, refId) && orderCurrentActivity.Response[iResp].CompletionStatus==2)
              reqSuccess = true;
          if(!reqSuccess) {
            String chkRes = "true";
            if(String.length(nextAct.PreExecCheck) > 0) {
              String sXML = RuleFunctions.Helpers.GetXMLForSubscriber(orderRequest, refId);
              chkRes = XPath.execute("/("+nextAct.PreExecCheck+")", sXML, "ns0=www.tibco.com/...");
            }
            if(String.equals(chkRes,"true")) {
              Events.OMConsumers.OMXFM.Request.GET_PROFILE_FROM_CCP reqEvent = Event.createEvent(
                /* xslt://GET_PROFILE_FROM_CCP Variant ①  — see §9.8 for full XSLT
                   Outputs: JMSPriority, JMSCorrelationID, OrderID, RefID, OrderType,
                             payload/ns:GetPrepaidCreditInfoRequest{ns:MSISDN, ns:OrderChannel} */);
              Event.Ext.sendEventImmediate(reqEvent);
              if (RuleFunctions.Helpers.AllowWriteLog(orderRequest.OrderData.OrderType)) {
                long pid = System.nanoTime();
                Event.Ext.sendEventImmediate(Event.createEvent(/* Logger XSLT — OPERATION_NAME=GET_PROFILE_FROM_CCP_ALL, AUDIT_TRACE=Request Sent */));
              }
              if(!isActResub) orderCurrentActivity.RequestCount++;
              isSkipped = false;
            }
          }
        }
        int iCOULen = orderRequest.OrderData.Customer.ParentOU[i].ChildOU@length;
        for (int p=0; p < iCOULen; p++) {  // ChildOU Loop
          iSubscriberLen = orderRequest.OrderData.Customer.ParentOU[i].ChildOU[p].Subscriber@length;
          for( int q=0; q<iSubscriberLen; q++ ) {  // COU Subscriber Loop
            // [same success-check, PreExecCheck, send Variant ② pattern]
            /* xslt://GET_PROFILE_FROM_CCP Variant ② — params: orderRequest, i, p, q */
            if(!isActResub) orderCurrentActivity.RequestCount++;
            isSkipped = false;
          }
        }
      }
      if(!isSkipped) {
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch ( Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

§19.1 Overview

The response handler Response_GET_PROFILE_FROM_CCP_ALL receives the queryUserProfileResponse from CCP. It: (1) appends a ResponseBase to the activity's Response array; (2) looks up the Subscriber concept and populates its SubscriberOffers from CCP price plan data; (3) logs the audit response; (4) returns "true" when all fan-in requests are complete.

§19.4 SubscriberOffers Population (CCP Price Plans)

After appending ResponseBase, the handler queries the response payload for CCP price plan entries:

// Count PricePlanDto entries
int priceplanDtoLength = XPath.evalAsInt("count($eventResponse/payload/xsd2:queryUserProfileResponse/xsd2:queryUserProfileReturn/xsd2:PricePlanDtoList/xsd2:PricePlanDto)");

for (int i=0; i<priceplanDtoLength; i++) {
  String pp_name = XPath.evalAsString("$eventResponse/.../xsd2:PricePlanDto[$i+1]/xsd2:PricePlanName");
  // Create SubscriberOffers concept with OfferName=pp_name, ExtendedInfo{FE_OR_CCBS=CCP}
  subscriber.SubscriberOffers[subscriber.SubscriberOffers@length] = subscriberOfferConcept;
}

Key: Each CCP price plan creates a SubscriberOffers concept with ExtendedInfo[Name="FE_OR_CCBS"]/Value="CCP". This marker distinguishes CCP-sourced offers from CCBS-sourced offers (FE_OR_CCBS=CCBS).

§19.5 Subscriber Lookup

The handler looks up the Subscriber concept via two extId patterns:

subscriber = Instance.getByExtIdByUri("SUB:"+OMXTrackingId+":"+RefID, "/Concepts/.../Subscriber");
if(subscriber==null)
  subscriber = Instance.getByExtIdByUri("CSUB:"+OMXTrackingId+":"+RefID, "/Concepts/.../Subscriber");

SUB: = direct subscriber; CSUB: = ChildOU subscriber. Fallback handles both hierarchy levels.

§19.6 Response Completion Logic

CheckExpressionMeaning
Fan-in conditioncurrActivity.RequestCount == currActivity.Response@lengthAll dispatched requests have returned
Return "true"All responses receivedSignals orchestrator to advance to next activity
Return "false"Still waiting for responsesOrchestrator keeps activity in REQUESTING state
Note: Unlike other FMs, this response handler does not use tib:right(tib:trim(ResponseCode), 3) = "000" for success counting. It uses a simple count of all Response entries vs RequestCount — all responses (including errors) contribute to fan-in completion.
