Request_TCC_GET_MNP_AUTO_SHAREPLAN

TIBCO BusinessEvents FM Logic — TCC MNP Auto Shareplan Query
Backend: TCC getMnp900 Pattern: Subscriber-level fan-out Author: MalineeS. Generated: 2026-09-23
§1 — Overview & Purpose

Queries the TCC getMnp900 API once per subscriber (in ParentOU and ChildOU) to obtain the MNP auto shareplan assignment. For each subscriber whose MNP porting MSISDN maps to a shared plan, the response returns the mainNumber (the shareplan's lucky/main number). This is then written as a SHAREPLAN_MAIN_NUMBER ExtendedInfo entry on the subscriber, so downstream steps can provision the shareplan correctly.


The rule iterates all ParentOU.Subscriber[] and ParentOU.ChildOU.Subscriber[] entries. It fires only when the subscriber has not yet received a successful response. If all subscribers are already resolved it calls SkipActivity("4").

§5 — Execution Flow
  1. Detect resubmit: isActResub = (RequestCount > 0 && IsOrderResubmitted)
  2. Load next activity config (Instance.getByExtIdByUri) for PreExecCheck
  3. Iterate ParentOU[i].Subscriber[j]:
    • Skip if subscriber already has a successful response (CompletionStatus=2, matched by RefId)
    • Evaluate PreExecCheck XPath via GetXMLForSubscriber if defined
    • If chkRes="true": build and send TCC_GET_MNP_AUTO_SHAREPLAN event
    • Increment RequestCount (if not resubmit)
  4. Iterate ParentOU[i].ChildOU[k].Subscriber[j] (same logic, uses GetXMLForSubscriberInChildOU)
  5. If no requests sent (isSkipped=true): call SkipActivity(orderRequest, orderCurrentActivity, "4")
  6. Else: set Status = GetActivityStatusString("1", false), call SendDataToDB
  7. Send audit log event

Note: A commented-out variant references TCC_GET_SHAREPLAN_MAIN_NUMBER event (with ns2 namespace) — the active code uses the TCC_GET_MNP_AUTO_SHAREPLAN event exclusively.

§19 — Response Message Rule

§19.1 — Overview

Parses the TCC getMnp900 API response. Extracts mainNumber (lucky number / shareplan main MSISDN) and writes it as SHAREPLAN_MAIN_NUMBER ExtendedInfo on the matching subscriber. Performs fan-in: returns "true" when all request counts are successfully responded.

§19.4 — Post-Response Logic: SHAREPLAN_MAIN_NUMBER ExtendedInfo

If activityRes.mainNumber is not blank/null:

  • Search ParentOU[].Subscriber[] for subscriber whose RefId == activityRes.ReferenceId
  • Create SubscriberExtendedInfo:
    • extId = concat($eventResponse/RefID, ":SHAREPLAN_MAIN_NUMBER:", $activityRes/mnpNumber)
    • Name = "SHAREPLAN_MAIN_NUMBER"
    • Value = $activityRes/mainNumber
  • Append to pOuSub.ExtendedInfo[]

§19.5 — Fan-in Completion Logic

int successResponseCount = count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = "000"])
if (currActivity.RequestCount == successResponseCount) return "true"
else return "false"

Returns "true" (all subscribers responded with success code ending in "000") to signal completion to the orchestrator.
