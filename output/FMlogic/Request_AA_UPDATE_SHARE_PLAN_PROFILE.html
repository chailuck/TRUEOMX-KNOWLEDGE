Request_AA_UPDATE_SHARE_PLAN_PROFILE

Updates AA subscriber profile for SharePlan assignment — reuses AA_ACTIVATE_SUBS event with MNUM AATags; propagates RequestCount to AA_CHECK_CONFIRMATION

Priority: 5Target: AA Event: AA_ACTIVATE_SUBS (reused)Scope: ParentOU + ChildOU Author: SathidP-PCLogLevel: ERROR (anomaly)
§1 — Overview & Purpose
AA_UPDATE_SHARE_PLAN_PROFILE updates the AA (Activation & Assurance) system with the SharePlan multi-number (MNUM) profile for each subscriber. It reuses the AA_ACTIVATE_SUBS event and request schema, but sets specific AATags for the SharePlan relationship: MNUM/MAIN=SHAREPLAN_MAIN_NUMBER and MNUM/CHILD=subscriber MSISDN. After sending, it copies its RequestCount to the corresponding AA_CHECK_CONFIRMATION activity (same Parameter[0]).
⚠ Anomalies:
1. Audit log level = ERROR (unusual for a request log — typically INFO)
2. RequestCount propagation: Copies RequestCount to AA_CHECK_CONFIRMATION activity with matching Parameter[0] — ensures confirmation step knows how many responses to wait for

§5 — Execution Flow
  1. Validate parameters present (throw DATA_ISSUE if empty)
  2. Iterate ParentOU → Subscriber: evaluate PreExecCheck, determine pp/prev_pp from FE_OR_CCBS offer flags
  3. Call ProcessSwitchFeatures() and ConvertBillCycleDate()
  4. Build AA_ACTIVATE_SUBS event with MNUM AATags: MNUM/MNUM=Y, MNUM/MAIN=SHAREPLAN_MAIN_NUMBER, MNUM/CHILD=MSISDN
  5. Send sendEventImmediate(); increment RequestCount
  6. Repeat for ChildOU → Subscriber (same logic)
  7. After all iterations: find AA_CHECK_CONFIRMATION activity with same Parameter[0]; set its RequestCount = this activity's RequestCount
  8. Set status "1"; persist
