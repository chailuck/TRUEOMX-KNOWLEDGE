Request_CCBS_CREATE_PAYMENT_ARRANGEMENT

Backend: CCBS Pattern: Per-Account Loop (IntraActivitySequencing) Priority: 5 ForwardChain: true Generated: 2026-09-14
§1 — Overview & Purpose

Creates a payment arrangement in CCBS for each Account on the order. Uses a rich static business configuration (policy code, treatment type, payment method, interval, indicator) combined with dynamic data from the order (past-due amount, account ID, agreed due date, installment details) to construct the CreatePaymentArrangementRequest payload.

Uses the IntraActivitySequencing pattern with a per-account loop WITH reqSuccess check — if the previous CCBS response for this account was already successful (CompletionStatus==2), the current iteration is skipped to prevent duplicate arrangements.

All business constants are hardcoded in the rule as XSLT parameters — they cannot be configured from activity parameters without a code change.

[MEDIUM] Account[1]/AccountID used inside per-account loop: Multiple places in the rule source reference Account[1]/AccountID even inside the per-account loop iteration. For single-account orders this is harmless; for multi-account orders, every iteration may use the first account's ID instead of the current iteration's account. Verify intent — should be $account/AccountID.
[LOW] All business constants hardcoded: AgreedPolicyCode="PTPPA", BrokenTreatmentType="RESUME", PayMentMethod="CA", IntervalType=68, PaymentArrangementIndicator=78 — not configurable from ProcessConfig parameters without changing the rule file.

§5 — Execution Flow Diagram
  1. Compute isActResub
  2. Call PurgePendingRequestsBeforeResubmit(orderRequest, orderCurrentActivity) if isActResub==true
  3. Compute refId per account (for PreExecCheck and audit)
  4. Loop i = 0 to orderRequest.OrderData.Customer.Account@length - 1
  5. Per iteration: check reqSuccess — if Account[i] already succeeded (CompletionStatus==2 on previous run), skip
  6. Serialize account XML via GetXMLForAccount(orderRequest, refId) for PreExecCheck evaluation
  7. Evaluate PreExecCheck XPath against account-scoped XML
  8. If PreExecCheck fails: skip this account
  9. Build XSLT request with all static constants + dynamic account/amount data
  10. Assert event, ActionRequestEvent, emit per-account audit log
  11. After loop: SendFirstRequestEvent
  12. Status="1" + SendDataToDB

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_CCBS_CREATE_PAYMENT_ARRANGEMENT {
  attribute { priority = 5; forwardChain = true; }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
    if (isActResub) { PurgePendingRequestsBeforeResubmit(orderRequest, orderCurrentActivity); }
    try {
      for (int i = 0; i < orderRequest.OrderData.Customer.Account@length; i++) {
        Account account = orderRequest.OrderData.Customer.Account[i];
        String refId = ...; // per-account refId
        // reqSuccess check: if CompletionStatus==2 for this refId → skip
        int reqSuccess = XPath.evalAsInt("count(Response[RefId=refId and CompletionStatus=2])", ...);
        if (reqSuccess > 0) { continue; }
        String accountXML = GetXMLForAccount(orderRequest, refId); // PreExecCheck scope
        /* PreExecCheck evaluated per-account; if fails → skip account */
        Events...CCBS_CREATE_PAYMENT_ARRANGEMENT reqEvent = Event.createEvent("xslt://...");
        /* XSLT: ns1:CreatePaymentArrangementRequest — see §9 and §10 */
        /* Static params: AgreedPolicyCode=PTPPA, BrokenTreatmentType=RESUME, */
        /*   PayMentMethod=CA, IntervalType=68, PaymentArrangementIndicator=78, etc. */
        /* Dynamic: AgreedDueAmount=PAST_DUE_AMOUNT, EntityId=$account/AccountID */
        /* NOTE: some references use Account[1]/AccountID inside loop */
        Event.assertEvent(reqEvent);
        IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity);
        // Audit: AUDIT_TRACE = "Request Sent for RefId " + $refId
        Event.Ext.sendEventImmediate(logEvent);
      }
      IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
      orderCurrentActivity.Status = GetActivityStatusString("1", false);
      SendDataToDB(orderRequest);
    } catch (Exception ae) { HandleActivityException(orderRequest, orderCurrentActivity, ae, ""); }
  }
}
§19 — Response Message Rule

§19.1 Overview

Creates a CCBSCreatePaymentArrangement response concept, performs no additional post-processing (no order data updates), logs, and advances fan-in via IntraActivitySequencing. The response is purely a confirmation record.
