Request_OMX_ADD_FUT_FULL_SUSPEND

OMX — Add Future Full Suspend Order (activityReason-driven effectiveDate)

Priority: 5 forwardChain: true Backend: OMX Event: OMX_ADD_FUTURE Response: Hardcoded "true" Generated: 2026-09-23
§1 — Overview & Purpose

Creates a future full-suspend order in OMX. The effectiveDate and order type and activity reason are determined by ActivityReason parameter:

ActivityReasoneffectiveDateorderTypeactivityReason
BALOStoday + 3 days18"SUS1"
SUFICend-of-bill-cycle19"RESIC"
SCVGtoday + SoftToFullDaySoftToFullOrderTypeSoftToFullReason
⚠ Naming anomaly: ActivityID is OMX_ADD_FUT_FULL_SUSPEND but JMS event dispatched is OMX_ADD_FUTURE.
⚠ Hardcoded return: The response handler always returns "true" — no fan-in check on ResponseCode. This is unique among all OMX FMs and must be documented as a migration risk.

Subscriber selection: Uses tib:if-absent to get first available subscriber: ParentOU[1].Subscriber[1] OR ChildOU[1].Subscriber[1].

SOC selection: code = SOC of offer where ServiceType='80' AND FE_OR_CCBS='FE'.

§5 — Execution Flow
  1. Check resubmit; evaluate PreExecCheck
  2. Get first subscriber via tib:if-absent
  3. Resolve code (SOC): offer where ServiceType='80' AND FE_OR_CCBS='FE'
  4. Branch on ActivityReason (BALOS / SUFIC / SCVG) → set effectiveDate, orderType, activityReason
  5. Build futureOrderWithSoc payload; send OMX_ADD_FUTURE event
  6. Increment RequestCount; send audit log
  7. Set WAITING_RESPONSE; persist to DB
