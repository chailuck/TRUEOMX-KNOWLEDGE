§1 — Overview & Purpose

Cancels a Call Verify (call verification) feature on the mobile number via the SFF (Soft Feature Function) system. This is invoked when a subscriber's call verification is active but the CALL_VER_RESULT indicates it did not pass (CALL_VER_RESULT != "PASS").

Used in CANCEL_SUBSCRIBER process — Step 75 — gated on CALL_VER_RESULT != "PASS" and not ATS. Sends per-subscriber requests to SFF to remove the call verification feature.

Payload is minimal: only the subscriber's MSISDN (productIdNumber) and OMXTrackingId (refId) are required.

§5 — Execution Flow
  1. Resubmit check → PurgePendingRequestsBeforeResubmit() if resubmit
  2. Iterate ParentOU subscribers only
  3. For each: check if response already received (CompletionStatus==2)
  4. Evaluate PreExecCheck (CALL_VER_RESULT != "PASS" gate)
  5. Create SFF_CANCEL_CALL_VERIFY_MOBILE event with MSISDN + OMXTrackingId
  6. Event.assertEvent + IntraActivitySequencing.ActionRequestEvent()
  7. Send audit log
  8. After loop: SendFirstRequestEvent(), Status="1", SendDataToDB (or SkipActivity if no requests sent)

§17 — Migration Notes

R1: SFF is a legacy call-feature system — verify whether it survives the TRUE-DTAC network integration or if an equivalent service is needed.

R2: CALL_VER_RESULT is populated by an earlier step (not shown in this FM) — ensure the upstream supplier still sets this field.

R3: Only iterates ParentOU subscribers (no ChildOU loop) — verify if this is intentional for the SFF service scope.

Risk: MEDIUM — If SFF is decommissioned or replaced, this step needs equivalent cancel-call-verify logic in the new platform.
