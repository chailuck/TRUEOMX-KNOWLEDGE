Request_OMX_INJECT_OFFER

In-memory offer injection — creates SubscriberOffers or AgreementOffers from ProcessConfig parameters

Rule: Rules.OMConsumers.OMXOM.OMX_INJECT_OFFER Type: In-memory enrichment (no backend call) Author: DESKTOP-KB4BEG4 Generated: 2026-09-18
§1 — Overview & Purpose

OMX_INJECT_OFFER is a pure in-memory enrichment rule. It reads offer specification from the Parameter fields of the current Activity (comma-separated key=value pairs), evaluates the runtime PreExecCheck, then creates and appends SubscriberOffers or AgreementOffers concept instances to the live order model in TIBCO BusinessEvents working memory. No ESB call, no JMS event, no response handler.

This allows ProcessConfig designers to declaratively inject offers at any point in a flow without writing a new rule per offer. The same rule handles both subscriber-level (level=SUB) and OU-agreement-level (level=OU) injection across POU and COU hierarchies.

Found in Rules/OMConsumers/OMXOM/ (not OMXFM) — this is an OMX orchestration rule, not a functional module that calls an external system.

§5 — Execution Flow
  1. Evaluate runtime PreExecCheck from orderCurrentActivity.PreExecCheck via XPath.execute()
  2. If PreExecCheck fails → SkipActivity("4") and exit
  3. Log "InjectOffer Started" via sendEventImmediate(Logger)
  4. If orderRequest.OrderData.Customer.ParentOU@length == 0 → create a default ParentOU + Subscriber
  5. Loop iParam over all orderCurrentActivity.Parameter entries
  6. Parse each Parameter string (csv) → extract: soc, serviceType, action, offerName, level, checkDup, source, accOpenDate, mapCugId, checkExistingOu
  7. Validate required params: soc, serviceType, action, level — throw DATA_ISSUE if missing
  8. Loop POU (iPOU):
      • If level=OU: dedup check → checkExistingOu guard → create AgreementOffers + append to POU.Agreement.Offers
      • Loop POU Subscriber (ps): if level=SUB: dedup check → create SubscriberOffers + append
      • Loop ChildOU (iPCOU): same OU/SUB logic for child hierarchy
  9. Call NextActivity(orderRequest, orderCurrentActivity)
  10. Log "InjectOffer Completed" via sendEventImmediate(Logger)
  11. Exception → HandleActivityException(orderRequest, orderCurrentActivity, ae, "")

§9 — Object Construction (SubscriberOffers / AgreementOffers)

§9.1 SubscriberOffers (level=SUB)

  • SubscriberOffers Always
    • @extId ← concat(OMXUtils:generateTrackingID(), ':INJECT_OFFER') Always
    • EffectiveDate ← $orderRequest/OrderData/EffectiveDate Conditional: string-length > 0
    • OfferName ← param offerName Always
    • ServiceType ← param serviceType Always
    • Soc ← param soc Always
    • Action ← param action (ADD/REMOVE) Always
    • ParameterInfo/CUG ID ← OrderData/ExtendedInfo[GROUP_ID]/Value Conditional: mapCugId=Y and GROUP_ID exists
    • ExtendedInfo/FE_OR_CCBS ← param source (or "INJECT_OFFER" if blank) Always

§9.2 AgreementOffers (level=OU)

  • AgreementOffers Always
    • @extId ← concat(OMXUtils:generateTrackingID(), ':INJECT_OFFER')
    • EffectiveDate ← Account.OpenDate (if accOpenDate=Y, with compare-date logic) Conditional: accOpenDate=Y
    • EffectiveDate ← $orderRequest/OrderData/EffectiveDate Conditional: accOpenDate≠Y and string-length > 0
    • OfferName / ServiceType / Soc / Action ← params (same as SUB) Always
    • ExtendedInfo/FE_OR_CCBS ← param source (or "INJECT_OFFER") Always
    • ExtendedInfo/ACC_OPEN_DATE = "Y" ← static "Y" Conditional: accOpenDate=Y

    orderRequest.ProcessFlow.NextActivityID == "OMX_INJECT_OFFER";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    // 1. Evaluate runtime PreExecCheck from activity config
    // 2. Log "InjectOffer Started"
    // 3. Auto-create ParentOU/Subscriber if absent
    // 4. Loop iParam over Activity.Parameter (csv parse: soc,serviceType,action,offerName,level,...)
    // 5. Validate required params (DATA_ISSUE if missing)
    // 6. Loop POU → Subscriber → ChildOU → ChildOU.Subscriber

    //    dedup check via XPath.evalAsBoolean
    // 7. NextActivity() + Log "InjectOffer Completed"

}
