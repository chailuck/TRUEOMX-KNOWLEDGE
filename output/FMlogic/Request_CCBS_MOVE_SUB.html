Request_CCBS_MOVE_SUB

Backend: CCBS (MoveSubscriber) Pattern: Fire-and-Forget Author: awalia-t420 Generated: 2026-09-23
§1 — Overview & Purpose

Moves subscribers to a new organizational unit (OU) in CCBS. Contains 4 distinct OrderType-specific branches, with different subscriber selection, OU targeting, and policy values. The activity parameter MOVE_TO_OU specifies which SOURCE_OR_TARGET value identifies the destination OU. Sends one event per subscriber (POU and ChildOU) via fire-and-forget. The response handler updates the subscriber's SubscriberId in working memory from the CCBS response payload.

Bug: ChildOU audit logger uses OPERATION_NAME = "CCBS_MOVE_SUBS" (extra 'S') while POU logger uses "CCBS_MOVE_SUB". This causes inconsistent audit trail entries for multi-OU moves. Fix in migration target.

§5 — Execution Flow
  1. Get MOVE_TO_OU parameter via GetActivityParamValueFromKey(activity, "MOVE_TO_OU")
  2. Iterate POU[i] → Subscriber[j]; evaluate PreExecCheck
  3. Determine OrderType branch (36, 11001, 11002+countNewPou, default)
  4. Build MoveSubscriberRequest event with branch-specific fields
  5. Event.Ext.sendEventImmediate(reqEvent); RequestCount++
  6. Repeat for ChildOU[k] → Subscriber[j]
  7. Set IN_PROGRESS; send audit log (POU: "CCBS_MOVE_SUB"; ChildOU: "CCBS_MOVE_SUBS" — BUG)

§19 — Response Message Rule

§19.1 Overview

Creates CCBS_MoveSubscriberRes concept. Critically: updates each subscriber's SubscriberId in working memory with the new ID from CCBS response payload (SubscriberIdsInfo/SubscriberId/SubscrNumber), matched by RefID. Also writes ResponseCode/ResponseMsg back to subscriber. Fan-in via count "000" == RequestCount.

§19.3 Subscriber ID Update (Key Post-Processing)

// For each POU[i].Subscriber[j] where RefId == eventResponse.RefID:
subscriber.SubscriberId = eventResponse.payload/SubscriberIdsInfo/SubscriberId/SubscrNumber
subscriber.ResponseCode = eventResponse.ResponseCode
subscriber.ResponseMsg = eventResponse.ResponseMsg
// Also for ChildOU[k].Subscriber[j]

§19.4 Fan-in Completion

successResponseCount = count($currActivity/Response[tib:right(tib:trim(ResponseCode),3)="000"])
if (currActivity.RequestCount == successResponseCount) → return "true"
else → return "false"
