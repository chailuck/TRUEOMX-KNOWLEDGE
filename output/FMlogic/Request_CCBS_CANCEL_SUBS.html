§1 — Overview & Purpose

Sends a CancelSubscriber request to CCBS for each subscriber in the order. This is the core CCBS cancellation operation — it terminates the subscriber record in CCBS billing system, setting portOutIndicator (89=MNP, 78=standard) and an optional activity date (for back-dated cancellations).

Used in CANCEL_SUBSCRIBER process — Step 57. Also used in other order types (126, 127, 129, 15, 16) with back-date support.

Uses IntraActivitySequencing for fan-in completion — supports parallel CCBS calls across multiple subscribers.

§5 — Execution Flow
  1. Resubmit check — if resubmit: PurgePendingRequestsBeforeResubmit()
  2. Fetch LogicalDate concept for back-date calculations
  3. Get ALT_CES parameter from activity configuration
  4. Compute back-date flag: true for OrderTypes 126, 127, 129, 15, 16
  5. If back-date: compute strBackDate = EffectiveDate-1sec (or LogicalDate-1sec, or today-1sec)
  6. Iterate ParentOU subscribers — skip already-responded (CompletionStatus==2)
  7. Per-subscriber: evaluate PreExecCheck, compute activityDate (back-date vs EffectiveDate)
  8. Create and assert CCBS_CANCEL_SUBS event via IntraActivitySequencing.ActionRequestEvent()
  9. Repeat for ChildOU subscribers
  10. After loops: SendFirstRequestEvent(), set Status="1", SendDataToDB

§17 — Migration Notes

R1: portOutIndicator 89 (MNP channel) vs 78 (standard) — must be preserved exactly.

R2: Back-date calculation for order types 126/127/129/15/16 — EffectiveDate-1sec logic is critical for billing correctness.

R3: OLD_BAN_DATE guard prevents back-date before account activation — preserve this check.

Risk: HIGH — Core CCBS cancellation. Any mismatch in portOutIndicator or activityDate causes billing errors.
