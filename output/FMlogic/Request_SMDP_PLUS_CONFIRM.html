§1 — Overview & Purpose

This rule sends a ConfirmOrderRequest to SM-DP+ to confirm a previously initiated eSIM profile download. It is the second of two SMDP steps: SMDP_PLUS initiates the download; SMDP_PLUS_CONFIRM acknowledges completion and releases the profile for the device. Structurally identical to SMDP_PLUS with five key payload differences: ConfirmOrderRequest schema, a mandatory releaseFlag="true", a matchingId field from PMATCHID resources, an optional smdsAddress field, and no "BLANK" suppression for any parameter.

Relationship to SMDP_PLUS: This rule shares the same author, same two-branch dispatch structure (RIO_SWAP/ESIM vs standard), same eSIM offer filter (serviceType="80"), same FE_OR_CCBS/PreExecCheck pattern, same credential inclusion, and same exception handler. The COU Branch A variable bug present in SMDP_PLUS is fixed here — COU correctly uses $subscriber. Fan-in reverts to standard "000" (3-char) check.

§9 — Execution Flow
  1. Read parameters: ICCID, EID, VENDOR, MATCHING (dead), ORDER, PROJ
  2. Read LogicalDate (dead) + initialize dead variables
  3. Loop POU Subscribers → Loop Offers:
    1. eSIM filter (serviceType="80") — skip unless RESUME/ESIM mode
    2. FE_OR_CCBS filter + PreExecCheck
    3. reqSuccess check: Response[ReferenceId == SubscriberId AND CompletionStatus==2]
    4. Branch A (RIO_SWAP/ESIM): OLD_EID/ESIM gate → send event → break
    5. Branch B: send per-offer event (no break)
  4. Loop COU Subscribers → Loop Offers — same; COU Branch A uses $subscriber correctly
  5. If !isSkipped: GetActivityStatusString("1", false) + SendDataToDB()
  6. Else: SkipActivity("4")
  7. catch: status reset + HandleActivityException() + restore

§17 — Migration Notes & Recommendations

Functional Requirements

  • R1 — Only process eSIM offers (serviceType="80") unless ORDER=RESUME or PROJ=ESIM
  • R2 — PROJ=RIO_SWAP/ESIM: one event per subscriber (break); resource-only EID fallback in Branch A
  • R3 — Standard PROJ: one event per qualifying offer; eIdValue → PEID → EID(FE) chain
  • R4 — releaseFlag="true" always emitted (confirms profile release to device)
  • R5 — matchingId from PMATCHID(FE, not NONE_) → NEW_PMATCHID (Branch A only) → " " (space default)
  • R6 — smdsAddress optional — only emitted when ExtendedInfo[Name="smdsAddress"] is present
  • R7 — No "BLANK" suppression — all three fields (iccid, eid, vendor) always emitted if value available
  • R8 — Fan-in: last 3 chars "000" (standard — different from SMDP_PLUS "00")
  • R9 — Response TRUE path also calls SendDataToDB (unlike most other FMs)
