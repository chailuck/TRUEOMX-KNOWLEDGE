Request_OMX_SAVE_RESOURCE_INFO

Saves partial order state (swapsim) to downstream OMX system — persists subscriber resource and offer data mid-flow

Priority: 5 ForwardChain: true Target: OMX Internal Event: OMX_SAVE_PARTIAL_ORDER Scope: ParentOU + ChildOU
§1 — Overview & Purpose
OMX_SAVE_RESOURCE_INFO persists a partial order record to an OMX downstream system at the mid-point of a SIM-swap or resource change flow. It fires the OMX_SAVE_PARTIAL_ORDER event with status="swapsim", carrying the full subscriber context, offers, resource info, and extended info arrays. Required for the GET_AND_CONFIRM_RESOURCE order flow.

§5 — Execution Flow
  1. Validate required parameter ACTION via GetActivityParameterValueFromKey; throw DATA_ISSUE if absent
  2. Iterate ParentOU[p] → Subscriber[ps]: check if response already received (CompletionStatus==2 + RefId match)
  3. Evaluate PreExecCheck per subscriber (if defined)
  4. Build OMX_SAVE_PARTIAL_ORDER event via XSLT; include full subscriber context, offers, resources, extended info
  5. Send event (Event.sendEvent()); increment RequestCount; log audit
  6. Repeat for ChildOU[c] → Subscriber[cs] (same logic)
  7. Set activity status to "1" (SENT); persist via SendDataToDB

§19.4 Response Completion Logic

Success XPath: count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = "000"])
Fan-in condition: currActivity.RequestCount == successResponseCount
→ returns "true" when all sent requests have received ResponseCode ending in "000"
→ returns "false" if any are still pending or failed
