§1 — Overview & Purpose

INTX_GET_PRODUCT_PREFERENCE_LIST queries the INTX system for an existing product preference list associated with the customer's identification document (certificate). It is used during ACTIVATION to discover existing product preferences linked to the customer's ID, enabling pre-population of subscriber data or validation of existing subscriptions.


The rule sends a GetProductPreferenceListReq request with the customer's identification (certificate number) and optional search filters (SUBSTATUS, BUSINESSLINE, COMPANYCODE, CUSTOMERSEGMENT). The response handler can optionally extract the MSISDN list from the preference records and create new Subscriber concepts in the order hierarchy.

§5 — Execution Flow
  1. Check resubmit flag: isActResub = (RequestCount > 0 && IsOrderResubmitted)
  2. Evaluate PreExecCheck — if fails, call SkipActivity("4") and exit
  3. Extract optional parameters: SUBSTATUS, BUSINESSLINE, COMPANYCODE, CUSTOMERSEGMENT via GetActivityParameterValueFromKey
  4. Build INTX_GET_PRODUCT_PREFERENCE_LIST request event via XSLT (payload: ns2:GetProductPreferenceListReq with certificate search)
  5. Send event: Event.Ext.sendEventImmediate(reqEvent)
  6. Increment RequestCount if not resubmit
  7. Send REQ audit log
  8. Set orderCurrentActivity.Status = GetActivityStatusString("1", false) (ACTIVE/WAITING_FOR_RESPONSE)
  9. Call SendDataToDB(orderRequest)

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_INTX_GET_PRODUCT_PREFERENCE_LIST {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when { /* ActivityID == "INTX_GET_PRODUCT_PREFERENCE_LIST", Status == "WAITING" */ }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    try {
      // PreExecCheck gate — SkipActivity if fails
      // Extract params: SUBSTATUS, BUSINESSLINE, COMPANYCODE, CUSTOMERSEGMENT
      // Build event via XSLT:
      //   ns2:GetProductPreferenceListReq with Identification (CERTIFICATE search)
      //   + optional searchInfoArray entries per non-empty params
      //   [see §9 for full payload tree]
      Event.Ext.sendEventImmediate(reqEvent);
      if(!isActResub) orderCurrentActivity.RequestCount++;
      // sendEventImmediate(Logger REQ)
      orderCurrentActivity.Status = GetActivityStatusString("1", false);
      SendDataToDB(orderRequest);
    } catch (Exception ae) { HandleActivityException(orderRequest, orderCurrentActivity, ae, ""); }
  }
}
§19 — Response Message Rule

§19.1 — Overview

Response_INTX_GET_PRODUCT_PREFERENCE_LIST receives the INTX response, creates a SearchPreVerifyRes response concept, extracts the total result count, and optionally builds a Subscriber hierarchy from the returned MSISDN list.

§19.5 — GET_MSISDN_LIST=Y Branch

When the activity parameter GET_MSISDN_LIST=Y is set, the response handler:

  1. Builds a de-duplicated MSISDN list from existing order subscribers
  2. Reads MSISDNs from INTX response: productPreferenceList/productPreferenceInfoArray/subscriber/primResourceValue
  3. Adds new MSISDNs not already in the list
  4. If no ParentOU exists (pOuLen==0): creates a new ParentOU concept
  5. For each new MSISDN: creates a new Subscriber concept with MSISDN and RefId set, appends to ParentOU[0].Subscriber[]
