§1 — Overview & Purpose

CCBS_VALIDATE_ACCT_STATUS_ROOT_OU calls CCBS to validate the account status for each root-level Organizational Unit (ParentOU) associated with the customer. It is used during ACTIVATION to verify that the customer's account is in a valid state before proceeding with subscriber activation.


The rule fans out one CCBS request per ParentOU, using IntraActivitySequencing to send requests one at a time. The response returns rich account header data including credit information, collection status, agreement IDs, and billing details — all stored as CCBS_ValidateAcctStatusRootOURes concepts on the activity response array.

Resubmit-aware: uses IntraActivitySequencing.PurgePendingRequestsBeforeResubmit when resubmitting, and skips re-requesting OUs that already have a successful response (CompletionStatus==2).

§5 — Execution Flow
  1. Check resubmit flag: isActResub = (RequestCount > 0 && IsOrderResubmitted)
  2. If resubmit: call IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity)
  3. Loop over ParentOU[0..n] for each POU:
    a. Check if already successfully responded: Response[].ReferenceId == refId AND CompletionStatus==2 → skip if true
    b. Evaluate per-POU PreExecCheck via GetXMLForOU + XPath.execute
    c. If PreExecCheck passes: build and assert request event for this POU
    d. Call IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity)
    e. Send REQ audit log
  4. After loop: if any request was sent, call IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity)
  5. Set status to ACTIVE, call SendDataToDB
  6. If all POUs skipped: call SkipActivity("4")

§18 — Full Source Code
// @author awalia-t420
rule Rules.OMConsumers.OMXFM.Request.Request_CCBS_VALIDATE_ACCT_STATUS_ROOT_OU {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when { /* ActivityID == "CCBS_VALIDATE_ACCT_STATUS_ROOT_OU", Status == "WAITING" */ }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    try {
      if(isActResub) IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity);

      for (int i = 0; i < iPOULen; i++) {
        // Skip if already responded with CompletionStatus==2
        // Evaluate per-POU PreExecCheck via GetXMLForOU
        // Build event via XSLT: ns:ValidateAccountStatusOURequest {OUId, customerId}
        //   [see §9 for full payload — credential-gated UserName/PassWord headers]
        Event.assertEvent(reqEvent);
        IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity);
        // sendEventImmediate(Logger REQ)
      }
      if(!isSkipped) {
        IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
        orderCurrentActivity.Status = GetActivityStatusString("1", false);
        SendDataToDB(orderRequest);
      } else { SkipActivity(orderRequest, orderCurrentActivity, "4"); }
    } catch (Exception ae) { HandleActivityException(orderRequest, orderCurrentActivity, ae, ""); }
  }
}
§19 — Response Message Rule

§19.1 — Overview

Response_CCBS_VALIDATE_ACCT_STATUS_ROOT_OU receives each POU's CCBS response, creates a rich CCBS_ValidateAcctStatusRootOURes concept with account, collection, billing, and agreement data, appends it to the activity response array, and calls IntraActivitySequencing.ActionResponseEvent to either send the next queued request or signal completion.

§19.4 — Response Completion Logic

Standard success-count fan-in is commented out. Completion is determined by IntraActivitySequencing.ActionResponseEvent(currActivity):
— If more queued requests exist → sends next request, returns false (not complete)
— If all requests responded → returns true (complete, triggers next activity)
