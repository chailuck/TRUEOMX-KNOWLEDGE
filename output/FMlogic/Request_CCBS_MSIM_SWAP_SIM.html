Request_CCBS_MSIM_SWAP_SIM

Execute SIM swap in CCBS for Multi-SIM (MSIM) subscribers; pre-populates ResourceInfo (OLD_IMEI/IMEI/EID/SIM/IMSI) before dispatch and marks IS_CALLED_MSIM_SWAP_SIM=Y
Rule Priority: 5 ForwardChain: true Backend: CCBS (MSim) Pattern: IntraActivitySequencing Author: sakarin-radchapunya
§1 — Overview & Purpose

This rule fires when the process reaches CCBS_MSIM_SWAP_SIM. It performs the CCBS SIM swap for Multi-SIM (MSIM) subscribers. Before building the request event, it pre-populates the subscriber's ResourceInfo with missing values: OLD_IMEI (from OLD_MIIMEI), IMEI (from NEW_MIIMEI), EID (from NEW_EID), SIM (from NEW_SIM), IMSI (from NEW_IMSI) — only added when not already present. It builds a mSimData/OUList payload containing the subscriber ID, an empty Master MultiSIMInfo placeholder, all ResourceInfo entries, and ActivityReason/UserText. The pattern is IntraActivitySequencing. As a side effect, IS_CALLED_MSIM_SWAP_SIM=Y is set in subscriber.ExtendedInfo to gate downstream steps. Two XSLT variants exist: one for POU subscribers (includes RefID), one for ChildOU subscribers (no RefID in header).

§5 — Execution Flow
1
If resubmit: PurgePendingRequestsBeforeResubmit
2
Loop POU[i] → Subscriber[j]; evaluate PreExecCheck; check reqSuccess guard
3
Pre-populate ResourceInfo: Add OLD_IMEI (from OLD_MIIMEI), IMEI (from NEW_MIIMEI), EID (from NEW_EID), SIM (from NEW_SIM), IMSI (from NEW_IMSI) only if missing
4
Build and assert CCBS_MSIM_SWAP_SIM request event; ActionRequestEvent
5
If not resubmit: set IS_CALLED_MSIM_SWAP_SIM=Y in subscriber.ExtendedInfo
6
Repeat for ChildOU[k] → Subscriber[j] (same logic, no pre-populate for ChildOU subscribers)
7
SendFirstRequestEvent → set IN_PROGRESS; or SkipActivity
