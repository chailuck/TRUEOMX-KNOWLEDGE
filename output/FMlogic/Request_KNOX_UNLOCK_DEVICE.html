Request_KNOX_UNLOCK_DEVICE

Send Knox proxy unlock command per subscriber offer — iterates SubscriberOffers, dispatches KNOX_PROXY_SERVICE with method="unlockDevice"

Priority: 5 ForwardChain: true Target: Knox (via proxy) Event: KNOX_PROXY_SERVICE Fan-in: RequestCount == successResponseCount Used in RESTORE: Step 25
§1 — Overview & Purpose

This FM sends a Knox device unlock command for each subscriber offer where the subscriber has a Knox-enrolled device (IMEI_KNOX is populated). It iterates the full ParentOU/ChildOU/Subscriber/SubscriberOffers tree, builds a knoxProxyReq with method="unlockDevice", and sends it immediately (not via IntraActivitySequencing).


Event naming note: The rule dispatches event type KNOX_PROXY_SERVICE — not KNOX_UNLOCK_DEVICE. The ActivityID "KNOX_UNLOCK_DEVICE" is the FM name in ProcessConfig; the actual JMS event is the generic Knox proxy service endpoint.

RefID construction: pSubRefId + ":" + offer.Soc + ":" + FE_OR_CCBS_filter — offer-level granularity, not just subscriber-level.

§6 — Rule Action (THEN) — Key Details

Offer-level fan-out

Unlike most FMs that iterate Subscribers, this FM iterates SubscriberOffers within each Subscriber. The RefID is therefore SubRefId:Soc:FE_OR_CCBS — a per-offer identity.


transactionId construction

concat($offer/ExtendedInfo[Name="IMEI_KNOX"]/Value, tib:timestamp())

Combines the IMEI value with a server-side timestamp — unique per request.


Direct send (no IntraActivitySequencing)

Uses Event.Ext.sendEventImmediate(reqEvent) directly — parallel fan-out, not sequential. RequestCount is manually incremented (orderCurrentActivity.RequestCount++).


PreExecCheck difference between ParentOU and ChildOU: ParentOU uses GetXMLForSubscriberOfferFilterWithExtendedInfo(orderRequest, pSubRefId, offer.Soc, filter) while ChildOU uses GetXMLForSubscriberInChildOU(orderRequest, cSubRefId, pOuRefId) — different helper functions.
