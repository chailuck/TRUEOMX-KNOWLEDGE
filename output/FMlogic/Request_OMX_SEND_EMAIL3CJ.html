Request_OMX_SEND_EMAIL3CJ

3CJ Email Send — sends transactional email per Subscriber (ChildOU + POU) using template from FM34; supports PICKUP_SHOP / DEVICE_BUNDLE / default action modes
Backend: 3CJ (Email) Priority: 5 Pattern: FIRE-AND-FORGET per Subscriber Author: Chayatorn P. Depends: EMAIL_TEMPLATE_CONTENT from FM34
§1 — Overview & Purpose
OMX_SEND_EMAIL3CJ sends a transactional email via the 3CJ email service for each qualifying Subscriber. The email template is identified by EMAIL_TEMPLATE_CONTENT ExtInfo (written by FM34) — the rule parses substring-before(EMAIL_TEMPLATE_CONTENT, ".") for the template_id and substring-after for the version.
Fire-and-forget per Subscriber: Event.Ext.sendEventImmediate + manual RequestCount++. Fan-in: count("000") == RequestCount.
Depends on FM34: EMAIL_TEMPLATE_CONTENT must be present in Subscriber ExtInfo (set by FM34 response). If FM34 was skipped, template_id and version will be empty strings.
Three ACTION modes: PICKUP_SHOP, DEVICE_BUNDLE, and default (SIM/MSISDN only). Parameters ACTION and CID are read from ProcessConfig.
Two iteration loops: ChildOU Subscribers first (outer: POU → ChildOU → Subscriber), then POU Subscribers separately. Both loops share the same XSLT payload structure.
