Request_CVSS_CREDIT_CHECK

CVSS Credit Evaluation — per-account EvaluateCreditRequest with customer-type dispatching
Backend: CVSS Author: awalia-t420 Priority: 5 Pattern: IntraActivitySequencing Iteration: Account[]
§1 — Overview & Purpose
CVSS_CREDIT_CHECK evaluates credit class for each Account by submitting a full customer profile to CVSS (Credit Validation & Scoring System). The response updates Account.AccountManagementInfo.CreditClass with the CVSS-evaluated value.
Account-level iteration: Loops Customer.Account[], sending one EvaluateCreditRequest per Account. Skips accounts where a CompletionStatus==2 response already exists (resubmit protection).
Response write-backs (3): (1) Saves existing CreditClass as CURRENT_CREDITCLASS ExtInfo (backup). (2) Overwrites Account.AccountManagementInfo.CreditClass with CVSS value. (3) Appends CVSS_CREDIT_CHECK_COMPLETE ExtInfo marker.
Two XSLT variants: Old XSLT (commented out, OMX-2748) did not include CES field. Active XSLT adds <CES>. The payload structure is otherwise identical. OrderType=11002 extracts approveCode in the BE rule but this variable is not passed to the XSLT.

§17 — Migration Notes & Recommendations
RiskSeverityMitigation
OrderType=11002 extracts approveCode in BE rule but does not pass it to the XSLT — dead code after OMX-2748 refactor. Active XSLT uses maxAllowApproveCode / POU.ExtInfo[APPROVE_CODE] directly MEDIUM Remove BE-level approveCode extraction in migration; confirm active XSLT path is correct for 11002
creditClass in Prerequisiteinfo is always xsi:nil=true — CVSS receives no prior credit class hint LOW Document as intentional; CVSS independently evaluates
Hardcoded userid=60001 and education="ED5" — undocumented constants LOW Move to global variables or configuration in migration
timeinbusiness and timeinemp both map to CustomerGeneralInfo.TimeInBusiness — likely intentional but field duplication LOW Verify with CVSS API specification; may need distinct sources
CURRENT_CREDITCLASS backup written before overwrite only if CreditClass.length > 0 — if CreditClass empty, no backup is created LOW Acceptable; backup is only needed when existing value is present
Large payload (40+ fields) with many hardcoded empty strings — CVSS may reject or ignore these LOW Review CVSS schema; consider omitting xsi:nil / empty string fields in migration
