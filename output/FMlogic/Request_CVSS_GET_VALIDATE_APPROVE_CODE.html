Request_CVSS_GET_VALIDATE_APPROVE_CODE

CVSS — Validate Approve Code(s) for MaxAllow, IR, CreditLimit, and SharePlan Scenarios
Backend: CVSS Pattern: sendEventImmediate (single or fan-out per list) Priority: 5 Author: awalia-t420 Generated: 2026-09-21
§1 — Overview & Purpose

CVSS_GET_VALIDATE_APPROVE_CODE validates one or more approval codes from the order against CVSS. Used during ACTIVATION to verify that approve codes for max-allow, IR (international roaming), credit limit, and MNP scenarios are valid before proceeding with provisioning.

Two execution paths:
  • Path A (isApproveList=true): SharePlan mode — one request per maxAllowApproveCodeList entry via sendEventImmediate fan-out
  • Path B (isApproveList=false): Standard mode — single request containing up to 4 getValidateApproveCode blocks (maxAllow, maxAllow_MNP, ir, ir_MNP, simbundle)
Response fan-in: Unconditional return "true" — response handler iterates all getValidateApproveCodeResponse blocks in the payload and stores results.

§5 — Execution Flow
  1. Evaluate PreExecCheck (global serialize) — if fails → SkipActivity
  2. Evaluate isApproveList = count(maxAllowApproveCodeList) > 0
  3. Path A (isApproveList=true): Find subType from POU[0].Subscriber where SHAREPLAN_PARENT_TYPE exists → SubscriberType
  4. Path A: For each maxAllowApproveCodeList[i]: send one request with approveCode, numberOfRequest, idNumber, companyCode=subType, requestType="maxallow", customerLevel="NON-TOP", customerType; RequestCount++
  5. Path B (isApproveList=false): Send single request with payload containing multiple optional getValidateApproveCode blocks based on order data (see §7)
  6. RequestCount++; status ACTIVE; SendDataToDB
