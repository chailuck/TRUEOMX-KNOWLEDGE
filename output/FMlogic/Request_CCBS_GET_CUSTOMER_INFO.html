Request_CCBS_GET_CUSTOMER_INFO

CCBS — Retrieve Customer Header / Identification Info

Priority: 5 forwardChain: true Backend: CCBS Event: CCBS_GET_CUSTOMER_HEADER Generated: 2026-09-23
§1 — Overview & Purpose

Fires when the order orchestrator reaches the CCBS_GET_CUSTOMER_INFO activity. Retrieves customer header data from CCBS using the GetCustomerHeaderRequest operation. Despite the activity name suggesting full customer info, the dispatched JMS event type is CCBS_GET_CUSTOMER_HEADER — indicating this rule reuses the header event channel.

The response handler (via parameter flags) can optionally extract and write back:

  • OLD_IDENTIFICATION ExtendedInfo — when GET_OLD_IDENTIFICATION=Y
  • CustomerGeneralInfo.Identification — when GET_CUST_GENERAL_INFO=Y
⚠ Naming anomaly: ActivityID is CCBS_GET_CUSTOMER_INFO but the JMS event type dispatched is CCBS_GET_CUSTOMER_HEADER. Both share the same underlying CCBS operation (GetCustomerHeaderRequest). Modernization should clarify this naming discrepancy.

§5 — Execution Flow
  1. Check resubmit flag (isActResub)
  2. Read PreExecCheck XPath from activity; evaluate against serialized orderRequest
  3. If check passes: build GetCustomerHeaderRequest event via XSLT and send immediately
  4. Increment RequestCount (skip if resubmit)
  5. Send audit log event
  6. Set status to WAITING_RESPONSE via GetActivityStatusString("1", false)
  7. If check fails: call SkipActivity(orderRequest, orderCurrentActivity, "4")
