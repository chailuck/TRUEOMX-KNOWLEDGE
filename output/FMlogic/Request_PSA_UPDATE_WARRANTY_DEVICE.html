Request_PSA_UPDATE_WARRANTY_DEVICE

PSA Warranty Device Update — iterates Material per Subscriber across all POU/ChildOU
Backend: PSA Priority: 5 Pattern: FIRE-AND-FORGET per Material RefId: SubRefId:MatCode composite key 2 XSLT variants (POU/ChildOU)
§1 — Overview & Purpose
PSA_UPDATE_WARRANTY_DEVICE registers warranty information for each device material (IMEI/MatCode) in the PSA system. Unlike most FMs, it iterates Subscriber MaterialInfo.Material — not Account or Subscriber — making one PSA call per material item.
Fire-and-forget per material: Event.Ext.sendEventImmediate + manual RequestCount++ inside the material loop. Fan-in: count("000") == RequestCount.
RefId = composite key: pSubRefId + ":" + material.MatCode (ParentOU) or cSubRefId + ":" + material.MatCode (ChildOU). This composite key is used for CompletionStatus==2 resubmit skip and is the ReferenceId in the event header.
Two XSLT variants: ParentOU subscriber uses $pMatRefId/$psub; ChildOU subscriber uses $cMatRefId/$csub. Payload structure is identical between variants; only parameter bindings differ.
SALE_CHANNEL dispatch: "SHOP" → "1"; "DEALER" → "2"; other → no SALE-CHANNEL element emitted.
