Request_ASRM_UPDATE_ATTRIBUTE_SIM

TIBCO BusinessEvents FM Logic — SIM Attribute Update (EXPIRE_SELF / MATCHING_ID / SIM_NOTE)
Author: SathidP-PC Priority: 5 Forward Chain: true Target: ASRM (Amdocs RM) Pattern: IntraActivitySequencing (POU+COU Subscribers) Lines: 134
§1 — Overview & Purpose

This rule updates a SIM card attribute in ASRM (Amdocs Resource Manager) for every subscriber in the order — across both POU subscribers and COU subscribers. The attribute to update is determined by the PROJ parameter from the ProcessConfig activity; the value for the default case is calculated from the EXPIRE_SELF parameter.

Three attribute modes driven by PROJ parameter:
  • PROJ=BULKESIM → sets MATCHING_ID = subscriber's PMATCHID resource
  • PROJ=RMRF → sets SIM_NOTE = subscriber's MSISDN
  • Otherwise (default) → sets EXPIRE_SELF = date calculated from EXPIRE_SELF parameter

§5 — Execution Flow Diagram
  1. Detect resubmit: isActResub = (RequestCount > 0 && IsOrderResubmitted)
  2. Load activity config: read EXPIRE_SELF parameter → compute expire_self date; read PROJ parameter → paramValue
  3. expire_self calculation:
    • If EXPIRE_SELF param is null → expire_self = " "
    • If EXPIRE_SELF == "-1" → expire_self = " "
    • Otherwise → DateTime.format(DateTime.addDay(Date.today(), number(EXPIRE_SELF)), "dd/MM/yyyy")
  4. Loop A — POU Subscribers: for each ParentOU[i].Subscriber[j]:
    • Check reqSuccess (CompletionStatus==2 response with matching RefId) → skip if done
    • Evaluate PreExecCheck via GetXMLForSubscriber(orderRequest, refId)
    • If chkRes=="true": dispatch ASRM_UPDATE_ATTRIBUTE_SIM event; send audit log; RequestCount++
  5. Loop B — COU Subscribers: for each ParentOU[i].ChildOU[k].Subscriber[j]:
    • Same reqSuccess + PreExecCheck pattern
    • PreExecCheck helper: GetXMLForSubscriberInChildOU(orderRequest, refId, ParentOU[i].RefId)
    • Dispatch event with COU-specific SIM resolution (always uses SIM resource, not MISIM)
  6. Post-loop: if dispatched → GetActivityStatusString("1", false) + SendDataToDB(); else → SkipActivity(..., "4")
  7. catch: HandleActivityException(orderRequest, orderCurrentActivity, ae, "")
§6 — Parameter-Driven Logic

§6.1 EXPIRE_SELF Parameter

Read via GetActivityParamValueFromKey(orderCurrentActivity, "EXPIRE_SELF").

attrValueexpire_self Result
null" " (space — blank)
"-1"" " (space — blank)
Any numeric string (e.g., "30")DateTime.format(DateTime.addDay(Date.today(), 30), "dd/MM/yyyy") → e.g., "26/08/2026"
Used as the EXPIRE_SELF attribute value when PROJ is neither BULKESIM nor RMRF. A value of " " effectively clears the field in ASRM.

§6.2 PROJ Parameter — Attribute Mode Selection

§6.3 SIM Resource Resolution (POU Subscriber)

Conditionns:Value Source
paramValue contains "RIO" AND ResourceInfo[ResourceName="MISIM"] exists with count>0ResourceInfo[ResourceName="MISIM"]/ValuesArray
paramValue contains "RIO" AND no MISIM resourceResourceInfo[ResourceName="SIM"]/ValuesArray
Otherwise (no RIO)ResourceInfo[ResourceName="SIM"]/ValuesArray

§6.4 SIM Resource Resolution (COU Subscriber)

Always uses ResourceInfo[ResourceName="SIM"]/ValuesArray. No MISIM/RIO logic for COU subscribers.

MISIM/RIO asymmetry: POU subscribers may use the MISIM resource (for RIO project orders); COU subscribers always use the standard SIM resource. This is a behavioural difference between the two XSLT variants.
§7 — Conditional UserName/Password

Both POU and COU variants wrap the UserName and PassWord fields in an additional global variable gate:

<xsl:if test="$globalVariables/OMX_OM/Rules/OMConsumers/OMXFM/Request/IsEnableUserPass='true'">
    <!-- UserName and PassWord are only included if IsEnableUserPass='true' -->
</xsl:if>

This differs from most other FM rules that unconditionally include UserName/PassWord when the order data has them. The ASRM endpoint may not require credentials in all environments; this flag enables runtime toggling.

§17 — Migration Notes & Recommendations

Functional Requirements

  • R1 — Fan-out to all POU and COU subscribers in the order
  • R2 — Attribute mode selection from PROJ parameter: BULKESIM → MATCHING_ID; RMRF → SIM_NOTE; default → EXPIRE_SELF
  • R3 — EXPIRE_SELF date: today + n days (from parameter); "-1" or null → blank
  • R4 — POU subscribers with RIO project use MISIM resource if available; fall back to SIM
  • R5 — COU subscribers always use SIM resource
  • R6 — UserName/PassWord inclusion gated on IsEnableUserPass='true' global variable
  • R7 — Resubmit safety: skip if CompletionStatus==2 response already exists for subscriber RefId

Design Risks

RiskSeverityMitigation
PROJ parameter containing "RIO" triggers MISIM logic — substring check, not exact matchMEDIUMTest with paramValues like "RIOPILOT", "XRIO" — all trigger MISIM path

BULKESIM: AttrValue PMATCHID may be absent — no default, resulting in empty AttrValueLOWConfirm ASRM accepts missing AttrValue or add explicit guard

/**
 * @description
 * @author SathidP-PC
 */
rule Rules.OMConsumers.OMXFM.Request.Request_ASRM_UPDATE_ATTRIBUTE_SIM {
    attribute { priority = 5; forwardChain = true; }
    declare {
        Concepts.OrderRequest.OrderRequest orderRequest;
        Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
    }
    when {
        orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
        orderCurrentActivity.ActivityID == "ASRM_UPDATE_ATTRIBUTE_SIM";
        orderRequest.ProcessFlow.NextActivityID == "ASRM_UPDATE_ATTRIBUTE_SIM";
        orderCurrentActivity.Status == "WAITING";
    }
    then {
        boolean isActResub=(orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
        try {
            Concepts.OM.ProcessConfig.Activity nextAct = Instance.getByExtIdByUri(
                orderRequest.ProcessFlow.NextActivityName, "/Concepts/OM/ProcessConfig/Activity");

            // Compute expiry date from EXPIRE_SELF parameter
            String attrValue = RuleFunctions.Helpers.GetActivityParamValueFromKey(orderCurrentActivity, "EXPIRE_SELF");
            String expire_self = " ";
            if (attrValue != null) {
                if(String.equals(attrValue, "-1")) {
                    expire_self = " ";
                } else {
                    expire_self = DateTime.format(DateTime.addDay(Date.today(),
                        XPath.evalAsInt(/* "number($attrValue)" */)), "dd/MM/yyyy");
                }
            }
            String paramValue = RuleFunctions.Helpers.GetActivityParamValueFromKey(orderCurrentActivity, "PROJ");

            boolean isSkipped = true;

            // Loop A: POU Subscribers
            for (int i=0; i < orderRequest.OrderData.Customer.ParentOU@length; i++) {
                for(int j=0; j < orderRequest.OrderData.Customer.ParentOU[i].Subscriber@length; j++) {
                    // reqSuccess check, PreExecCheck, then dispatch:
                    // Event.createEvent("xslt://{{/Events/.../ASRM_UPDATE_ATTRIBUTE_SIM}}...")
                    //   → See §9 for XSLT (MISIM/RIO logic, PROJ-driven attribute)
                    // Audit: "Request Sent for RefId " + refId
                }

                // Loop B: COU Subscribers
                for(int k=0; k < orderRequest.OrderData.Customer.ParentOU[i].ChildOU@length; k++) {
                    for(int j=0; j < orderRequest.OrderData.Customer.ParentOU[i].ChildOU[k].Subscriber@length; j++) {
                        // COU variant: always SIM resource; same PROJ-driven attribute logic
                    }
                }
            }

            if(!isSkipped) {
                orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
                RuleFunctions.Helpers.SendDataToDB(orderRequest);
            } else {
                RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
            }
        } catch (Exception ae) {
            RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
        }
    }
}
§19 — Response Message Rule

§19.1 Overview

Response_ASRM_UPDATE_ATTRIBUTE_SIM.rulefunction receives the ASRM response, creates a ASRM_InvokeUnifiedResourceRes concept, appends it to currActivity.Response[], and uses the ResponseCode suffix "000" fan-in check to signal completion.

Event.sendEvent() vs Event.Ext.sendEventImmediate(): The response audit log uses Event.sendEvent() (not the Immediate variant). This means the audit event may be processed asynchronously, potentially after the response function returns.
extId generated outside XSLT: Unlike most response handlers where extId is generated inside the XSLT via OMXUtils:generateTrackingID(), this handler calls OMXUtils.generateTrackingID() directly in BE code and passes the result as a parameter to the XSLT.
