Request_CRM_UPDATE_ASSET

CRM Asset Registration — registers subscriber as CRM asset with KYC/identity data; IntraActivitySequencing fan-in; OrderType 1/34/52/66 dispatch
Backend: CRM Priority: 5 Pattern: IntraActivitySequencing Author: DESKTOP-HINKNF3 POU Subscribers only
§1 — Overview & Purpose
CRM_UPDATE_ASSET registers each subscriber as an asset in the CRM system with KYC/identity verification data. It sends ns:updateAssetRequest and uses IntraActivitySequencing — events are asserted (Event.assertEvent) and dispatched via ActionRequestEvent/SendFirstRequestEvent, not fire-and-forget.
IntraActivitySequencing pattern: Event.assertEvent(reqEvent) + ActionRequestEvent(reqEvent, currActivity) + SendFirstRequestEvent(currActivity). Fan-in: ActionResponseEvent(currActivity) returns true/false.
OrderType=1 TrueFamily skip: If OrderType="1" AND campaignCode=="TrueFamily" AND subscriber has no FE ResourceInfo → continue (skip this subscriber). No exception — silently skips.
CustomerAccount dispatch by OrderType: OT=1/66 → customer-level name/address; OT=34/52 → subscriber-level name/address. Asset section always uses subscriber-level MSISDN.
OT=34 dummyMsisdn: OT=34 uses dummyMsisdn + dummyMsisdnFlag="true" instead of serviceId. Supports pre-provisioning with dummy MSISDN.
ParentCustomer section: Emitted only if Customer.OtherAddress exists — holds parent/guardian data for minor subscriber cases.
