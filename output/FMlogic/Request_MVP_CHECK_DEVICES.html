Request_MVP_CHECK_DEVICES

Checks whether each subscriber's device supports 5G via MVP (Mobile Value Platform) — fan-out per subscriber, populates 5G_DEVICE flag in working memory
Priority: 5 ForwardChain: true Backend: MVP Pattern: Fan-out per subscriber Generated: 2026-08-13
§1 — Overview & Purpose

This rule fires when the order orchestrator reaches the MVP_CHECK_DEVICES activity. It iterates over every subscriber in the order (ParentOU and ChildOU hierarchy) and sends a MvpCheckDevicesRequest to the MVP (Mobile Value Platform) system for each one, asking whether the subscriber's device is 5G-capable.

The response handler checks the MvpCheckDevicesResponse/device field — if it equals "5G", a SubscriberExtendedInfo concept with Name="5G_DEVICE", Value="Y" is written to the subscriber in working memory; otherwise Value="N". Downstream rules use this flag to gate 5G-specific offer provisioning.

Business Purpose: Before removing or adding offers, determine if the subscriber's handset is 5G-capable. Enables conditional offer routing — e.g., skip 5G SA offer provisioning for non-5G devices.

§17 — Migration Notes & Recommendations

Functional Requirements

IDRequirement
R1Query MVP to determine if each subscriber's device supports 5G
R2Fan-out to ALL subscribers (POU + COU); identical request for both
R3Store result as SubscriberExtendedInfo[5G_DEVICE=Y/N] per subscriber
R4Skip subscribers that already have a successful response
R5Fan-in: complete when RequestCount == success-response count (ResponseCode suffix "000")
R6channel="omx" and check_current_soc="no" are hardcoded — cannot be configured per-order

Design Risks

RiskSeverityMitigation
Hardcoded channel="omx"MEDIUMIf MVP requires different channel identifiers per environment or caller, this needs parameterisation.
Hardcoded check_current_soc="no"LOWIntentional design — device check only, not SOC check. Document assumption explicitly in migration.
Response audit always logs (no AllowWriteLog gate)LOWResponse handler logs unconditionally. Minor performance impact for high-volume order types.
5G_DEVICE flag matchingMEDIUMValue comparison is case-sensitive (= "5G"). Any MVP response returning "5g" or "5G SA" would set flag to "N".
§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_MVP_CHECK_DEVICES {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "MVP_CHECK_DEVICES";
    orderRequest.ProcessFlow.NextActivityID == "MVP_CHECK_DEVICES";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
    try {
      Concepts.OM.ProcessConfig.Activity nextAct = Instance.getByExtIdByUri(...);
      int iPOULen = orderRequest.OrderData.Customer.ParentOU@length;
      String pouRefId = "";
      boolean isSkipped = true;
      for (int i=0; i<iPOULen; i++) {
        pouRefId = orderRequest.OrderData.Customer.ParentOU[i].RefId;
        for (int j=0; j<iSubscriberLen; j++) {
          Concepts.OrderRequest.OrderElements.Subscriber subscriber = orderRequest.OrderData.Customer.ParentOU[i].Subscriber[j];
          // [success-check, PreExecCheck omitted for brevity]
          Events.OMConsumers.OMXFM.Request.MVP_CHECK_DEVICES reqEvent = Event.createEvent(
            /* xslt://MVP_CHECK_DEVICES — see §9.8 for full XSLT
               params: orderRequest, refId, subscriber
               Outputs: extId(OMXUtils:generateTrackingID), JMSPriority, JMSCorrelationID,
                        OrderID, RefID, OrderType,
                        payload/ns:MvpCheckDevicesRequest{ns:transaction_id, ns:channel="omx",
                        ns:msisdn, ns:check_current_soc="no"} */);
          Event.Ext.sendEventImmediate(reqEvent);
          if (RuleFunctions.Helpers.AllowWriteLog(orderRequest.OrderData.OrderType)) {
            Event.Ext.sendEventImmediate(Event.createEvent(/* Logger XSLT — OPERATION_NAME=MVP_CHECK_DEVICES */));
          }
          if(!isActResub) orderCurrentActivity.RequestCount++;
          isSkipped = false;
        }
        // COU loop (p, q) — same XSLT, same subscriber param pattern
      }
      if(!isSkipped) {
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch (Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

Receives MvpCheckDevicesResponse from MVP. Appends ResponseBase; iterates all subscribers to find the matching RefID; creates a SubscriberExtendedInfo with Name="5G_DEVICE" and Value="Y"/"N" based on the device field; logs audit; returns fan-in completion status.
