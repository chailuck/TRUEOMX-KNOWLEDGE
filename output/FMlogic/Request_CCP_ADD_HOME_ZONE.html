§1 — Overview & Purpose

Adds a Home Zone assignment to a subscriber in the CCP (ZTE/zSmart BSS) system. Sends a modSubsHomeZone request via the CCP_MOD_SUBS_HOME_ZONE JMS event, using the igoHomeZoneCode extended info field from the order as the zone code. Action code "1" = Add.


Used in PREPAID_REGISTRATION (step 7). This activity sets the subscriber's geographic home zone in CCP, which is used for location-based prepaid services.

Key trait — IntraActivitySequencing: Unlike most OMXFM rules that send all subscriber requests in parallel, this FM uses IntraActivitySequencing to send requests sequentially — one at a time. On resubmit, pending requests are purged before restarting.

§5 — Execution Flow Diagram
  1. Resubmit check — isActResub = (RequestCount > 0 && IsOrderResubmitted)
  2. If resubmit — call IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity) to clear queued requests
  3. Loop ParentOU — for each ParentOU[p], loop each Subscriber[ps]
  4. Skip-check — scan Response[] for RefId==pSubRefId with CompletionStatus==2; skip if found
  5. PreExecCheck — evaluate XPath if present; skip subscriber if "false"
  6. Build request event — XSLT → CCP_MOD_SUBS_HOME_ZONE event; Action="1", HomeZoneCode from igoHomeZoneCode
  7. Assert event — Event.assertEvent(reqEvent) (adds to BE working memory)
  8. Queue for sequencing — IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity)
  9. Audit log — gated by AllowWriteLog(OrderType)
  10. Loop ChildOU — same logic for ChildOU subscribers
  11. Send first request — IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity) (dispatches first in queue)
  12. Status update — Status = "1" IN_PROGRESS + SendDataToDB; or SkipActivity("4")
  13. Exception handler — HandleActivityException
§6 — Rule Action (THEN) — Logic Detail

IntraActivitySequencing pattern: All subscriber request events are assembled and queued via ActionRequestEvent, then only the first one is sent via SendFirstRequestEvent. Each subsequent request is dispatched only after the previous response is received and processed by ActionResponseEvent in the response RF. This enforces strict sequential processing of multiple subscribers.

Resubmit handling: Calls PurgePendingRequestsBeforeResubmit before re-queuing — ensures stale queued events from a prior attempt are cleared.

Audit log: Correctly gated by AllowWriteLog(orderRequest.OrderData.OrderType) — only writes for allowed order types.

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_CCP_ADD_HOME_ZONE {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "CCP_ADD_HOME_ZONE";
    orderRequest.ProcessFlow.NextActivityID == "CCP_ADD_HOME_ZONE";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    try {
      if(isActResub) {
        RuleFunctions.Helpers.IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity);
      }
      // ParentOU + ChildOU loop: build CCP_MOD_SUBS_HOME_ZONE event (§9.8)
      // Event.assertEvent(reqEvent) → IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity)
      // AllowWriteLog gate → audit Logger event
      if (!isSkipped) {
        RuleFunctions.Helpers.IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch (Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

§19.1 Overview

Standard ResponseBase handler using IntraActivitySequencing for fan-in. After processing each subscriber response, calls ActionResponseEvent which: (1) marks the response as processed, (2) dispatches the next queued request event if any remain, and (3) returns true when all queued requests have completed successfully.
