§1 — Overview & Purpose
SBM_ADD_3GPREPAID provisions a 3G prepaid package (SOC/offer) through the SBM (Service Billing Manager) system. For each SubscriberOffer on both ParentOU and ChildOU subscribers, it sends a doServiceArrayRequest that bundles two sub-calls: an optional CheckPackAllowRequest (to validate whether the package is allowed) followed by a mandatory DoServiceRequest (functionId=100200004). Credentials (app_user/app_password) are selected between BATCH and ONLINE modes based on the order's IntegrationMethod.

§17 — Migration Notes & Recommendations

Known Issues & Dead Code

Bug — Double colon in ParentOU RefID (line 78):
offerRefId = pOuRefId + ":" + ":" + refId + ":" + offer.OfferName
Produces PAGR1::SUB1:PKG instead of likely-intended PAGR1::SUB1:PKG or 4-part PAGR1::SUB1:PKG. ChildOU variant (line 137) uses the correct 4-part format. This mismatch means ParentOU and ChildOU RefIDs have different structures — may cause issues with response correlation matching.
Bug — QUOTA_BUNDLE XPath typo in ChildOU variant (line 164):
ExtendedInfo[Name="QUOTA_BUNDLE]"/Value — closing bracket ] is inside the string literal, making the predicate [Name="QUOTA_BUNDLE]"] which will never match. ParentOU variant (line 106) is correct. The bundle_level parameter will never be sent for ChildOU subscriber offers.
Dead variable — billCycleNo (lines 102, 161):
billCycleNo = ConvertBillCycleDate(BillCycleNo) is computed but not passed as an XSLT parameter and not used anywhere in the payload. ConvertBillCycleDate is called needlessly for every offer.

§19 — Response Message Rule

§19.1 Overview

Response_SBM_ADD_3GPREPAID.rulefunction handles the async reply from SBM FM. It creates an SBM_DoServiceRes concept (including DoServiceReturn detail elements), then — as part of OMX-3001 (TrueID+ markused flow) — writes back the SBM_TRX_ID onto every FE-origin offer. Fan-in is driven by IntraActivitySequencing.ActionResponseEvent (not a manual count).

§19.4 SBM_TRX_ID Writeback (OMX-3001)

For every subscriber offer where FE_OR_CCBS="FE" (covers both ParentOU and ChildOU subscribers), a new SubscriberOffersExtendedInfo is appended:

ExtendedInfo NameValue sourceCondition
SBM_TRX_ID$eventResponse/payload/ns1:doServiceArrayResponse/ns1:DoServiceReturn/ns:transaction_idFE_OR_CCBS="FE" on offer
Transaction ID is written from the first DoServiceReturn element — the XPath does not select by index, so if multiple DoServiceReturn elements exist, the first one's transaction_id is used for all FE offers.

§19.5 Response Completion Logic

if (RuleFunctions.Helpers.IntraActivitySequencing.ActionResponseEvent(currActivity)) {
    return "true";   // All parallel SBM requests matched — activity complete
} else {
    return "false";  // Still waiting for more responses
}
Uses IntraActivitySequencing.ActionResponseEvent for fan-in — NOT the manual count(Response[000]) XPath pattern. This is consistent with the request side's ActionRequestEvent/SendFirstRequestEvent sequencing.
