OMX Add Next Price Plan — Schedule Future SOC Change Across All Offer Contexts

Priority: 5forwardChain: trueAuthor: warawich-nbPattern: IntraActivitySequencing (per-offer)Event: OMX_ADD_FUTUREfutureType: NXTPPGenerated: 2026-07-27
§1 — Overview & Purpose

This rule schedules a "Next Price Plan" (NXTPP) future SOC change for each offer in the order that has a SocProperties-encoded next price plan. It iterates across four contexts — POU Agreement, POU Subscriber, COU Agreement, and COU Subscriber — and sends one OMX_ADD_FUTURE JMS event per qualifying offer. The effective date is computed from the logical date, bill cycle, and a duration extracted from SocProperties.

Event type note: The JMS request event is Events.OMConsumers.OMXFM.Request.OMX_ADD_FUTURE, not OMX_ADD_NXT_PP. The same event type is shared with OMX_ADD_NEXT_OFFER (distinguished by futureType field: "NXTPP" here vs "NXTOFFER" there).
LogicalDate concept: Before iterating, reads /Concepts/OM/LogicalDate to support simulated date testing. If LogicalDate.LogicalDate is non-blank, uses that date; otherwise falls back to DateTime.now().
FE_OR_CCBS filter: Subscriber-level offers (POU Sub, COU Sub) are only processed when FE_OR_CCBS = "FE". Agreement-level offers (POU Agreement, COU Agreement) are processed regardless of FE_OR_CCBS value.

§5 — Execution Flow
1
Init: isActResub; read LogicalDate concept; initialise requestedDate, requestedBy="OMX", requestedByUser=Channel, futureType="NXTPP", isSkipped=true
2
For each POU Agreement offer: read FE_OR_CCBS from ExtendedInfo (no FE filter); evaluate PreExecCheck via GetXMLForAgreementOffer; check reqSuccess by OUId; call GetNextPricePlan(socProps) → skip if blank; GetSocCodeFromName → skip if blank; compute effectiveDate; build userText; send OMX_ADD_FUTURE (nodeLevel=3, nodeId=pOuId); RequestCount++
3
For each POU Subscriber offer: same but FE_OR_CCBS="FE" filter enforced; PreExecCheck via GetXMLForSubscriberOffer; reqSuccess checked by SubscriberId; nodeLevel=5, nodeId=subId; FLG_SMS read for FLG_SMS_WELCOME_SUB extendedInfo
4
For each COU Agreement offer: if nxtPPName non-empty → same pattern; PreExecCheck via GetXMLForAgreementOfferInChildOU; nodeLevel=3, nodeId=cOu.OUId; adds OU_ID and AGR_ID extendedInfo
5
For each COU Subscriber offer: FE_OR_CCBS="FE" filter; PreExecCheck via GetXMLForSubscriberOfferInChildOU; nodeLevel=5, nodeId=subId; adds OU_ID extendedInfo (always, not conditional)
6
If any event sent → status IN_PROGRESS + SendDataToDB; else → SkipActivity("4")
7
Exception → HandleActivityException

§10.4 — LogicalDate Override

Reads /Concepts/OM/LogicalDate concept:
  if (LogicalDate.LogicalDate is non-blank)
      logicalDate = DateTime.parseString(LogicalDate.LogicalDate, "yyyy-MM-dd'T'HH:mm:ssXXX")
  else
      logicalDate = DateTime.now()

Purpose: allows test environments to simulate future dates without changing system clock.

§17 — Migration Notes & Recommendations

Functional Requirements

  • R1 — Four iteration contexts (POU-Agreement, POU-Subscriber, COU-Agreement, COU-Subscriber) each producing one OMX_ADD_FUTURE event per qualifying offer. All four must be preserved.
  • R2 — FE_OR_CCBS filter is applied only at subscriber level (FE only); Agreement-level offers are not filtered and must process regardless of FE_OR_CCBS value.
  • R3 — Skip logic (continue) is triggered when either GetNextPricePlan returns blank OR GetSocCodeFromName returns blank. Both guards must be honoured.
  • R4 — LogicalDate concept support: if present and non-blank, use it as the base date for effective date computation. Required for test environments.
  • R5 — Fan-in via IsAllResponseSuccess: returns "true" when all responses have CompletionStatus=2 (not "000" suffix like most FMs). Verify the helper's exact condition in migration.
  • R6 — ReferenceId in the response concept is sourced from payload/AddFutureOrderResponse/nodeId (payload-level), not from the event header RefID — unique among this process's response concepts.
  • R7 — OMX-2896: FLG_SMS_WELCOME_SUB extendedInfo must be included in subscriber-level offers when FLG_SMS ExtendedInfo is present (corporate customer SMS welcome flag).
  • R8 — futureType="NXTPP" and ns2:type=80 and ns2:subType="NXTPP" are all static and must not be configurable at runtime (they distinguish this call from OMX_ADD_NEXT_OFFER which uses "NXTOFFER").
