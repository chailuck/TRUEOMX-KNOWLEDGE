Request_BDH_GET_DEALER_POOLS_BY_DEALER_CODE

Backend: BDH Pattern: Single Request Priority: 5 ForwardChain: true Generated: 2026-09-14
§1 — Overview & Purpose

Retrieves the dealer pool list for the order's DealerCode from the BDH (Billing Dealer Hub) backend. The result is stored as a CCBS_GetDealerPoolsForDealer concept and also written as a CustomerExtendedInfo entry named DEALER_POOLS for downstream use by other activities.

This is a simple single-request FM — one outbound event is dispatched for the entire order (not per-subscriber). Execution is gated by the activity's PreExecCheck (DealerCode must be non-empty).

[LOW] Missing isActResub / PurgePendingRequestsBeforeResubmit: Unlike most OMXFM request rules, this rule does not check isActResub or call PurgePendingRequestsBeforeResubmit before re-dispatching. On order resubmit, duplicate requests may be sent.

§5 — Execution Flow Diagram
  1. Compute isActResub = RequestCount > 0 && IsOrderResubmitted (not acted upon — no purge call)
  2. Fetch the activity concept via Instance.getByExtIdByUri to read PreExecCheck
  3. Evaluate PreExecCheck XPath on serialized orderRequest — default result: "true"
  4. If PreExecCheck passes: create and send BDH_GET_DEALER_POOLS_BY_DEALER_CODE request event via XSLT
  5. Set isSkipped = false; increment RequestCount (if not resubmit)
  6. If AllowWriteLog: emit audit logger event
  7. If !isSkipped: set Status="1", call SendDataToDB; else call SkipActivity("4")
  8. On exception: call HandleActivityException
§6 — Rule Action (THEN) — Step-by-Step Logic

§6.1 PreExecCheck Evaluation

The PreExecCheck expression for step 1 in ProcessConfig is:

string-length(/ns0:OrderRequest/OrderData/DealerCode/text())!=0

This gate ensures the FM only fires when a non-empty DealerCode is present in the order.

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_BDH_GET_DEALER_POOLS_BY_DEALER_CODE {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "BDH_GET_DEALER_POOLS_BY_DEALER_CODE";
    orderRequest.ProcessFlow.NextActivityID == "BDH_GET_DEALER_POOLS_BY_DEALER_CODE";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    // NOTE: isActResub computed but PurgePendingRequestsBeforeResubmit NOT called
    try {
      Activity nextAct = Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName, "...");
      String chkXPath = nextAct.PreExecCheck;
      String chkRes = "true";
      boolean isSkipped = true;

      if (String.length(orderCurrentActivity.PreExecCheck) > 0) {
        String sXML = Instance.serializeUsingDefaults(orderRequest);
        chkRes = XPath.execute("/(...", sXML, "ns0=...");
      }

      if (String.equals(chkRes, "true")) {
        Events...BDH_GET_DEALER_POOLS_BY_DEALER_CODE reqEvent = Event.createEvent("xslt://...");
        /* XSLT builds ns1:GetDealerPoolsByDealerCodeReq with ns1:dealerCodeList — see §9.8 */
        Event.Ext.sendEventImmediate(reqEvent);
        isSkipped = false;
        if (!isActResub) orderCurrentActivity.RequestCount++;
        if (RuleFunctions.Helpers.AllowWriteLog(...)) {
          Event.Ext.sendEventImmediate(Event.createEvent("xslt://Logger..."));
        }
      }

      if (!isSkipped) {
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch (Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

§19.1 Overview

Processes the BDH response: creates a CCBS_GetDealerPoolsForDealer concept, extracts pool codes as comma-separated string, upserts a CustomerExtendedInfo DEALER_POOLS entry on the order, logs the response, and signals fan-in completion using request-count matching.

§19.3 Response Concept Construction

Type: Concepts.FM.Response.CCBS_GetDealerPoolsForDealer (specific — not generic ResponseBase)

  • createObject
    • object extId=concat("GDPFD:", $orderRequest/OrderData/OMXTrackingId)Always

      • ResponseMessage←$eventResponse/ResponseMsgConditional
      • CompletionStatus←$eventResponse/CompletionStatusConditional
      • ReferenceId←$eventResponse/RefIDConditional
      • PoolName [0..*]←ns1:poolCode from results[code=200 and dealerCode=DealerCode]/poolList[for-each, code=200 filter]Conditional (repeated)

After creating the concept, poolNames is computed as:

concat(",", tib:concat-sequence-format($activityRes/PoolName, ","), ",")

Then a CustomerExtendedInfo concept keyed "CUSTEXT:" + OMXTrackingId + ":" + RefID + ":DEALER_POOLS" is looked up and created if absent.
