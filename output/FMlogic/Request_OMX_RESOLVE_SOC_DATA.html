Request_OMX_RESOLVE_SOC_DATA

Batch SOC data resolution — aggregate all unique offer names, fire single request, enrich orderRequest with package metadata
Target: OMX FM Service Pattern: Batch/Aggregate + Data Enrichment forwardChain: true Event: OMX_RESOLVE_SOC_DATA Author: RS33-BANDIT Generated: 2026-08-04
§1 Overview & Purpose

This FM resolves detailed SOC (Service Offer Code) package metadata for every unique offer name referenced in the order. It collects all unique SOC names across Agreement Offers, SubscriberOffers, and their RelatedOffersArrays for all POU and COU levels, deduplicates them via an ArrayList, and fires a single batch request event. The response handler then writes resolved metadata (ServiceType, RevenueType, OfferRate, DataInfo, IR flag) back into every matching offer entry in the orderRequest.

Architectural pattern: Unlike per-subscriber fan-out FMs, this FM uses a batch/aggregate pattern — one request covers all SOC names simultaneously. There is always exactly RequestCount = 1 (unless resubmit is skipped). The fan-in simply checks RequestCount == Response@length rather than counting "000" successes.

§19 Response Message Rule

§19.1 — Overview

The response handler for OMX_RESOLVE_SOC_DATA performs two distinct functions:

  1. Parse response — map the backend ResolveSocDataResponse into OMX_ResolveSocDataRes concept with a SocData[] array.
  2. Enrich orderRequest — for each resolved SocData record, walk all 4 offer sources and write ServiceType, RevenueType, OfferRate, DataInfo fields back to every matching offer by PackageCode. Also applies IR flag and OMX-2771 serviceType override.
This is the most complex response handler in this FM set — it does NOT simply store the response and signal fan-in. It performs an O(S × O) enrichment pass across the entire order structure.

§19.4 — SOC Data Enrichment Logic

StepLogic
1. FilterSkip SocData entries where PackageCat is blank/null
2. Compute serviceTypeRuleFunctions.Helpers.IndentifySocDataServiceType(packageCat, dataType)
3. OMX-2771 overrideIf serviceType == "88" AND SocData.TssDisplayType == "ROAM" → serviceType = "91" (IR Data Pack via iService)
4. Compute raterate = Number.doubleValue(SocData.Price) if not blank; else 0.0
5. Match offers4-pass loop: POU Agreement → POU Subscriber → COU Agreement → COU Subscriber; match by packageCode == offer.OfferName
6. Write metadataServiceType, RevenueType=packageType, OfferRate=rate; create or update DataInfo (Package, ChargeType, PackType)
7. IR flagIf offer.ServiceType == "87" (SubscriberOffers only): append SubscriberOffersExtendedInfo(Name="IR_DATA", Value="Y")
8. RelatedOffersLoop RelatedOffersArray; match by packageCode; write only ServiceType (not full metadata)

// Append response concept to activity response array: currActivity.Response[currActivity.Response@length] = activityRes; // Fan-in check: if (currActivity.RequestCount == currActivity.Response@length) { return "true"; // all responses received } else { return "false"; // still waiting }
