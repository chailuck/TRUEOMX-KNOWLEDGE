Request_CJ_UPDATE_CALL_VERIFICATION

Update call-verification result in the Customer Journey service per subscriber
Backend: CJ Pattern: POU Loop · IntraSeq Fan-in Author: TIT_F25-Maline5 Priority: 5 Generated: 2026-09-18
§1 — Overview & Purpose

This rule sends the call-verification update to the CJ service for each POU subscriber. It maps order ExtendedInfo fields (CALL_VER_STATUS, CALL_VER_REASON, INBOUND_CNT, OUTBOUND_CNT) to the CJ UpdateCallVerification payload and derives the logical fcrStatus and callVerResult values from business rules. The rule is guarded by a PreExecCheck on IS_UPDATE_CALLVER=Y in OrderData.

⚠ Dead code: A full CCBS_CANCEL_SUBS event creation block exists in the source but is entirely commented out. It has no effect.

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_CJ_UPDATE_CALL_VERIFICATION {
  // @author TIT_F25-Maline5
  attribute { priority = 5; forwardChain = true; }
  declare { Concepts.OrderRequest.OrderRequest orderRequest;
            Concepts.OM.ProcessConfig.Activity orderCurrentActivity; }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "CJ_UPDATE_CALL_VERIFICATION";
    orderRequest.ProcessFlow.NextActivityID == "CJ_UPDATE_CALL_VERIFICATION";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    try {
      // POU subscriber loop
      // activityDate = EffectiveDate if non-empty else ""
      // DEAD CODE: CCBS_CANCEL_SUBS event block is commented out — no effect
      // Build UpdateCallVerification event — see §9 for field derivations
      Events.OMConsumers.OMXFM.Request.CJ_UPDATE_CALL_VERIFICATION reqEvent =
        Event.createEvent("xslt://{{/Events/.../CJ_UPDATE_CALL_VERIFICATION}} <!-- §9: fcrStatus/callVerResult derived from CALL_VER_STATUS -->");
      Event.assertEvent(reqEvent);
      RuleFunctions.Helpers.IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity);
      // Logger audit (sendEventImmediate) — see §11
      // Completion: SendFirstRequestEvent / SkipActivity("4")
    } catch(Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

Response_CJ_UPDATE_CALL_VERIFICATION appends the ResponseBase concept and advances the IntraSeq fan-in. The commented-out successResponseCount block (count of "000" responses) was replaced with ActionResponseEvent pattern — consistent with CJ_QUERY_STATE and CCBS_UPDATE_SUBSCRIBER.
