§1 — Overview & Purpose

Sends a RemoveComponentOTT request to the TVS (True Vision) system when a subscriber with a TVS account is being cancelled. The request cancels the OTT component, processes equipment return, and unregisters the mobile-TVS relationship.

Used in CANCEL_SUBSCRIBER process — Step 55 — gated on presence of TVS_CUSTOMER_NUMBER in Customer ExtendedInfo. Iterates both ParentOU and ChildOU subscribers.

§5 — Execution Flow
  1. Check resubmit flag
  2. Iterate ParentOU subscribers — check response already received for each RefId
  3. If not yet responded: evaluate PreExecCheck per-subscriber
  4. If check passes: build and send TVS_REMOVE_COMPO_OTT event, increment RequestCount
  5. Send audit log
  6. Repeat for ChildOU subscribers (same pattern)
  7. After all loops: if any sent → Status="1", SendDataToDB; else SkipActivity("4")

§17 — Migration Notes

R1: TVS integration requires TVS_CUSTOMER_NUMBER in Customer ExtendedInfo — must be populated upstream before this step.

R2: TVS_RETURN_EQUIPT uses colon-delimited triplet format (type:serial:returnFlag) — ensure parsing logic is replicated in modern implementation.

R3: AUDIT_TRACE says "TDG_UPDATE_SERIAL" — appears to be a copy-paste error in legacy code; modernization should correct the label.

Risk: MEDIUM — Per-subscriber loop (ParentOU + ChildOU) means fan-in count must account for all matching subscribers.
