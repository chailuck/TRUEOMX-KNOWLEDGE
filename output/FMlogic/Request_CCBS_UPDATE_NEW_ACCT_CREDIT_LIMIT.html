CCBS Credit Limit Update — fire-and-forget with isUpdateCredit gate, ODS/personal/7-11 limit dispatch
Backend: CCBS Author: awalia-t420 Priority: 5 Pattern: FIRE-AND-FORGET (no IntraActivitySequencing) Fan-in: IsAllResponseSuccess
§1 — Overview & Purpose
CRITICAL — Same fire-and-forget pattern as FM21: Uses Event.Ext.sendEventImmediate(reqEvent) directly, manual orderCurrentActivity.RequestCount++, and IsAllResponseSuccess(currActivity) for fan-in. No IntraActivitySequencing involvement.
CCBS_UPDATE_NEW_ACCT_CREDIT_LIMIT updates the personal credit limit on new CCBS accounts. A key gate (isUpdateCredit) means some orders send NO event at all — if no qualifying credit limit source is found, the FM completes as a no-op.
isUpdateCredit gate (3 conditions — any is sufficient): (1) personalCreditLimit > 0; (2) ODS qualifies (ODSCreditLimit present); (3) Channel = "7-11". If none true, the account is skipped.
Credit limit priority: INDY (Type=73) + ODS qualifies → ODSCreditLimit; PersonalCreditLimit > 0 → use it; Channel="7-11" → hardcoded 215. OrderType=8 carry: postpaid→postpaid → carry source credit limit.
ActivityReason precedes credit logic: Computed BEFORE the credit class resolution: Type=73 → "CREQ"; AccountSubType=TOP/PREMIUM AND Channel ends in "U" → "SUCL"; else → "G142".
