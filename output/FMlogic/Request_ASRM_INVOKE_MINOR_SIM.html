Request_ASRM_INVOKE_MINOR_SIM

ASRM Unified Resource Activity — Minor/Secondary SIM Operations (Multi-SIM Cancellation, RIO Old-EID, SubscriberOffer-based)
Priority: 5 forwardChain: true Backend: ASRM Channel: OMXFMConnectionRequest Author: SathidP-PC Generated: 2026-07-23
§1 — Overview & Purpose

This rule fires when the order orchestration engine reaches an activity with ActivityID = ASRM_INVOKE_MINOR_SIM and status WAITING. Unlike ASRM_INVOKE_SIM (which targets the primary SIM for each subscriber), this rule handles secondary and additional SIM card operations via three mutually exclusive dispatch paths, chosen per-subscriber based on subscriber data attributes.

Three subscriber dispatch paths — evaluated in this priority order:
  1. Path A — Multi-SIM (MSIM_TO_CANCEL): If ExtendedInfo[Name="MSIM_TO_CANCEL"] exists → loop over pipe-delimited SIM ICC IDs, send one request per SIM.
  2. Path B — RIO / Old EID: Else if ResourceInfo[ResourceName="OLD_EID"] exists → single request sourced from ResourceInfo["OLD_SIM"].
  3. Path C — SubscriberOffers: Else → iterate SubscriberOffers[], dispatch one request per offer that has ParameterInfo["Related SIM"].
⚠ MSRES special skip logic: For any subscriber with SubscriberActivityInfo/ActivityReason='MSRES' (Mobile SIM Reservation), if the ACTIVITY is RESERVE, the subscriber is skipped automatically (reqSuccess=true). This prevents re-reserving an already-reserved SIM.
⚠ Per-SIM paired MSISDN key: The resource Type is determined by ResourceInfo[ResourceName=concat("SIM_PAIR_MSISDN_", $simValue)] — a dynamic key per SIM value. This differs from ASRM_INVOKE_SIM which uses the fixed key SIM_PAIR_MSISDN.

§5 — Execution Flow Diagram
1
Parameter Parsing — iterate Parameter[] with tib:tokenize(param,"=") → extract ACTIVITY value (RESERVE / PREACTIVATE / ACTIVATE)
2
ParentOU Subscriber Loop — for each ParentOU[i] → Subscriber[j]:
  • If already has SUCCESS response → skip
  • If ActivityReason='MSRES' AND activityValue='RESERVE' → skip (reqSuccess=true)
  • → select dispatch path below (A / B / C)
3A
PATH A — Multi-SIM (MSIM_TO_CANCEL)

Condition: exists($currSub/ExtendedInfo[Name="MSIM_TO_CANCEL"])

  1. Run PreExecCheck via GetXMLForSubscriber + XPath.execute
  2. Read simValues = ExtendedInfo["MSIM_TO_CANCEL"]/Value
  3. Split by "|" → simValueArray[]
  4. For each entry: split by "," → take [0] as simValue
  5. Send one ASRM_INVOKE_UNIFIED_RESOURCE_ACTIVITY event per SIM (XSLT with $currSub, $simValue)
  6. Send Logger audit event per request
  7. Increment RequestCount per request (if not resubmit)
3B
PATH B — RIO / Old EID

Condition (else): count($currSub/ResourceInfo[ResourceName="OLD_EID"]) > 0

  1. Run PreExecCheck via GetXMLForSubscriber
  2. Read simValue = ResourceInfo["OLD_SIM"]/ValuesArray
  3. Send ONE ASRM_INVOKE_UNIFIED_RESOURCE_ACTIVITY event
  4. Send Logger audit event
  5. Increment RequestCount (if not resubmit)
3C
PATH C — SubscriberOffers

Condition (else — no MSIM_TO_CANCEL, no OLD_EID)

  1. Iterate currSub.SubscriberOffers[] → for each curoffer:
  2. Read filter = curoffer.ExtendedInfo["FE_OR_CCBS"]/Value
  3. Run PreExecCheck via GetXMLForSubscriberOfferFilterWithExtendedInfo(…, curoffer.Soc, filter)
  4. Read simValue = curoffer.ParameterInfo["Related SIM"]/ValuesArray[1]
  5. Send ASRM_INVOKE_UNIFIED_RESOURCE_ACTIVITY per qualifying offer
  6. Send Logger audit event
  7. Increment RequestCount (if not resubmit)
4
ChildOU Loop — same tri-path logic for ParentOU[i] → ChildOU[k] → Subscriber[j] using GetXMLForSubscriberInChildOU / GetXMLForSubscriberOfferInChildOUFilterWithExtendedInfo
5
Status Update — if any request sent → Status = IN_PROGRESS; if all paths skipped → SkipActivity("4")
6
Exception Handling — catch → HandleActivityException → Status = ERROR

Path A — Pipe-Delimited Parsing

MSIM_TO_CANCEL format: "ICCID_1|ICCID_2,EXTRA|ICCID_3"
String.split(simValues, "\\|") → array of tokens
String.split(token, ",")[0] → takes first field only (the ICCID/SIM value); anything after comma is discarded

Path C — Offer-Level Filter

The filter variable (curoffer.ExtendedInfo["FE_OR_CCBS"]/Value) is passed to GetXMLForSubscriberOfferFilterWithExtendedInfo, which uses it to further filter the XML view of the offer before the PreExecCheck XPath runs. This allows per-offer scoping of the PreExecCheck expression.

§17 — Migration Notes & Recommendations

Functional Requirements

  • R1 — Implement three-path dispatch: MSIM_TO_CANCEL → OLD_EID/OLD_SIM → SubscriberOffers.
  • R2 — Path A must loop over pipe-delimited SIM values, splitting each by comma and taking [0].
  • R3 — Path B sources the SIM value from ResourceInfo["OLD_SIM"], not from ExtendedInfo.
  • R4 — Path C must iterate SubscriberOffers with per-offer PreExecCheck using FE_OR_CCBS filter.
  • R5 — Resource Type lookup key must be concat("SIM_PAIR_MSISDN_", $simValue) — per-SIM, not fixed.
  • R6 — MSRES + RESERVE subscribers must be auto-skipped before path evaluation.
  • R7 — RequestCount increments per individual request (multiple per subscriber in Path A and C).
  • R8 — Both ParentOU and ChildOU subscriber hierarchies must be supported.

§19 — Response Message Rule

§19.1 — Overview

RuleFunctions.OrderResponse.Response_ASRM_INVOKE_MINOR_SIM — identical structure to Response_ASRM_INVOKE_MSISDN and Response_ASRM_INVOKE_SIM. Creates ASRM_InvokeUnifiedResourceRes, appends to currActivity.Response[], logs audit (_RES), evaluates fan-in.

§19.4 — Fan-in Completion Logic

int successResponseCount = XPath.evalAsInt( "count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = \"000\"])"); if(currActivity.RequestCount == successResponseCount) return "true"; else return "false";
⚠ Important: Because Path A can send multiple requests per subscriber (one per SIM in MSIM_TO_CANCEL), RequestCount can be much larger than the subscriber count. The fan-in will only complete when ALL individual SIM operations return ResponseCode ending in "000".
