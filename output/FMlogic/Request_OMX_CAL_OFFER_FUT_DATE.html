Request_OMX_CAL_OFFER_FUT_DATE

Internal OMXOM Rule — Calculate Offer Future/Immediate Date Enrichment
Priority: 5 forwardChain: true Type: OMXOM Internal Synchronous — No JMS Author: RS33-BANDIT Generated: 2026-09-07
§1 — Overview & Purpose
OMX_CAL_OFFER_FUT_DATE is an internal OMXOM computation rule. It enriches every offer in the order (Agreement Offers, Subscriber Offers, Related Offers) with date-type annotations — determining whether each offer's EffectiveDate and ExpirationDate are immediate (IM), future (FUT), or absent — relative to a logical reference date. The rule writes EFF_TYPE and EXP_TYPE ExtendedInfo fields onto each offer and clears or preserves the actual date fields accordingly.
⚙️ OMXOM Internal Pattern
Synchronous — no JMS or external backend call. Completes by calling RuleFunctions.Helpers.NextActivity(orderRequest, orderCurrentActivity). No response rulefunction exists.

§5 — Execution Flow Diagram
1
Resolve logical date
Fetch Concepts.OM.LogicalDate from WM by extId="LogicalDate". If logicalDateRes.LogicalDate is blank, fall back to DateTime.now(). Parse using format "yyyy-MM-dd'T'HH:mm:ssXXX".
2
Determine FUT_TYPE flag
Evaluate XPath: boolean($orderRequest/OrderData/ExtendedInfo[Name='FUT_TYPE' and (Value='FUTSOC' or Value='EXPSOC')]) → isOmxFut boolean. Controls whether IM dates are cleared.
3
Read activity parameters
CAL_PARAM_EXP — if "Y", derive ExpirationDate from offer parameter TR_ORIG_CONTRACT_EXPIRE_DATE when ExpirationDate is null.
EXCLUDE_OFFER — offer name to exclude from the CAL_PARAM_EXP logic.
4
Process each ParentOU
For each ParentOU: process Agreement Offers → Subscriber Offers (+ Related Offers) → ChildOU Agreement Offers → ChildOU Subscriber Offers (+ Related Offers).
5
Per-offer date enrichment (applied to each offer type):
a. Read FE_OR_CCBS ExtendedInfo filter value from offer
b. Evaluate PreExecCheck XPath (if set) with offer XML context — skip offer if "false"
c. Compute EFF_TYPE = GetActivityEffectiveType(offer.EffectiveDate, logicalDate) → write as ExtendedInfo
d. If EFF_TYPE="IM" and !isOmxFut → clear EffectiveDate
e. Apply LogicalDate provisioning type A/B check (Wattanachai extension)
f. If ExpirationDate=null and CAL_PARAM_EXP="Y" and offer not excluded → populate from TR_ORIG_CONTRACT_EXPIRE_DATE (OMX-2623)
g. Compute EXP_TYPE = GetActivityEffectiveType(offer.ExpirationDate, logicalDate) → write as ExtendedInfo
h. If EXP_TYPE="FUT": save original as EXP_DATE_VALUE ExtendedInfo, clear ExpirationDate
i. If EXP_TYPE="IM" and !isOmxFut → clear ExpirationDate
j. If ServiceType="87" and (EFF_TYPE="FUT" or EXP_TYPE="FUT") → write SBM_NO_PROVISIONING=Y
6
Complete activity
Call RuleFunctions.Helpers.NextActivity(orderRequest, orderCurrentActivity) → advances process flow. Emit audit log "OMX-OM CalOfferFutureDate Completed."
7
Exception handling
Wrapped in try/catch → RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "")

§8 — System & Integration Dependencies

§8.1 Order Type Dependencies

Used in PREPAID_ADD_OFFER (step 9) and any process that needs offer date type enrichment. The FUT_TYPE ExtendedInfo on the order controls whether IM dates are cleared — orders with FUT_TYPE=FUTSOC or EXPSOC preserve IM dates.

§8.2 No ESB/JMS Integration

This is a pure in-memory computation. No JMS channel, no external system call. All data is read from and written back to the OrderRequest WM concept.

§18 — Full Source Code (condensed)
rule Rules.OMConsumers.OMXOM.OMX_CAL_OFFER_FUT_DATE {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "OMX_CAL_OFFER_FUT_DATE";
    orderRequest.ProcessFlow.NextActivityID == "OMX_CAL_OFFER_FUT_DATE";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    try {
      // 1. Resolve logical date
      DateTime logicalDate;
      Concepts.OM.LogicalDate logicalDateRes = Instance.getByExtIdByUri("LogicalDate", "/Concepts/OM/LogicalDate");
      if(String.length(String.trim(logicalDateRes.LogicalDate)) <= 0) {
        logicalDate = DateTime.now();
      } else {
        logicalDate = DateTime.parseString(logicalDateRes.LogicalDate, "yyyy-MM-dd'T'HH:mm:ssXXX");
      }

      // 2. FUT_TYPE flag: FUTSOC or EXPSOC → preserve IM dates
      boolean isOmxFut = XPath.evalAsBoolean("xpath://...FUT_TYPE=FUTSOC or EXPSOC...");

      String logicalDateTypeA = "A";   // Wattanachai
      String logicalDateTypeB = "B";

      // 3. Activity parameters
      String calParamExp = GetActivityParameterValueFromKey(orderCurrentActivity, "CAL_PARAM_EXP");
      String excludeOffer = GetActivityParameterValueFromKey(orderCurrentActivity, "EXCLUDE_OFFER");

      // 4-5. Iterate ParentOU → Agreement Offers, Subscriber Offers (+ Related), ChildOU → same
      // Per offer: read FE_OR_CCBS filter, evaluate PreExecCheck, then:
      //   - Set EFF_TYPE = GetActivityEffectiveType(offer.EffectiveDate, logicalDate)
      //   - If EFF_TYPE="IM" && !isOmxFut: clear EffectiveDate
      //   - LOGICALDATE_PROV: CheckOfferDateWillCompareWithLogicalDate() → A or B
      //   - If ExpirationDate=null && calParamExp="Y" && !excludeOffer: GetDateFromOfferParamName(offer,"TR_ORIG_CONTRACT_EXPIRE_DATE")
      //   - Set EXP_TYPE = GetActivityEffectiveType(offer.ExpirationDate, logicalDate)
      //   - If EXP_TYPE="FUT": save as EXP_DATE_VALUE, clear ExpirationDate
      //   - If EXP_TYPE="IM" && !isOmxFut: clear ExpirationDate
      //   - If ServiceType="87" && (EFF_TYPE="FUT" || EXP_TYPE="FUT"): SBM_NO_PROVISIONING=Y

      // 6. Complete
      RuleFunctions.Helpers.NextActivity(orderRequest, orderCurrentActivity);
      // Audit: "OMX-OM CalOfferFutureDate Completed."

    } catch (Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
