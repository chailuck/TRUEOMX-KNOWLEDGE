Request_OMX_GET_3CJ_EMAIL_TEMPLATE

3CJ SMS/Email Template Fetch — retrieves notification templates per Subscriber; writes EMAIL_TEMPLATE_CONTENT or SMS_MSG to Subscriber ExtInfo
Backend: 3CJ (SMS/Email Template) Priority: 5 Pattern: FIRE-AND-FORGET per Subscriber Author: TIT_CP-CHAYAT2 Write-back: EMAIL_TEMPLATE_CONTENT or SMS_MSG
§1 — Overview & Purpose
OMX_GET_3CJ_EMAIL_TEMPLATE fetches notification templates from the 3CJ service for each Subscriber. Despite its name, it uses the OMX_GET_3CJ_SMS_TEMPLATE event type. The response handler determines whether each returned template is an email template (by checking emailSubject) and writes it to the Subscriber's ExtInfo as either EMAIL_TEMPLATE_CONTENT or SMS_MSG.
Fire-and-forget per Subscriber: Event.Ext.sendEventImmediate + manual RequestCount++. Fan-in: count("000") == RequestCount.
Event name mismatch: The ActivityID is OMX_GET_3CJ_EMAIL_TEMPLATE but the JMS event type sent and received is OMX_GET_3CJ_SMS_TEMPLATE. This is intentional — the same endpoint serves both SMS and email templates; the contentType (from FLOW_ID ExtInfo) differentiates them.
CompletionStatus==2 resubmit skip: Per-subscriber response checked by RefId + CompletionStatus==2 before sending.
Write-back in response: Response handler iterates omxnNotiTemplate[]; if emailSubject != "" → EMAIL_TEMPLATE_CONTENT; else → SMS_MSG. Multiple templates possible — one subscriber ExtInfo entry per template item.
