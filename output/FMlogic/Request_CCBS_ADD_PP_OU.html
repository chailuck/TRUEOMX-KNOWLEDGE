🔍 1. Overview & Purpose
This rule sends Add Offer (PP — Postpaid Package, ServiceType 80) requests to the CCBS backend for all Organisational Units (OU) in the customer's hierarchy. It iterates over every ParentOU → ChildOU pair and, for each OU that holds an Agreement containing at least one Offer with ServiceType = '80', constructs and dispatches a CCBS_ADD_AGREEOFFER JMS event via the FM channel. An audit log entry is emitted after each successful dispatch.

This rule fires when the process flow pointer reaches activity CCBS_ADD_PP_OU and that activity's status is WAITING. It supports resubmission (purges stale pending requests before re-sending) and LargeCustomer date-override logic (computes tomorrow's logical date when LargeCustomerIndicator = 89). A configurable PreExecCheck XPath filter can exclude specific OU / Agreement combinations from dispatch. If no events are dispatched the activity is automatically SKIPPED and the flow advances.

Scope: Two independent loop paths are handled in this single rule — one for ChildOU agreements and one for ParentOU agreements. Both paths produce identical event schemas; only the source OU concept reference differs.

❓ 4. Rule Conditions (WHEN)

All four conditions must be satisfied simultaneously for the rule to fire. The engine matches orderCurrentActivity and orderRequest via the extId join.

orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName
orderCurrentActivity.ActivityID == "CCBS_ADD_PP_OU"
orderRequest.ProcessFlow.NextActivityID == "CCBS_ADD_PP_OU"
orderCurrentActivity.Status == "WAITING"

🔄 5. Execution Flow Diagram
1
Guard & Resubmit Check
Determine isActResub (RequestCount > 0 AND IsOrderResubmitted). If true, call PurgePendingRequestsBeforeResubmit to clear stale events.
2
Large Customer Date Override
If LargeCustomerIndicator = 89, compute tomorrowLogicalDate = DateTime.now() + 1 day formatted as ISO-8601.
3
Iterate ChildOU Agreements
For each ParentOU[i] → ChildOU[j]: if Agreement exists with Offers, run PreExecCheck. If passes, count offers/relatedOffers, build CCBS_ADD_AGREEOFFER XSLT event, send immediately, increment RequestCount, emit audit log.
4
Iterate ParentOU Agreements
For each ParentOU[i]: if Agreement exists with Offers, run PreExecCheck. If passes, same build-and-send pattern as ChildOU, then emit audit log.
5a
isSkipped = true path → SKIPPED
No events were dispatched (no qualifying agreements). Call SkipActivity(orderRequest, orderCurrentActivity, "4") → status becomes SKIPPED and flow advances to next activity.
5b
isSkipped = false path → IN_PROGRESS
At least one event was dispatched. Set orderCurrentActivity.Status = "IN_PROGRESS" via GetActivityStatusString("1", false). Call SendDataToDB to persist state.
6
Exception Handler
Any exception caught → HandleActivityException: sets activity status ERROR, order status FAILED, fires error Logger event, persists to DB.
▶ 6. Rule Action (THEN) — Step-by-Step Logic
1
Resubmit flag: isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted)
2
Fetch nextAct: Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName, "/Concepts/OM/ProcessConfig/Activity") — used to read PreExecCheck expression.
3
Purge on resubmit: If isActResub, call PurgePendingRequestsBeforeResubmit(orderCurrentActivity).
4
Large Customer date: Evaluate XPath $orderRequest/OrderData/Customer/CustomerGeneralInfo/LargeCustomerIndicator=89. If true, tomorrowLogicalDate = format(addDay(now(),1), "yyyy-MM-dd'T'00:00:00XXX").
5
ChildOU loop — for iPou in ParentOU.length → for iCou in ChildOU.length:
  a) Skip ChildOU if childOu.Agreement == null or Offers.length == 0
  b) Run PreExecCheck: call GetXMLForAgreementInChildOU(orderRequest, agreement.RefId, parentOu.RefId) then XPath evaluate; skip if result != "true"
  c) Count: countOfers = count($childOu/Agreement/Offers), countRelatedOffersArray = count($childOu/Agreement/*/RelatedOffersArray)
  d) Build and send CCBS_ADD_AGREEOFFER event via XSLT (see §9)
  e) If not resubmit: orderCurrentActivity.RequestCount++; set isSkipped = false
  f) Emit audit Logger event
6
ParentOU loop — after ChildOU inner loop, checks parentOu.Agreement directly:
  Same structure as ChildOU but uses GetXMLForAgreement(orderRequest, agreement.RefId) for PreExecCheck, and references $parentOu in XSLT.
7
Post-loop decision:
  • isSkipped == true → RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4")
  • isSkipped == false → orderCurrentActivity.Status = GetActivityStatusString("1", false); SendDataToDB(orderRequest)
!
catch(Exception ae): HandleActivityException(orderRequest, orderCurrentActivity, ae, "")

🛠 17. Migration Notes & Recommendations
Functional Requirements
IDRequirement
R1The replacement service MUST iterate the full ParentOU → ChildOU hierarchy for each order and send one AddOfferRequest per qualifying OU agreement.
R2Only Offers with ServiceType = '80' (Postpaid Package) MUST be selected; other ServiceType values MUST be ignored.
R3The SOC sequence number request MUST include incrementByCount = count(Offers) + count(all RelatedOffersArray) across the agreement.
R4When RCIndicator = 65 on a PP offer or its related offers, a chargeDistributionDetailsInfo block MUST be included with the matching Account's AccountID as targetPayChannelId.
R5The activityReason field MUST default to "CREQ" when AgreementActivityInfo.ActivityReason is blank or absent.
R6A configurable PreExecCheck XPath gate MUST be evaluated per OU before dispatch; OUs failing the check MUST be silently skipped.
