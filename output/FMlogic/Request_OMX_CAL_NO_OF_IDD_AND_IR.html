Request_OMX_CAL_NO_OF_IDD_AND_IR

In-memory calculation — counts subscribers requiring IDD/IR provisioning and stores results in POU

Rule: Rules.OMConsumers.OMXOM.OMX_CAL_NO_OF_IDD_AND_IR Type: In-memory calculation (no backend call) Author: CHAYATORN.P Generated: 2026-09-18
§1 — Overview & Purpose

OMX_CAL_NO_OF_IDD_AND_IR is a pure in-memory calculation rule. It iterates over each POU's subscribers and counts how many require IDD provisioning (NumberOfIDD) and how many require IR provisioning (NumberOfIR), then stores these counts on the ParentOU concept. No external system is called; no JMS message is sent to a backend.

The counts drive downstream steps that need to know whether IDD/IR services need to be provisioned for the current batch of subscribers (e.g., SBM, CCBS package changes).

No external system call. This rule only reads and writes BE working memory. It advances to NextActivity() immediately after calculation.
Found in Rules/OMConsumers/OMXOM/ — OMX orchestration rule, not an OMXFM backend-calling rule.

§5 — Execution Flow
  1. Evaluate runtime PreExecCheck from orderCurrentActivity.PreExecCheck via XPath.execute()
  2. If PreExecCheck fails → SkipActivity("4") and exit
  3. Loop iPOU over all orderRequest.OrderData.Customer.ParentOU:
    • Initialize noOfIdd = 0, noOfIR = 0
    • Loop subs over pOu.Subscriber:
        • IDD check: if subscriber has a CCBS offer with TR_IDD_FLAG=Y → noOfIdd += 0 (already provisioned, skip); else noOfIdd += 1
        • IR check: if subscriber has a CCBS offer with TR_IR_FLAG=Y OR a FE offer with OFFER_TYPE=IDD → noOfIR += 0; else noOfIR += 1
    • Set pOu.NumberOfIDD = noOfIdd
    • Set pOu.NumberOfIR = noOfIR
  4. Log "OmxCalNoOfIddAndIR Started" via sendEventImmediate(Logger)
  5. Call NextActivity(orderRequest, orderCurrentActivity)
  6. Exception → HandleActivityException(orderRequest, orderCurrentActivity, ae, "")
Counter naming note: The rule increments noOfIdd += 0 when the flag IS already set (i.e., CCBS already has it). The counter counts subscribers who do NOT yet have the service. This is intentional: the count represents how many NEW IDD/IR registrations are needed, not how many exist.
Commented-out inner loop: The for (int subOffer ...) inner loop over SubscriberOffers is fully commented out in the source. The subscriber-level check runs per-subscriber (not per-offer). The loop comment is dead code.
