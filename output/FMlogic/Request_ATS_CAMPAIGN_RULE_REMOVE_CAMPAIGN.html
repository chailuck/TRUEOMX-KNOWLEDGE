Target: ATS Operation: RemoveCampaign Priority: 5 ForwardChain: true Generated: 2026-09-23
§1 — Overview & Purpose

Sends a RemoveCampaign request to the ATS CampaignRule service for each BundleInfo entry in the order. For MobileSoftBundle cancellations, it informs ATS to remove the campaign association, receiving back a CampaignRuleResponse that identifies which subscriber offers should be updated (ATS_REMOVE or ATS action tags).

Used in CANCEL_SUBSCRIBER process — Step 25 — gated on the presence of MobileSoftBundle offers.

§5 — Execution Flow
  1. Check if this is a resubmit (RequestCount > 0 && IsOrderResubmitted)
  2. Evaluate PreExecCheck XPath against order XML
  3. If check passes: iterate each BundleInfo entry (0-based index)
  4. For each bundle: create and send ATS_CAMPAIGN_RULE event via XSLT, increment RequestCount
  5. Send audit log event (_REQ suffix)
  6. If at least one request was sent: set activity Status = "1" (RUNNING), persist to DB
  7. If all bundles were skipped: call SkipActivity(status="4")
  8. On exception: call HandleActivityException

§19 — Response Message Rule

§19.1 Overview: Parses ATS CampaignRuleResponse. Extracts convergenceAction and benefitCampaignList to update BundleInfo and SubscriberOffers FE_OR_CCBS tags. Fan-in by ResponseCode "000" count.

§19.2 Scope Variables:

§19.4 Response Logic:
  • Creates ResponseBase with ResponseCode, ResponseMessage, CompletionStatus, ReferenceId
  • If convergenceAction present: updates BundleInfo.ConvergenceAction for matching CampaignCode
  • For each productList/benefitCampaignList item: updates SubscriberOffers.Action and sets FE_OR_CCBS = ATS_REMOVE (if REMOVE) or ATS (otherwise)
  • Fan-in: count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = "000"]) == currActivity.RequestCount
