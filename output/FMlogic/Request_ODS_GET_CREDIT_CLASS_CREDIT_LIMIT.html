Request_ODS_GET_CREDIT_CLASS_CREDIT_LIMIT

ODS Credit Assessment — multi-SIM pre-pass across all subscribers then per-account evaluation
Backend: ODS Author: awalia-t420 Priority: 5 Pattern: IntraActivitySequencing Iteration: Account[] (with subscriber pre-pass)
§1 — Overview & Purpose
ODS_GET_CREDIT_CLASS_CREDIT_LIMIT calls ODS (Offer & Data Service) to retrieve a credit class and credit limit for each Account. The results are written back to Account ExtInfo as ODS_CREDIT_CLASS and ODS_CREDIT_LIMIT for downstream use by FM21 (CCBS_UPD_CREDIT_CLASS) and FM22 (CCBS_UPDATE_NEW_ACCT_CREDIT_LIMIT).
Multi-SIM pre-pass (unique pattern): Before the Account loop, the rule scans ALL subscribers across ALL POU/ChildOU to identify multi-SIM subscribers (TR_MULTISIM_IND=RCM AND FE_OR_CCBS=FE). The accumulated sumMinorRC (sum of OfferRate) is passed as an XSLT parameter to every Account's request.
Two XSLT variants (OMX-2605): Old XSLT (commented out) omitted priceplanRC for DIY offers, included an OrderType=53 creditClass default, and lacked relaxBlacklist. Active XSLT adds all three. OrderType=11002 has special primaryResourceValue and priceplanName paths.
Response write-backs (2): Writes ODS_CREDIT_CLASS and ODS_CREDIT_LIMIT as AccountExtendedInfo to the matching Account, using extId pattern ACCEXT:{trackId}:{RefID}:CREDIT_CLASS/CREDIT_LIMIT.

§7 — Key Logic Patterns & Dispatches
PatternDetail
Multi-SIM pre-pass Scans all POU[i].ChildOU[k].Subscriber[j].SubscriberOffer[] AND POU[i].Subscriber[j].SubscriberOffer[]. Sets isMultiSIM=true when ExtendedInfo[Name='TR_MULTISIM_IND'].Value='RCM' AND ExtendedInfo[Name='FE_OR_CCBS'].Value='FE'. Accumulates sumMinorRC += SubscriberOffer.OfferRate when condition met.
LogicalDate logicalDate = GetFirstBillDate(orderRequest) — billing calculation function, not the order creation date.
agreeRefId From POU.Agreement[RefId=AgreementRefId] linked to Account[i]. Used in ODS for agreement-scoped priceplan lookups.
OrderType=11002 paths primaryResourceValue: from POU[agreeRefId]/Subscriber[AccountRefId=AccountRefId].MSISDN → ChildOU fallback.
priceplanName: from POU.Agreement[agreeRefId].Offer[0].ProductId.
DIY priceplanRC (OMX-2605) If Subscriber.SubscriberOffer[isDIYOffer='Y'].OfferRate exists → include in priceplanRC. Active XSLT only.
relaxBlacklist (OMX-2605) RELAX_STATUS ExtInfo appended by NAS response. Active XSLT reads it from Subscriber ExtInfo and passes as <relaxBlacklist>. Old XSLT omitted this field.
OrderType=53 creditClass default Old XSLT sent hardcoded creditClass=3 for OrderType=53. Active XSLT removes this — ODS always evaluates.

§17 — Migration Notes & Recommendations
RiskSeverityMitigation
Multi-SIM pre-pass accumulates sumMinorRC across ALL subscribers globally — if the subscriber list is large, this loop is O(N×M) (accounts × subscribers × offers) before the account loop begins MEDIUM In migration, consider streaming aggregation or pre-aggregating OfferRate at order construction time
relaxBlacklist reads RELAX_STATUS written by NAS_ACTIVATE_NEW_SUBS response — FM20 has an implicit ordering dependency on FM18 MEDIUM Document FM18→FM20 dependency explicitly in ProcessConfig. Validate that activity sequencing enforces this.
Old XSLT (pre-OMX-2605) hardcoded creditClass=3 for OrderType=53 — completely removed in active XSLT LOW Confirm OrderType=53 behaviour is correct without the default; ODS now evaluates fully
ODS_GetCreditClassCreditLimitRes has 6 fields (adds CreditClass + CreditLimit to standard 4) — downstream code reads these from the response concept, not ExtInfo directly in the response function LOW Ensure migration keeps both response concept fields and ExtInfo write-backs; they serve different consumers
extId pattern "ACCEXT:{trackId}:{RefID}:CREDIT_CLASS" ties the ODS result to the tracking ID at call time — if trackId changes on resubmit, lookup in FM21/FM22 may fail MEDIUM FM21/FM22 should search ExtInfo by Name, not by extId, to be resubmit-safe
