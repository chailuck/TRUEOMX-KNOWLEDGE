Request_ASRM_GET_NEXT_AVAILABLE_UNIFIED_RESOURCE_LIST

Find & reserve the next available SIM/eSIM resource from ASRM for swap/portIn operations (RIO, RIO_SWAP, ESIM)
Rule Priority: 5 ForwardChain: true Backend: ASRM Pattern: IntraActivitySequencing Author: chch
§1 — Overview & Purpose

This rule fires when the order flow reaches the ASRM_GET_NEXT_AVAILABLE_UNIFIED_RESOURCE_LIST activity. It requests the next available SIM resource from ASRM by building a UnifiedResourceListRequest with criteria: COMPANY (from param or account CompanyCode), SIM_TYPE (from subscriber ResourceInfo or default '6'), DEALER (from param or default), Status=AVAILABLE, Type=SIM, with Activity=RESERVE. The call pattern is IntraActivitySequencing (fan-out per subscriber/offer, fan-in when all respond). Three XSLT variants handle: ① PROJ=RIO/RIO_SWAP/ESIM with OLD_EID check (one call per account), ② standard offer-level iteration for POU subscribers, ③ standard offer-level for ChildOU subscribers. The response handler writes the returned ICCID back into the order working memory at the correct location (subscriber ExtendedInfo or SubscriberOffers ExtendedInfo) based on PROJ.

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_ASRM_GET_NEXT_AVAILABLE_UNIFIED_RESOURCE_LIST {
  attribute { priority=5; forwardChain=true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "ASRM_GET_NEXT_AVAILABLE_UNIFIED_RESOURCE_LIST";
    orderRequest.ProcessFlow.NextActivityID == "ASRM_GET_NEXT_AVAILABLE_UNIFIED_RESOURCE_LIST";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    String operationName = orderCurrentActivity.ActivityID;
    boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
    try {
      boolean isSkipped = true;
      String projName = "PROJ";
      String paramValue = RuleFunctions.Helpers.GetActivityParamValueFromKey(orderCurrentActivity, projName);
      String dealerCode = "DEALERCODE";
      String dealerCodeValue = RuleFunctions.Helpers.GetActivityParamValueFromKey(orderCurrentActivity, dealerCode);
      String company = RuleFunctions.Helpers.GetActivityParameterValueFromKey(orderCurrentActivity, "COMPANY");

      // POU loop: for each subscriber/offer
      // BRANCH A: PROJ=RIO/RIO_SWAP/ESIM — single call with OLD_EID/ESIM gate; break after
      // BRANCH B: per-offer fan-out with FE_OR_CCBS filter and PreExecCheck
      // ChildOU loop: same pattern as BRANCH B

      // XSLT builds UnifiedResourceListRequest — see §9 for full field mapping
      // Full XSLT source in §9.8 (3 variants)

      if (!isSkipped) {
        RuleFunctions.Helpers.IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch (Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

§19.1 Overview

Parses ASRM response into ASRM_GetURListRes concept. Extracts ICCID from UnifiedResourceListInfo/UnifiedResourceInfoArr[1]/UnifiedResourceIdInfo/Value. Writes ICCID to the order working memory (subscriber or offer level, based on PROJ). Fan-in: IntraActivitySequencing.ActionResponseEvent(currActivity).

§19.4 Post-processing: ICCID write-back

§19.4 Fan-in Completion Logic

Uses IntraActivitySequencing.ActionResponseEvent(currActivity) which checks internal state. Returns "true" when all expected responses have arrived.
