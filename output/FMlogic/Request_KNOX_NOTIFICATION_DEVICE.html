Request_KNOX_NOTIFICATION_DEVICE

Sends a Knox device notification (method="notificationDevice") per qualifying subscriber offer via the shared KNOX_PROXY_SERVICE event. Message body resolved via KnoxNotifyMsgVRF decision table from order type, activity reason, and subscriber language.
Backend: Knox (notificationDevice) Event: KNOX_PROXY_SERVICE (shared) Pattern: Per-offer fan-out forwardChain: true Author: DESKTOP-995HR2V Used in step: 68 Generated: 2026-08-11
§1 — Overview & Purpose

Sends one Knox knoxProxyReq (method=notificationDevice) per qualifying subscriber offer. Uses the same shared KNOX_PROXY_SERVICE event as KNOX_SAVE_DEVICE — the operation is distinguished by the hardcoded ns2:method = "notificationDevice". The notification message body is resolved at runtime via the KnoxNotifyMsgVRF decision table, driven by OrderType, activityReason, and subscriber Language. The telephone number is read from the ProcessConfig Parameter[TEL] key.

  • Parameter guard: throws DATA_ISSUE if no Parameter entries — TEL is mandatory
  • tel: GetActivityParameterValueFromKey(orderCurrentActivity, "TEL")
  • KnoxNotifyMsgVRF: DecisionTables.KnoxNotifyMsgVRF(OrderType, "NOTIFY", activityReason, lang, msg)
  • msg appended: offer.ExtendedInfo[len] = msg (Name="KNOX_NOTIFY_MSG") before sending
  • Method discriminator: ns2:method = "notificationDevice" (hardcoded)
  • Response: standard ResponseBase only — no write-back
[HIGH] POU XSLT sends wrong RefID: The POU XSLT param is named pSubRefId, which binds to the BE variable pSubRefId (bare subscriber RefId, e.g. "SUB001"), NOT the computed offerRefId ("SUB001:SOC:FE"). Knox echoes this RefID back; it is stored in ResponseBase.ReferenceId. The resubmit guard checks Response[ReferenceId == offerRefId] — since pSubRefId ≠ offerRefId, POU offers are always treated as not-yet-complete on resubmit and will be re-sent to Knox. This is the mirror-opposite of the PSA_UPDATE_KNOX_STATUS bug (where POU was correct, COU wrong).
[INFO] COU RefID is CORRECT: The COU XSLT param is named offerRefId, binding to the BE variable offerRefId = cSubRefId:Soc:filter. Resubmit correlation works for COU offers.
[MEDIUM] COU PreExecCheck uses subscriber-level context: GetXMLForSubscriberInChildOU instead of GetXMLForSubscriberOfferInChildOUFilterWithExtendedInfo.
[LOW] No PurgePendingRequestsBeforeResubmit: Duplicate Knox notifications possible on resubmit (compounded by the POU resubmit guard failure above).

§7 — KnoxNotifyMsgVRF Decision Table

Before dispatching the Knox event, both POU and COU variants call the KnoxNotifyMsgVRF decision table to resolve the notification message string. The resolved concept is then appended to the offer's ExtendedInfo.

StepActionDetail
1Create msg conceptInstance.createInstance(SubscriberOffersExtendedInfo) with Name="KNOX_NOTIFY_MSG", extId=generateTrackingID()
2Resolve langsub.SubscriberGeneralInfo.Language if not blank; else default "TH"
3Resolve activityReasonsub.SubscriberActivityInfo.ActivityReason if not blank; else default ""
4Call decision tableDecisionTables.KnoxNotifyMsgVRF(OrderType, "NOTIFY", activityReason, lang, msg) → populates msg.Value
5Append to ExtendedInfooffer.ExtendedInfo[offer.ExtendedInfo@length] = msg
6Pass to XSLT$msg/Value → ns2:message (conditional on msg having Value)
DecisionTable inputs: OrderType (e.g., "POSTPAID_ADD_OFFER_SUB"), action = "NOTIFY" (hardcoded), activityReason (from SubscriberActivityInfo or ""), lang ("TH" or subscriber language). The table maps these to a human-readable Knox notification message string stored in msg.Value.
