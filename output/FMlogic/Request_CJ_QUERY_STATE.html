Request_CJ_QUERY_STATE

Query subscriber's current call verification state in the Customer Journey service
Backend: CJ Pattern: POU Loop · IntraSeq Fan-in Priority: 5 Generated: 2026-09-18
§1 — Overview & Purpose

This rule queries the Customer Journey (CJ) service for the current call-verification state of each subscriber (POU loop). The response is used to decide whether provisioning should be enabled/disabled and whether the PROFCVBAR offer should be added or removed. A complex state-machine in the response handler (§19) compares the CJ-held callVerStatus against the order's target CALL_VER_STATUS ExtendedInfo to determine the PROVISIONING flag and subscriber offer actions downstream.

Trigger: ActivityID == "CJ_QUERY_STATE" and Status == "WAITING".

§6 — Rule Action (THEN) — Key Logic

Iterates ParentOU[i].Subscriber[j]. For each subscriber:

  • Checks existing Response entries for CompletionStatus==2 and matching ReferenceId — skips if already succeeded
  • Evaluates PreExecCheck XPath using GetXMLForSubscriber
  • Creates CJ_QUERY_STATE event with ns:QueryStateRequest/ns:serviceId = subscriber.MSISDN
  • Registers event with IntraActivitySequencing.ActionRequestEvent
No ChildOU iteration — this is a POU-only loop. CJ query is per-subscriber on ParentOU only.

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_CJ_QUERY_STATE {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "CJ_QUERY_STATE";
    orderRequest.ProcessFlow.NextActivityID == "CJ_QUERY_STATE";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
    try {
      // ... (getByExtIdByUri, PurgePending if resubmit)
      boolean isSkipped = true;
      // POU loop → subscriber loop
      // ... already-succeeded check + PreExecCheck evaluation ...
      // Build QueryStateRequest XSLT event — see §9.8 for full XSLT
      Events.OMConsumers.OMXFM.Request.CJ_QUERY_STATE reqEvent = Event.createEvent("xslt://{{/Events/...CJ_QUERY_STATE}} <!-- §9.8: payload/ns:QueryStateRequest/ns:serviceId ← subscriber/MSISDN -->");
      Event.assertEvent(reqEvent);
      RuleFunctions.Helpers.IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity);
      // Logger audit event (sendEventImmediate) — see §11
      isSkipped = false;
      // End loops
      if(!isSkipped) {
        RuleFunctions.Helpers.IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
        orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
        RuleFunctions.Helpers.SendDataToDB(orderRequest);
      } else {
        RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch(Exception ae) {
      RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

§19.1 Overview

Response_CJ_QUERY_STATE processes the CJ backend reply. It performs a cross-reference state machine: it reads callVerStatus from the CJ response payload and compares it against CALL_VER_STATUS from each subscriber's ExtendedInfo to derive downstream PROVISIONING flags and PROFCVBAR offer actions.

§19.2 Scope Variables

VariableTypeRole
orderRequestConcepts.OrderRequest.OrderRequestFull order — updated with PROVISIONING / IS_UPDATE_CALLVER
eventResponseEvents.OMConsumers.OMXFM.Response.CJ_QUERY_STATECJ response event — carries ResponseCode, ResponseMsg, CompletionStatus, RefID, and payload
currActivityConcepts.OM.ProcessConfig.ActivityActivity for fan-in tracking

§19.3 ResponseBase Concept Construction

  • createObject (ResponseBase)
    • extId←OMXUtils.generateTrackingID()Always
    • ResponseCode←$eventResponse/ResponseCodeAlways
    • ResponseMessage←$eventResponse/ResponseMsgAlways
    • CompletionStatus←$eventResponse/CompletionStatusAlways
    • ReferenceId←$eventResponse/RefIDAlways

The constructed ResponseBase is appended to currActivity.Response[]. Also sets currActivity.ResponseCode and currActivity.ResponseMessage directly.

§19.4 Response Completion Logic & State Machine

The response handler extracts from the CJ payload:

  • currentStatus = payload/xsd2:QueryStateResponse/xsd2:callVerStatus (value from CJ)
  • callVerResult = payload/xsd2:QueryStateResponse/xsd2:callVerResult
  • newStatus = subscriber/ExtendedInfo[Name="CALL_VER_STATUS"]/Value (order target)

Decision matrix (currentStatus → newStatus → PROVISIONING, action, isUpdateCallver):

currentStatus (CJ)newStatus (Order)PROVISIONINGactionIS_UPDATE_CALLVER
NOFCRPASSYREMOVEY
NOFCROVERFLOWYREMOVEY
NOFCRNOTPASSNNoSetY
NOTPASSPASSYREMOVEY
NOTPASSOVERFLOWYREMOVEY
NOTPASSNOTPASSNNoSetY
OVERFLOWPASSNNoSetY
OVERFLOWOVERFLOWNNoSetY
OVERFLOWNOTPASSYADD ★Y
PASSPASSYREMOVEY
PASSNOTPASSNNoSetN
PASSOVERFLOWNNoSetN
★ OVERFLOW→NOTPASS: action=ADD also creates a new SubscriberOffers entry with OfferName=PROFCVBAR, ServiceType=85, Action=ADD, ExtendedInfo[FE_OR_CCBS]=FE and appends it to subscriber.SubscriberOffers[].

PROFCVBAR offer update: For all existing PROFCVBAR offers: sets subOffer.Action = action and appends ExtendedInfo[Name=CALL_VER_RESULT, Value=callVerResult].

Fan-in: Uses IntraActivitySequencing.ActionResponseEvent(currActivity) — returns "true" when all pending requests are resolved.

Note: IS_UPDATE_CALLVER=N cases (PASS→NOTPASS, PASS→OVERFLOW) suppress the downstream CJ_UPDATE_CALL_VERIFICATION step via its PreExecCheck.
