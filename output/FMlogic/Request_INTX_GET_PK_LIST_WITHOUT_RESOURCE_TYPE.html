Request_INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE

TIBCO BusinessEvents FM Logic — INTX Get Primary Key List Without Resource Type
Backend: INTX Priority: 5 ForwardChain: true Loop: ParentOU → Subscriber Fan-in: Simple (count "000") Generated: 2026-09-23
§1 — Overview & Purpose

This FM rule invokes the INTX getPrimaryKeyListWithoutResourceType service for each subscriber MSISDN under each ParentOU. Its primary purpose in the CREATE_BILL_ADJUSTMENT flow (step 1) is to resolve the subscriber's product ID (used as the internal SubscriberId) and product status (written back as CRM_SUB_STATUS ExtendedInfo), allowing downstream steps to determine whether to route the billing adjustment via AR credit (BILL=Y) or BL charge (BILL=N).

The response handler also checks subscriber active status by reading xsd5:productStatus from the INTX response and writes it into working memory for use by subsequent rules in the order flow.

OMX-2868 note: The response rule explicitly sets subscriber.SubscriberId from the INTX productId field and writes a CRM_SUB_STATUS ExtendedInfo entry — this is the canonical way subscriber IDs are resolved in INTX-gated flows.

§5 — Execution Flow Diagram
1
Resubmit check: If RequestCount > 0 && IsOrderResubmitted, call IntraActivitySequencing.PurgePendingRequestsBeforeResubmit to clean up stale request tracking.
2
PreExecCheck gate: Reads nextAct.PreExecCheck XPath. For CREATE_BILL_ADJUSTMENT step 1, the check is:
boolean(//Subscriber[ExtendedInfo[Name='PRIMARY_RESOURCE_TYPE' and Value='C']]) and exists(//SubscriberOffers/ExtendedInfo[Name='BILL']) — skips the activity if subscriber is not type C or has no BILL offer.
3
Per-subscriber loop (ParentOU → Subscriber): For each subscriber under each ParentOU, check if a successful response (CompletionStatus==2) already exists for this pSubRefId. If yes, skip that subscriber.
4
Evaluate PreExecCheck per subscriber: Calls GetXMLForSubscriber(orderRequest, pSubRefId) and executes the XPath. If result is not "true", this subscriber is skipped (the activity may still send for other subscribers).
5
Build & send INTX request event: Creates Events.OMConsumers.OMXFM.Request.INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE via XSLT with MSISDN, accountId, correlatedId. Sends immediately via Event.Ext.sendEventImmediate.
6
RequestCount increment: orderCurrentActivity.RequestCount++ (only on first run, not resubmit). Sets isSkipped = false.
7
Audit log: Sends ESB Logger event with AUDIT_TRACE = "Request Sent for INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE".
8
Activity status update: If at least one request was sent (!isSkipped): Status = GetActivityStatusString("1", false) (SENT) + SendDataToDB. Otherwise: SkipActivity(orderRequest, orderCurrentActivity, "4").

§18 — Full Source Code
rule Rules.OMConsumers.OMXFM.Request.Request_INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE {
  attribute { priority = 5; forwardChain = true; }
  declare {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when {
    orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
    orderCurrentActivity.ActivityID == "INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE";
    orderRequest.ProcessFlow.NextActivityID == "INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE";
    orderCurrentActivity.Status == "WAITING";
  }
  then {
    boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
    try {
      // ... get nextAct, PreExecCheck, isSkipped=true ...
      if(isActResub) IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity);
      // Loop ParentOU → Subscriber
      for(int p=0; p < pOuLen; p++) {
        for(int s=0; s < pSubLen; s++) {
          // skip if already responded with CompletionStatus==2
          if(!reqSuccess) {
            // evaluate PreExecCheck XPath via GetXMLForSubscriber
            if(chkRes == "true") {
              Events.OMConsumers.OMXFM.Request.INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE reqEvent =
                Event.createEvent("xslt://{{...}}");
                /* XSLT builds getPrimaryKeyListWithoutResourceTypeRequest:
                   correlatedId ← OMXTrackingId, primResourceValue ← msisdn,
                   accountId ← Account[1]/AccountID — see §9.8 for full XSLT */
              Event.Ext.sendEventImmediate(reqEvent);
              isSkipped = false;
              if(!isActResub) orderCurrentActivity.RequestCount++;
              // audit log — "Request Sent for INTX_GET_PK_LIST_WITHOUT_RESOURCE_TYPE"
            }
          }
        }
      }
      if(!isSkipped) {
        orderCurrentActivity.Status = GetActivityStatusString("1", false);
        SendDataToDB(orderRequest);
      } else {
        SkipActivity(orderRequest, orderCurrentActivity, "4");
      }
    } catch(Exception ae) {
      HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
    }
  }
}
§19 — Response Message Rule

§19.1 — Overview

Receives INTX response for a single subscriber. Extracts productId and productStatus from the response payload, updates subscriber working memory, and writes CRM_SUB_STATUS ExtendedInfo. Performs simple fan-in via count("000") == RequestCount.

§19.4 — Response Side Effects & Completion Logic

Data extraction from payload:

  • subStatus ← payload/xsd5:getPrimaryKeyListWithoutResourceTypeResponse/xsd5:return/xsd5:primaryKeyList/xsd5:primaryKeyInfoArray[1]/xsd5:productStatus
  • subscriberId ← payload/xsd5:getPrimaryKeyListWithoutResourceTypeResponse/xsd5:return/xsd5:primaryKeyList/xsd5:primaryKeyInfoArray[1]/xsd5:productId

Working memory writes:

  • subscriber.SubscriberId = subscriberId
  • Appends CRM_SUB_STATUS = subStatus to subscriber.ExtendedInfo[]

Fan-in condition:

int successResponseCount = count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = "000"])
if(currActivity.RequestCount == successResponseCount) → return "true"
else → return "false"

"true" signals that all subscriber requests have responded successfully — the process flow advances to the next activity.
