Request_ATS_ENQUIRY_CAMPAIGN

TIBCO BusinessEvents FM Logic — ATS Campaign Enquiry (Order-level, Single Request)
Rule Type: OMXFM Request Backend: ATS (Campaign Management) Priority: 5 Pattern: Single Order-Level Request Generated: 2026-08-13

§1 — Overview & Purpose

Request_ATS_ENQUIRY_CAMPAIGN sends an EnquiryCampaignRequest to the ATS (Campaign Management) system to retrieve the active campaigns associated with a subscriber. Unlike most other OMXFM rules, this rule fires a single order-level request — the per-subscriber fan-out code was written but deliberately commented out.

The request uses function="All", activeFlag="Y", and productType="TMV" to fetch all active TMV campaigns. The subscriber's MSISDN is selected via conditional logic based on the order type: for CHANGE_MSISDN orders (types 21 / 12001), the SOURCE subscriber is used; otherwise the first ParentOU/COU subscriber is used.

The response handler is the most complex in the FM set — it iterates all returned campaignInfo elements and enriches working memory with BundleInfo concepts and subscriber ExtendedInfo (CampaignCode, FamilyType, NUM_MEMBER), supporting both MobileSoftBundle and FindFriend campaign types with multi-branch debundle action logic.

Architecture divergence: The per-subscriber fan-out pattern (loops over POU + COU) is present in the source but entirely commented out. The active code fires exactly ONE request per order using Event.Ext.sendEventImmediate (not IntraActivitySequencing). Fan-in uses ResponseCode suffix "000" count against RequestCount.

§19 — Response Message Rule

§19.1 — Overview

Response_ATS_ENQUIRY_CAMPAIGN is the most complex response handler in this FM set. Beyond the standard ResponseBase mapping and audit log, it performs substantial working memory enrichment by processing each campaignInfo entry from the ATS response and writing campaign data into the order's BundleInfo array and subscriber ExtendedInfo.

§19.6 — Fan-in Completion Logic

int successResponseCount = XPath.evalAsInt( "count($currActivity/Response[tib:right(tib:trim(ResponseCode), 3) = \"000\"])"); if(currActivity.RequestCount == successResponseCount) { return "true"; } else { return "false"; }

Success = ResponseCode last 3 digits = "000". Since there is only 1 request (RequestCount=1), the first successful response triggers completion.
