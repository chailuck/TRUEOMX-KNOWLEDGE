Request_OMX_SAVE_PARTIAL_ORDER

Partial Order Save/Update — persists subscriber order data to OMX partial order store; dual SAVE/UPDATE action; richest payload in ACTIVATION flow
Backend: OMX Partial Order Service Priority: 5 Pattern: FIRE-AND-FORGET per Subscriber Author: Chayatorn P. Action: SAVE | UPDATE
§1 — Overview & Purpose
OMX_SAVE_PARTIAL_ORDER persists the full subscriber order snapshot to the OMX partial order store. It is the richest payload in the ACTIVATION flow — serialising customer info, subscriber offers, resources, and all ExtendedInfo collections from five different order scopes (order, customer, account, agreement, subscriber).
Mandatory parameter guard: Parameter@length == 0 throws DATA_ISSUE. The ProcessConfig Activity must supply at least ACTION and optionally STATUS parameters.
Dual operation: ACTION="SAVE" creates a new partial order; other values (e.g. "UPDATE") update an existing one. The OPERATION_NAME in audit log switches accordingly.
Fire-and-forget per Subscriber: Event.Ext.sendEventImmediate + manual RequestCount++. Iterates both POU and ChildOU Subscribers. Fan-in: count("000") == RequestCount.
Agreement ExtInfo scope: POU path uses ParentOU[i+1]/Agreement/ExtendedInfo; ChildOU path uses ParentOU[i+1]/ChildOU[k+1]/Agreement/ExtendedInfo. Note 1-indexed XSLT offset from 0-indexed BE loop variables.
