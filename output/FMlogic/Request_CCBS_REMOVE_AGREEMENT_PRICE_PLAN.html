Rule: Rules.OMConsumers.OMXFM.Request.Request_CCBS_REMOVE_AGREEMENT_PRICE_PLAN ActivityID: CCBS_REMOVE_AGREEMENT_PRICE_PLAN Priority: 5 Pattern: Per-offer dispatch (POU first, then COU) Used in step: 18 Generated: 2026-09-11
§1 — Overview & Purpose

CCBS_REMOVE_AGREEMENT_PRICE_PLAN removes an existing price plan from an agreement. For each ParentOU's Agreement Offers (POU scope first), then for each ChildOU — it iterates all qualifying offers per scope. Per-offer PreExecCheck determines if the offer qualifies. Each qualifying offer that has not already received a successful response dispatches one CCBS_REMOVE_AGREEMENT_PRICE_PLAN JMS event.

[CRITICAL BUG] COU loop iterates wrong offer array (line 102): The COU loop at line 96 iterates childOU, but the inner offer loop at line 102 iterates parentOU.Agreement.Offers (not childOU.Agreement.Offers). The offer variable cagof is drawn from parentOU's offers and dispatched with the childOU's RefId. This means the COU scope effectively sends parentOU offers labelled as childOU — a copy-paste error. In practice if parentOU and childOU have the same set of offers, results may appear correct.
Key design notes:
  • POU→COU order: POU Agreement Offers are processed first (lines 47–92), then COU scope (lines 96–146). Opposite of CCBS_CHANGE_PP_OU (which was COU→POU).
  • Per-offer dispatch: One event dispatched per qualifying Agreement Offer (not per OU). Same pattern as OMX_ADD_FUT_OFFERS.
  • Parameter[1] validation: If Parameter[1] is non-blank → must be "ADD" or "REMOVE" or throws DATA_ISSUE exception. If non-blank → also overrides agof.Action = param for each offer before dispatch.
  • FE_OR_CCBS filter: Read from each offer's ExtendedInfo and passed to the PreExecCheck XML helper. Not used as a dispatch gate in the rule itself.
  • reqSuccess check: Uses OU RefId (pOuRefId or cOuRefId) — not offer Soc. If any response with that OU's RefId and CompletionStatus==2 exists → ALL offers in that OU are skipped on resubmit.
  • logicalDateVal computed but unused: LogicalDate is loaded from BE concept AND may be overridden with tomorrowLogicalDate, but logicalDateVal is never passed to any XSLT nor used elsewhere. Dead code.
  • JMS headers not conditional: Unlike CCBS_CHANGE_PP_OU, JMSPriority/JMSCorrelationID/OrderID/RefID/UserName/PassWord are emitted unconditionally (no xsl:if guards).
  • PurgePendingRequestsBeforeResubmit: Called when isActResub==true.
  • Fan-in: Delegated to helper IsAllResponseSuccess(currActivity) — checks all responses (not just "000" count).

§5 — Execution Flow Diagram
  1. LogicalDate: Load from BE concept Concepts.OM.LogicalDate; if LargeCustomerIndicator=89 → override with DateTime.addDay(now,1) (→ unused).
  2. isActResub + PurgePending: If RequestCount>0 && IsOrderResubmitted → Purge pending requests.
  3. Parameter[1] validation: If non-blank: validate in {"ADD","REMOVE"} or throw DATA_ISSUE.
  4. POU scope: For each ParentOU → if Agreement.Offers > 0 → for each Offer: if param non-blank → set agof.Action=param; read FE_OR_CCBS filter; reqSuccess check (by pOuRefId); if !reqSuccess → PreExecCheck via GetXMLForAgreementOfferFilterWithExtendedInfo → if "true" → read activityReason/userText → dispatch → RequestCount++ → Logger.
  5. COU scope: For each ChildOU → if childOU.Agreement.Offers > 0 → for each parentOU.Agreement.Offers (bug: should be childOU): same offer-level loop as POU but with cOuRefId and GetXMLForAgreementOfferInChildOUFilterWithExtendedInfo.
  6. isSkipped resolution: If any event sent → Status="1" + SendDataToDB. Else → SkipActivity("4").
§6 — Parameter[1] Handling & Action Override

Note: The Action value is written directly to the concept object (agof.Action = param) before dispatching. This mutates working memory. The action is NOT included in the XSLT payload for CCBS_REMOVE_AGREEMENT_PRICE_PLAN (the payload only includes EffectiveDate, ExpirationDate, OfferName, OfferInstanceId, RelatedOffers, ServiceType, Soc). The FE_OR_CCBS filter (read for each offer) is only passed to the PreExecCheck helper, not to the event payload.
§7 — reqSuccess Check & COU Bug

§7.1 — reqSuccess Check

Before dispatching each offer, the rule scans orderCurrentActivity.Response[]:

for(iResp...) {
    if(String.equals(Response[iResp].ReferenceId, pOuRefId /* or cOuRefId */)
       && Response[iResp].CompletionStatus == 2) {
        reqSuccess = true;
    }
}

The reqSuccess check is per-OU (not per-offer): it compares ReferenceId == OU.RefId. If any response exists with that OU's RefId and CompletionStatus==2 → ALL offers in that OU are skipped on resubmit.

§7.2 — COU Loop Bug

[CRITICAL BUG] Line 102: for(int cof = 0; cof < parentOU.Agreement.Offers@length; cof++)
The inner loop bound should be childOU.Agreement.Offers@length but uses parentOU.Agreement.Offers@length.

Line 103: Concepts.OrderRequest.OrderElements.AgreementOffers cagof = parentOU.Agreement.Offers[cof];
The offer pulled should be from childOU.Agreement.Offers[cof] but is from parentOU.Agreement.Offers[cof].

Impact: For each childOU, the rule dispatches parentOU's Agreement Offers (not childOU's) tagged with cOuRefId. The XSLT uses $cagof (parentOU offer) with $cOuRefId and $cAgId (childOU's AgreementId). This creates a mismatch: childOU's AgreementId + parentOU's SOC data + childOU's RefId.
