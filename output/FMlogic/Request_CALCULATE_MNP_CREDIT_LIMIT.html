Request_CALCULATE_MNP_CREDIT_LIMIT

TIBCO BusinessEvents FM Logic — MNP Credit Limit Calculation (Account-level)
Backend: CES / OMX Credit Limit Service Pattern: Account-level fan-out + IntraActivitySequencing Author: mbausaka-t430 Generated: 2026-09-23
§1 — Overview & Purpose

Calculates the MNP (Mobile Number Portability) credit limit for each account in the order. Factors in any International Roaming (IR) SOC (41601 or 41606) by adding CalcIR=15000 to the limit request. Sends one request per account using IntraActivitySequencing.


Two backend paths:

  • GoldenDB=Y → CES_CALCULATE_MNP_CREDIT_LIMIT event (CES service)
  • GoldenDB≠Y → CALCULATE_MNP_CREDIT_LIMIT event (standard OMX service)

The response handler writes back PersonalCreditLimit (rounded to nearest 100) and CreditLimitWaiverInd ("U" for VIP/HY accounts, "N" otherwise) to Account.AccountManagementInfo.


PreExecCheck in ProcessConfig gates this FM on CustomerTypeInfo/Type != 73 (non-corporate) and OrderType=7 (MNP).

§5 — Execution Flow
  1. Detect resubmit: isActResub = (RequestCount > 0 && IsOrderResubmitted)
  2. If resubmit: call IAS.PurgePendingRequestsBeforeResubmit(orderCurrentActivity)
  3. For each Account[i]:
    • Evaluate per-account PreExecCheck via GetXMLForAccount(orderRequest, refId)
    • If chkRes="true":
      • Compute SubCount via XPath (count SubscriberOffers by AccountRefId in ParentOU/ChildOU)
      • Compute CheckIR: true if any SOC = 41601 or 41606; set CalcIR=15000 if true
      • If GoldenDB=Y: create and assert CES_CALCULATE_MNP_CREDIT_LIMIT event, call IAS.ActionRequestEvent
      • Else: create and assert CALCULATE_MNP_CREDIT_LIMIT event, call IAS.ActionRequestEvent
  4. If at least one request sent: call IAS.SendFirstRequestEvent, set status to "1", SendDataToDB
  5. If isSkipped: call SkipActivity(orderRequest, orderCurrentActivity, "4")
§7 — Data Extraction & XPath Computations

SubCount (subscriber offer count per account)

if(count($orderRequest/OrderData/Customer/ParentOU/Subscriber[AccountRefId=$refId]/SubscriberOffers)>0)
then count($orderRequest/OrderData/Customer/ParentOU/Subscriber[AccountRefId=$refId]/SubscriberOffers)
else count($orderRequest/OrderData/Customer/ParentOU/ChildOU/Subscriber[AccountRefId=$refId]/SubscriberOffers)

CheckIR (IR SOC detection)

if(
  ($orderRequest/OrderData/Customer/ParentOU/Subscriber[AccountRefId=$refId]/SubscriberOffers/Soc='41601')
  or ($orderRequest/.../SubscriberOffers/RelatedOffersArray/Soc='41606')
  or ChildOU equivalents
) then true() else false()

→ If CheckIR=true: CalcIR = 15000 (added to credit limit request)


CreditLimitWaiverInd (in response handler)

"U" if (no RawAccountID AND (Type=70 OR SubType starts "HY" OR Grading != 'NON-TOP'))
else "N"

PersonalCreditLimit (in response handler)

0.00 if (no RawAccountID AND (Type=70 OR SubType starts "HY")) OR Grading != 'NON-TOP'
else if (has RawAccountID AND Grading='NON-TOP') then ceiling(CalCreditLimit/100)*100
else ceiling(CalCreditLimit/100)*100

Result is rounded up to nearest 100.

§9.6 — Core Payload — CalculateMNPCreditLimitRequest

Namespace: http://services.omx.truecorp.co.th/FM/CalculateMNPCreditLimitRequest (prefix ns1)

<ns1:CalculateMNPCreditLimitRequest>
  <ns1:MNPCreditLimitAcc>
    <ns1:customerType>$orderRequest/OrderData/Customer/CustomerTypeInfo/Type</ns1:customerType>
    <ns1:grading>$orderRequest/OrderData/Customer/CustomerGeneralInfo/Grading</ns1:grading>
    /* Conditional: if AccountID non-empty */
    <ns1:accountId>$orderRequest/OrderData/Customer/Account[$var]/AccountID</ns1:accountId>
    <ns1:accountSubType>$orderRequest/OrderData/Customer/Account[$var]/AccountManagementInfo/AccountSubType</ns1:accountSubType>
    /* for-each: ServiceType=80 SubscriberOffers for subscribers in this account (both ParentOU and ChildOU) */
    <ns1:soc>Soc (from SubscriberOffers[ServiceType='80'])</ns1:soc>
    <ns1:CalCreditLimit>0</ns1:CalCreditLimit>
    <ns1:CalcIR>15000 (if IR SOC present) or 0</ns1:CalcIR>
  </ns1:MNPCreditLimitAcc>
</ns1:CalculateMNPCreditLimitRequest>

Note: $var = number($i) + 1 (XPath is 1-based, Java loop is 0-based)

§19 — Response Message Rule

§19.1 — Overview

Parses CalculateMNPCreditLimitResponse and writes CreditLimitWaiverInd and PersonalCreditLimit back to the matching account. Fan-in is managed by IntraActivitySequencing.ActionResponseEvent rather than manual count comparison.
