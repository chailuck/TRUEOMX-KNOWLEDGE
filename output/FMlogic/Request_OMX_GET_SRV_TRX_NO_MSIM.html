Also writes the total count to AA_CHECK_CONFIRMATION.RequestCount for downstream fan-in.
Backend: OMX FM (OMX_GET_SRV_TRX_NO) Pattern: Single-shot JMS (count=N, array response) forwardChain: true Author: mranade-T420 Used in steps: 40, 42 Generated: 2026-08-06
§1 Overview & Purpose

Fetches service transaction sequence numbers (SrvTrxNo) for MultiSIM activation. The rule counts all qualifying MASTER and MINOR SIM entries across all POU subscribers, sends a single OMX_GET_SRV_TRX_NO request with amount=countSrvTrxNo, and receives an array of sequence numbers back. The response handler then distributes one sequence number per SIM into each SIM's SrvTrxNoInfo[] concept array.

  • Subscribers without MultiSIMInfo are silently skipped (no error)
  • PreExecCheck uses GetXMLForSubscriberFilterWithMultiSIMInfo — a MSIM-specific helper that passes role ("MASTER"/"MINOR"), Source filter, and IMSI
  • If countSrvTrxNo == 0 → SkipActivity("4"); no JMS event sent
  • Resubmit guard: isActResub prevents double-counting of RequestCount
  • AA_CHECK_CONFIRMATION write-back: response sets RequestCount = countSrvTrxNo on the matching downstream activity (matched by Parameter[0])
Single backend call: Unlike per-SIM fan-out, this FM sends one call with ns:amount=N and the OMX sequence service returns N values as ns:sequenceValue[1..N]. The response handler indexes into this array using countSrvTrxNo as a running pointer.

§4 SIM Counting Logic (Request Rule THEN)

The request rule traverses all POU → Subscribers and counts qualifying SIM slots:

SIM slotCondition to qualifyPreExecCheck XML builderFilter param
MASTERsub.MultiSIMInfo != null (null → continue/skip sub)GetXMLForSubscriberFilterWithMultiSIMInfo(orderRequest, refId, "MASTER", Master.Source, "")Master.Source (e.g., "FE" / "PREV_MSIM")
MINOR[k]Inner loop after MASTER check; no null guard on MultiSIMInfo (relies on outer skip)GetXMLForSubscriberFilterWithMultiSIMInfo(orderRequest, refId, "MINOR", Minor[k].Source, Minor[k].IMSI)Minor[k].Source + Minor[k].IMSI
One count per SIM slot: Each MASTER that passes PreExecCheck → +1; each MINOR[k] that passes → +1. The total is the amount sent to the backend — one sequence number will be returned per qualifying slot.
COU Subscribers: The request rule only traverses ParentOU[i].Subscriber[j] — there is NO COU (ChildOU) traversal in this FM. Only POU subscribers are processed.

§6 Response Handler — SrvTrxNo Distribution

The response rulefunction traverses the same POU → Subscriber structure. It uses countSrvTrxNo (starts at 0, increments per qualifying SIM) as an index into the backend's ns:sequenceValue[] array:

For each qualifying MASTER SIM:

  1. Re-runs PreExecCheck via GetXMLForSubscriberFilterWithMultiSIMInfo(…, "MASTER", filter, "")
  2. Creates OMX_GetSrvTrxNoRes:
    • extId = concat("OMX_GET_SRV_TRX_NO:", eventResponse/ns:sequenceValue[countSrvTrxNo+1])
    • ResponseCode, ResponseMessage, CompletionStatus ← eventResponse (conditional)
    • srvTrxNo ← eventResponse/payload/ns:GetSrvTrxNoResponse/ns:sequenceValue[countSrvTrxNo+1]
    • OMXTrackingId ← JMSCorrelationID (conditional)
    • srv_trx_tp_cd ← param1
  3. Appends seqResBySeq to currActivity.Response[]
  4. Creates SrvTrxNoMSIMInfo:
    • extId = OMXUtils.generateTrackingID()
    • SrvTrxNo ← srvTrxNo
    • SrvTrxTp ← srv_trx_tp_cd (=param1)
    • SrvStatus ← master.Source ("FE"/"PREV_MSIM")
  5. Appends SrvTrxNoMSIMInfo to master.SrvTrxNoInfo[]
  6. countSrvTrxNo++

For each qualifying MINOR[k] SIM:

  1. Re-runs PreExecCheck via GetXMLForSubscriberFilterWithMultiSIMInfo(…, "MINOR", minor.Source, minor.IMSI)
  2. Creates another OMX_GetSrvTrxNoRes (same logic, same countSrvTrxNo index)
  3. Appends to currActivity.Response[]
  4. Creates SrvTrxNoMSIMInfo with SrvStatus ← minor.Source
  5. Appends to minor.SrvTrxNoInfo[]
  6. countSrvTrxNo++
Index alignment dependency: The request rule and response handler must traverse SIMs in the same order and apply the same PreExecCheck to produce the same countSrvTrxNo sequence — otherwise the sequence number distribution will be misaligned. Any state change between request and response that alters qualifier results would corrupt the mapping.
§7 AA_CHECK_CONFIRMATION Write-Back

After all SIM processing, the response handler scans all Process Flow activities looking for an AA_CHECK_CONFIRMATION step whose Parameter[0] matches currActivity.Parameter[0] (i.e., param1, e.g., "NAC" or "DSD"):

for(int i=0; i<iActLen; i++) { if(String.equals(activities[i].ActivityID, "AA_CHECK_CONFIRMATION") && String.equals(activities[i].Parameter[0], currActivity.Parameter[0])) { activities[i].RequestCount = countSrvTrxNo; } }
Purpose: Sets AA_CHECK_CONFIRMATION.RequestCount to the actual number of SIMs processed. AA_CHECK_CONFIRMATION uses this value as its fan-in threshold — it waits for this many activation confirmations before advancing the process.

§10 Migration Notes & Recommendations

Functional Requirements

RefRequirement
R1Only POU subscribers are traversed — no COU traversal in this FM.
R2Subscribers without MultiSIMInfo are skipped (both request and response).
R3Single OMX call with sequenceName="AA_TRX_NO_SEQ" and amount=N — one call regardless of SIM count.
R4Response must distribute sequenceValue[k+1] per SIM in traversal order — index alignment between request count and response distribution is critical.
R5SrvTrxTp comes from param1 (activity parameter); SrvStatus comes from Master.Source / Minor.Source.
R6After response: update AA_CHECK_CONFIRMATION.RequestCount = countSrvTrxNo for the matching activity (matched by Parameter[0] == param1).
R7Resubmit: isActResub = RequestCount > 0 && IsOrderResubmitted → suppress RequestCount increment; no PurgePendingRequestsBeforeResubmit.
