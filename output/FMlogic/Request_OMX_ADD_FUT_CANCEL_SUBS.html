Request_OMX_ADD_FUT_CANCEL_SUBS

TIBCO BusinessEvents FM — OMX Add Future Cancel Subscriber (full-to-cancel scheduled cancellation)
Rule: Rules.OMConsumers.OMXFM.Request.Request_OMX_ADD_FUT_CANCEL_SUBS Priority: 5 forwardChain: true Author: DESKTOP-HINKNF3 Backend: OMX (FutureOrder) Generated: 2026-09-16
§1 — Overview & Purpose

Fires when ActivityID == "OMX_ADD_FUT_CANCEL_SUBS" and status is WAITING. This FM is the "Full Suspend → Future Cancel" bridge: when the activity reason is FCVG, it schedules a future order in OMX to automatically cancel the subscriber FullToCancelDay days after today. It resolves the primary subscriber from ParentOU[0]/Subscriber[0] (or ChildOU fallback), then fires a single OMX_ADD_FUTURE event with a futureOrderWithSoc payload (type CANSUB, level 5 = Subscriber). The response rulefunction always returns "true" unconditionally (no fan-in count).

Trigger condition (FCVG): This activity is gated by ActivityReason="FCVG" in the ProcessConfig PreExecCheck. Only full-suspension orders with convergence-driven cancellation scheduling reach this step.

§5 — Execution Flow
  1. Load LogicalDate; set requestedDate = DateTime.now(); requestBy = Channel
  2. Apply PreExecCheck on full OrderData XML (activity-level gate, e.g., ActivityReason="FCVG")
  3. If check fails → SkipActivity("4")
  4. Resolve subExtId via XPath tib:if-absent (POU[1]/Sub[1] or COU[1]/Sub[1])
  5. If subExtId null → throw DATA_ISSUE exception
  6. Read GVs: FullToCancelDay → plusDay; FullToCancelOrderType → orderType; FullToCancelReason → reasonCode
  7. Compute effectiveDate = DateTime.addDay(now(), plusDay)
  8. Fire OMX_ADD_FUTURE event with futureOrderWithSoc payload
  9. Increment RequestCount (if not resubmit); set status "1"; persist DB
  10. Catch block → HandleActivityException
