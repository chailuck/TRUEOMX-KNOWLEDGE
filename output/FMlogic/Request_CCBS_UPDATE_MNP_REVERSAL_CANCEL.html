§1 — Overview & Purpose

Updates CCBS L9 MNP attributes for a port-in reversal or MNP rejection scenario (ActivityReason=MNPHR or RFREOT). Unlike the standard CCBS_L9_UPDATE_MNP_ATTRIBUTES FM, this variant reads MNP fields from the subscriber's ExtendedInfo (DONOR_OPERATOR, DONOR_ZONE, REC_OPERATOR, REC_ZONE) rather than from the order-level MNPInfo, and hardcodes L9PortInd=86.

Used in CANCEL_SUBSCRIBER process — Step 59 — gated on ActivityReason=MNPHR or RFREOT and not ATS.

Note: The request event type reuses CCBS_L9_UPDATE_MNP_ATTRIBUTES schema/event — only data sources differ.

§17 — Migration Notes

R1: L9PortInd=86 is the MNP reversal/cancel indicator — critical to preserve; confusing with L9PortInd=79 (normal cancel) is a common error.

R2: MNP attributes sourced from subscriber ExtendedInfo (not order MNPInfo) — these fields must be populated by earlier steps (INTX_GET_SIM_INFO).

R3: The rule event type reuses CCBS_L9_UPDATE_MNP_ATTRIBUTES event — both rules share the same JMS schema; routing is distinguished by ActivityID.

Risk: HIGH — Incorrect L9PortInd can leave MNP records in inconsistent state in CCBS.
