Request_INTX_GET_ACCOUNT_CUSTOMER_PREFERENCE_LIST

TIBCO BusinessEvents FM Logic — INTX Account Customer Preference List
Target: INTX Fan-out: Classic Parallel Loop: POU Subscriber + COU Subscriber Author: RNAPP-PC Generated: 2026-08-04
§1 — Overview & Purpose

This FM retrieves the account customer preference list from the INTX system for each subscriber in the order. It queries INTX to obtain the collection indicator (COLLECTION_IND), which indicates whether an account is flagged for debt collection, and stores the result as a SubscriberExtendedInfo entry on each subscriber concept.


This FM uses a classic parallel fan-out pattern — one JMS request event is fired per subscriber immediately via Event.Ext.sendEventImmediate(), incrementing RequestCount for each. The response handler matches by RefID and applies collection indicator logic independently for POU vs COU subscribers.

Key distinction from CCBS FMs: This FM does NOT use IntraActivitySequencing (no SendFirstRequestEvent, no ActionRequestEvent, no PurgePendingRequestsBeforeResubmit). It does NOT have ALT_CES routing. Target system is INTX, not CCBS. The subscriber concept object ($psub/$csub) is passed directly as an XSLT parameter — a unique pattern not seen in CCBS FMs.

  • orderCurrentActivity.RequestCount++

  • Set cSubRefId = csub.RefId, cOuRefId = ChildOU[c].RefId
  • PreExecCheck: GetXMLForSubscriberInChildOU(orderRequest, cSubRefId, pOuRefId)
  • If PreExecCheck fails → continue (skip this subscriber)

§6 — Rule Action (THEN) — Step-by-Step Logic
// ─── Outer loop: ParentOU ────────────────────────────────────────────
int pOuLen = orderRequest.OrderData.Customer.ParentOU@length;
for (int p = 0; p < pOuLen; p++) {

    // ─── POU Subscriber loop ────────────────────────────────────────
    int pSubLen = orderRequest.OrderData.Customer.ParentOU[p].Subscriber@length;
    for (int ps = 0; ps < pSubLen; ps++) {
        Concepts.OrderRequest.OrderElements.Subscriber psub =
            orderRequest.OrderData.Customer.ParentOU[p].Subscriber[ps];
        String pSubRefId = psub.RefId;
        String pOuRefId  = orderRequest.OrderData.Customer.ParentOU[p].RefId;

        // PreExecCheck gate
        String preExecXML = RuleFunctions.OMConsumers.OMXFM.GetXMLForSubscriber(
                                orderRequest, pSubRefId);
        if (String.equals(preExecXML, "")) { continue; }

        // Build and fire request event (XSLT Variant ①: POU)
        Event reqEvent = Event.createEvent(
            "xslt://{{/Events/OMConsumers/OMXFM/Request/INTX_GET_ACCOUNT_CUSTOMER_PREFERENCE_LIST}}"
            /* params: $orderRequest, $pSubRefId, $globalVariables, $psub */
            /* → see §9.8 for full XSLT; emits ns12:GetAccountCustomerPreferenceListReq */
        );
        Event.Ext.sendEventImmediate(reqEvent);
        orderCurrentActivity.RequestCount++;
    }

    // ─── ChildOU loop ───────────────────────────────────────────────
    int cOuLen = orderRequest.OrderData.Customer.ParentOU[p].ChildOU@length;
    for (int c = 0; c < cOuLen; c++) {

        // ─── COU Subscriber loop ────────────────────────────────────
        int cSubLen = orderRequest.OrderData.Customer.ParentOU[p].ChildOU[c].Subscriber@length;
        for (int cs = 0; cs < cSubLen; cs++) {
            Concepts.OrderRequest.OrderElements.Subscriber csub =
                orderRequest.OrderData.Customer.ParentOU[p].ChildOU[c].Subscriber[cs];
            String cSubRefId  = csub.RefId;
            String cOuRefId   = orderRequest.OrderData.Customer.ParentOU[p].ChildOU[c].RefId;

            // PreExecCheck gate (includes parent OU ref)
            String preExecXML = RuleFunctions.OMConsumers.OMXFM.GetXMLForSubscriberInChildOU(
                                    orderRequest, cSubRefId, pOuRefId);
            if (String.equals(preExecXML, "")) { continue; }

            // Build and fire request event (XSLT Variant ②: COU)
            Event reqEvent = Event.createEvent(
                "xslt://{{/Events/OMConsumers/OMXFM/Request/INTX_GET_ACCOUNT_CUSTOMER_PREFERENCE_LIST}}"
                /* params: $orderRequest, $cSubRefId, $globalVariables, $csub */
                /* → see §9.8 for full XSLT; emits ns12:GetAccountCustomerPreferenceListReq */
            );
            Event.Ext.sendEventImmediate(reqEvent);
            orderCurrentActivity.RequestCount++;
        }
    }
}

§13 — Exception / Error Handling

Exception handling follows the standard OMXFM pattern via the response rulefunction's fan-in check. If a response arrives with ResponseCode not ending in "000", it is counted as a failure — the fan-in condition RequestCount == successResponseCount will not be satisfied until all pending responses resolve.

No explicit try/catch or HandleActivityException calls observed in the request rule itself.

/**
 * @description Request rule for INTX_GET_ACCOUNT_CUSTOMER_PREFERENCE_LIST
 * Author: RNAPP-PC
 * Pattern: Classic parallel fan-out (sendEventImmediate + RequestCount++)
 * Target: INTX
 * Scope: All POU Subscribers + All COU Subscribers
 */
rule Rules.OMConsumers.OMXFM.Request.Request_INTX_GET_ACCOUNT_CUSTOMER_PREFERENCE_LIST {
    attribute {
        priority = 5;
        forwardChain = false;
    }
    declare {
        Concepts.OrderRequest.OrderRequest orderRequest;
        Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
        Concepts.GlobalVariables globalVariables;
    }
    when {
        /* standard working memory match — all three concepts present */
    }
    then {
        int pOuLen = orderRequest.OrderData.Customer.ParentOU@length;
        for (int p = 0; p < pOuLen; p++) {

            /* ─── POU Subscriber loop ─────────────────────────────────────── */
            int pSubLen = orderRequest.OrderData.Customer.ParentOU[p].Subscriber@length;
            for (int ps = 0; ps < pSubLen; ps++) {
                Concepts.OrderRequest.OrderElements.Subscriber psub =
                    orderRequest.OrderData.Customer.ParentOU[p].Subscriber[ps];
                String pSubRefId = psub.RefId;
                String pOuRefId  = orderRequest.OrderData.Customer.ParentOU[p].RefId;

                String preExecXML = RuleFunctions.OMConsumers.OMXFM.GetXMLForSubscriber(
                                        orderRequest, pSubRefId);
                if (String.equals(preExecXML, "")) { continue; }

                Event reqEvent = Event.createEvent(
                    /* XSLT Variant ①: POU — params: $orderRequest, $pSubRefId, $globalVariables, $psub, $pid
                       → emits ns12:GetAccountCustomerPreferenceListReq (see §9.8 for full XSLT)
                       Fields: correlatedId(cond), pageNumber=1(static),
                               searchList[PRIMRESOURCEVAL=$psub/MSISDN(cond), BUSINESSLINE=MOBILE(static), SUBSTATUS=ACTIVEORSUSPEND(static)] */
                );
                Event.Ext.sendEventImmediate(reqEvent);
                orderCurrentActivity.RequestCount++;
            }

            /* ─── COU loop ────────────────────────────────────────────────── */
            int cOuLen = orderRequest.OrderData.Customer.ParentOU[p].ChildOU@length;
            for (int c = 0; c < cOuLen; c++) {
                int cSubLen = orderRequest.OrderData.Customer.ParentOU[p].ChildOU[c].Subscriber@length;
                for (int cs = 0; cs < cSubLen; cs++) {
                    Concepts.OrderRequest.OrderElements.Subscriber csub =
                        orderRequest.OrderData.Customer.ParentOU[p].ChildOU[c].Subscriber[cs];
                    String cSubRefId  = csub.RefId;

                    String preExecXML = RuleFunctions.OMConsumers.OMXFM.GetXMLForSubscriberInChildOU(
                                            orderRequest, cSubRefId, pOuRefId);
                    if (String.equals(preExecXML, "")) { continue; }

                    Event reqEvent = Event.createEvent(
                        /* XSLT Variant ②: COU — same as ① but $cSubRefId/$csub (see §9.8) */
                    );
                    Event.Ext.sendEventImmediate(reqEvent);
                    orderCurrentActivity.RequestCount++;
                }
            }
        }

        String status = RuleFunctions.OM.GetActivityStatusString("1", false);
        RuleFunctions.OM.SendDataToDB(orderRequest, orderCurrentActivity, globalVariables);
    }
}
§19 — Response Message Rule
§19.1 — Overview

The response rulefunction Response_INTX_GET_ACCOUNT_CUSTOMER_PREFERENCE_LIST handles each individual subscriber response from INTX. It: (1) builds a ResponseBase concept and appends it to the activity's response array; (2) locates the matching subscriber by RefId across POU and COU subscriber arrays; (3) creates a SubscriberExtendedInfo concept with Name="COLLECTION_IND" and a computed value, appending it to the matched subscriber's ExtendedInfo array; (4) fires an audit log event; (5) evaluates the fan-in completion condition.

Critical: POU vs COU collection indicator logic differs. POU applies a strict business rule (Y only if indicator=Y AND startDate present). COU does a raw pass-through (copies actual value, or N if absent). This asymmetry must be preserved exactly in any migration.

POU Variant — Binary Y/N logic: 
if (collectionIndicator = "Y"
    AND string-length(startDate) > 0) {
    Value = "Y"
} else {
    Value = "N"
}

Source: $eventResponse/payload/ns:GetAccountCustomerPreferenceListRes/ns:getAccountCustomerPreferenceListResponse/ns:return/ns:accountCustomerPreferenceList/ns:accountCustomerPreferenceInfoArray[ns:system="CCBS"]/ns:account/ns:accountCollection/ns:collectionIndicator

COU Variant — Raw pass-through logic: 
if (string-length(collectionIndicator) > 0) {
    Value = collectionIndicator  // raw value

Same XPath source. Key difference: COU copies the raw indicator value (could be "Y", "N", or any value returned by INTX), while POU enforces a strict Y+startDate gate.
