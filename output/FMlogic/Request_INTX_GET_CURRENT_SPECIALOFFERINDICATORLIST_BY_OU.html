Request_INTX_GET_CURRENT_SPECIALOFFERINDICATORLIST_BY_OU

Retrieves special offer indicator lists from INTX per OU, with paged requests and data enrichment
System: INTX Priority: 5 Author: usuf c Pattern: Paged dual-loop POU/COU + direct send Fan-in: count(success) == RequestCount JMSCorrelationID: OMXTrackingId Generated: 2026-09-15
§1 Overview & Purpose

This FM retrieves the current special offer indicator list from INTX (GetSpecialOfferIndListByOU) for each OU. It implements a two-pass paged design:

  • Pass 1 (PAGE_SIZE=1): Queries total number of offers. Response writes OFFERS_BY_INDICATION_TOTAL_SIZE into pou.ExtendedInfo.
  • Pass 2 (PAGE_SIZE=actual): Retrieves actual offer data page-by-page. Response enriches Subscriber.SubscriberOffers with SPECIAL_OFFER_INDICATOR and FE_OR_CCBS metadata.

The specialOfferIndicatorParam (Parameter[2]) defaults to "FCA" if blank.

§5 Execution Flow Diagram
1
Init — Get nextAct by extId. If resubmit, PurgePendingRequestsBeforeResubmit. Get specialOfferIndicatorParam from Parameter[2]; default "FCA" if blank. isSkipped=true.
2
Outer POU Loop — PreExecCheck gate (GetXMLForOU). If pass: compute paging: total from parentOU/ExtendedInfo[OFFERS_BY_INDICATION_TOTAL_SIZE] (default 1), size from PAGE_SIZE (default 1), iteration=ceil(total/size).
3
POU Page Loop for pageNumber=0..iteration-1 — CompletionStatus==2 check (uses COUrefId which is empty for POU ⚠). If not complete: build and sendEventImmediate. If !resubmit: RequestCount++, isSkipped=false, send audit (also Ext.sendEventImmediate).
4
Inner COU Loop — Same paging logic with GetXMLForChildOU + COUrefId CompletionStatus==2 check.
5
Post-loop — If !isSkipped → Status="1" + SendDataToDB. Else → SkipActivity("4").
6
Exception → HandleActivityException.
⚠ Bug Note (POU CompletionStatus check): In the POU page loop (line 66 of rule), the resubmit skip check uses COUrefId (ChildOU RefId), which has NOT been set yet at that point in the POU loop — its value is "" or the last COU from a previous POU iteration. For POU, the effective ReferenceId in responses is POUrefId (set from parentOU.RefId). This means the POU CompletionStatus skip never triggers correctly on resubmit. Document and verify with INTX team.

/**
 * @description
 * @author usuf c
 */
rule Rules.OMConsumers.OMXFM.Request.Request_INTX_GET_CURRENT_SPECIALOFFERINDICATORLIST_BY_OU {
    attribute { priority = 5; forwardChain = true; }
    declare {
        Concepts.OrderRequest.OrderRequest orderRequest;
        Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
    }
    when { ... ActivityID == "INTX_GET_CURRENT_SPECIALOFFERINDICATORLIST_BY_OU" ... }
    then {
        boolean isActResub = (orderCurrentActivity.RequestCount>0 && orderRequest.IsOrderResubmitted);
        try {
            Activity nextAct = Instance.getByExtIdByUri(orderRequest.ProcessFlow.NextActivityName, ...);
            if(isActResub) PurgePendingRequestsBeforeResubmit(...);

            // Parameter[2] = specialOfferIndicatorParam; default "FCA"
            String specialOfferIndicatorParam = XPath.evalAsString("orderCurrentActivity/Parameter[2]");
            if(BRMS.IsBlankOrStringNull(specialOfferIndicatorParam)) specialOfferIndicatorParam = "FCA";

            // POU loop
            for(int i=0; i<iPOULen; i++) {
                ParentOU parentOU = orderRequest.OrderData.Customer.ParentOU[i];
                // PreExecCheck gate
                if(chkRes == "true") {
                    // Paging: total from OFFERS_BY_INDICATION_TOTAL_SIZE or 1
                    String pageSize = GetActivityParamValueFromKey(nextAct, "PAGE_SIZE"); // default "1"
                    double total = XPath.evalAsDouble("parentOU/ExtendedInfo[OFFERS_BY_INDICATION_TOTAL_SIZE]"); // else 1
                    int iteration = Math.ceil(total / size);
                    for(int pageNumber=0; pageNumber<iteration; pageNumber++) {
                        // CompletionStatus==2 check using COUrefId ⚠ (bug: should use POUrefId)
                        if(!reqSuccess) {
                            reqEvent = Event.createEvent("xslt://...");
                            /* See §9.8: params orderRequest, parentOU, globalVariables,
                               specialOfferIndicatorParam, pageSize, pageNumber */
                            Event.Ext.sendEventImmediate(reqEvent);
                            if(!isActResub) { orderCurrentActivity.RequestCount++; isSkipped=false; }
                            Event.Ext.sendEventImmediate(Event.createEvent("xslt://Logger..."));
                        }
                    }
                }
                // COU loop — same paging, uses COUrefId for CompletionStatus check
            }
            if(!isSkipped) { Status="1"; SendDataToDB(); }
            else SkipActivity("4");
        } catch(Exception ae) { HandleActivityException(...); }
    }
}
§19 Response Message Rule

§19.1 Overview

The response handler has two distinct modes based on pageSize:

  • Pass 1 (pageSize=="1"): Writes OFFERS_BY_INDICATION_TOTAL_SIZE = totalSize into pou.ExtendedInfo (and COU's parent pou.ExtendedInfo). No offer data stored.
  • Pass 2 (pageSize>1): Enriches Subscriber.SubscriberOffers from response offer list. For each offer: if SOC already exists → adds/updates SPECIAL_OFFER_INDICATOR ExtendedInfo; if new SOC → creates new SubscriberOffers concept with FE_OR_CCBS="CCBS" + SPECIAL_OFFER_INDICATOR.
