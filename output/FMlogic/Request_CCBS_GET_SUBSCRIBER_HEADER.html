§1Overview & Purpose

CCBS_GET_SUBSCRIBER_HEADER retrieves the full subscriber header record from CCBS (AMDOCS L9 billing system) and enriches the OMX order graph with name, address, status and account data.


It is unique among OMXFM rules in that it uses the IntraActivitySequencing pattern — a throttled fan-out mechanism — rather than the standard parallel fan-out. This ensures that multiple subscriber requests within one order are sent one-at-a-time, preventing CCBS session contention.


The response handler is among the most complex in the system: it populates up to six subscriber sub-concepts (SubscriberName, SubscriberName2, SubscriberAddress, SubscriberAddress2, SubscriberGeneralInfo, ExtendedInfo) using LinkType / NameType routing across up to 15 AddressElement slots, with full ClearField erasure support.

ALT_CES Routing: An ALT_CES activity parameter enables alternate CES endpoint routing — when present and value != "", the CES host is overridden from the subscriber's ExtendedInfo rather than the order's default CES field.

§5Execution Flow Diagram
  1. Resubmit check: If this is a retry, call PurgePendingRequestsBeforeResubmit(orderCurrentActivity) to clear previously queued but not yet sent requests.
  2. ALT_CES resolution: Read ALT_CES from activity parameters. If value = "Y" and ExtendedInfo[ALT_CES]/Value != "" → override CES from ExtendedInfo; otherwise use OrderData/CES.
  3. Credential gate: Read global IsEnableUserPass. If "true", add UserName (OrderData/User) and PassWord (OrderData/Password) headers to the JMS request event.
  4. Payload build: Construct GetSubscriberHeaderRequest with SubscriberIdInfo/subscrNumber = SubscriberId (from the matched subscriber).
  5. IntraActivitySequencing throttle: Call ActionRequestEvent(reqEvent, orderCurrentActivity). The sequencing engine holds requests in a queue and releases them one at a time; if the slot is busy, this call parks the event without firing — throttling the fan-out.
  6. Completion path: Call SendFirstRequestEvent(orderCurrentActivity) + GetActivityStatusString("1", false) + SendDataToDB to persist the status.
  7. Skip path: Call SkipActivity("4") if PreExecCheck condition fails at the order level.
§6Rule Action (THEN) — Detailed Logic

6.1 IntraActivitySequencing Fan-Out

Unlike standard parallel fan-out, CCBS_GET_SUBSCRIBER_HEADER uses a throttled pattern:

CallWhenPurpose
PurgePendingRequestsBeforeResubmit(orderCurrentActivity)On resubmitCancels queued-but-unsent requests before rebuilding the queue
ActionRequestEvent(reqEvent, orderCurrentActivity)Each subscriber requestAdds request to sequencing queue; throttles so only one is in-flight at a time
SendFirstRequestEvent(orderCurrentActivity)After queuing all requestsTriggers the first release from the queue; sequencing engine dispatches next on response arrival

/**
 * Request_CCBS_GET_SUBSCRIBER_HEADER
 * Author: warawich-nb

rule Rules.OMConsumers.OMXFM.Request.Request_CCBS_GET_SUBSCRIBER_HEADER {
  attribute { validity = ACTION; }
  scope {
    Concepts.OrderRequest.OrderRequest orderRequest;
    Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
  }
  when { /* standard OMXFM activation condition */ }
  then {
    // On resubmit: purge previously queued-but-unsent requests
    IntraActivitySequencing.PurgePendingRequestsBeforeResubmit(orderCurrentActivity);

    // Resolve CES endpoint (ALT_CES routing)
    String altParam = GetActivityParameterValueFromKey(orderCurrentActivity, "ALT_CES");
    // ALT_CES XSLT logic embedded in event builder:
    // when altParam="Y" AND ExtendedInfo[ALT_CES]/Value != "" → CES = ExtendedInfo[ALT_CES]/Value
    // otherwise → CES = OrderData/CES

    // Build JMS request event (POU variant — ns1 prefix):
    // [§9.8: GetSubscriberHeaderRequest/SubscriberIdInfo/subscrNumber = SubscriberId]
    // Credential headers added when IsEnableUserPass='true'
    Event reqEvent = Event.createEvent("xslt://{{/Events/OMConsumers/OMXFM/Request/CCBS_GET_SUBSCRIBER_HEADER}}"
      /* XSLT output: GetSubscriberHeaderRequest + credential headers — see §9 */);

    // Throttle via IntraActivitySequencing (serialise CCBS calls)
    IntraActivitySequencing.ActionRequestEvent(reqEvent, orderCurrentActivity);
    // COU variant: same payload with ns prefix (not ns1)

    // Completion path:
    IntraActivitySequencing.SendFirstRequestEvent(orderCurrentActivity);
    String status = GetActivityStatusString("1", false);
    SendDataToDB();

    // Skip path (PreExecCheck failed):
    // SkipActivity("4");
  }
}
§19Response Message Rule

19.1 Overview

The response rulefunction (Response_CCBS_GET_SUBSCRIBER_HEADER.rulefunction, 551 lines) is the data-enrichment heart of this FM. It:

  1. Creates a custom CCBS_GetSubscriberHeaderRes concept (not standard ResponseBase)
  2. Enriches POU subscriber: dealerCode, MSISDN backfill, AccountID (param-gated)
  3. Enriches all subscribers: ConvergenceCode, CONVERGENT_CODE, subStatus (ASCII decode), Language (param-gated)
  4. Maps full Name/Address from NameAddressInfoList using LinkType/NameType routing
  5. Applies ClearField erasure pattern across all mapped fields
  6. Delegates SubscriberName2 to CCBS_GET_SUBSCRIBER_HEADER_EXTEND
  7. Delegates OrderType=129 address mapping to MapSubscriberAddress/Address2FromGetSubscriberHeader
  8. Emits audit log event, then releases next queued request via ActionResponseEvent

19.5 ClearField Erasure Pattern

For every mapped field: if the current value (uppercased) equals the global ClearField sentinel → set the field to null. This allows downstream systems to explicitly request a field be erased by passing the ClearField token. The pattern is applied universally to all 40+ name/address fields.
