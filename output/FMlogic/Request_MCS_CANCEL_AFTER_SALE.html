Request_MCS_CANCEL_AFTER_SALE

Backend: MCS Operation: CancelAftersale Priority: 5 ForwardChain: true Pattern: sendEventImmediate (parallel) Generated: 2026-08-14
§1 — Overview & Purpose

Request_MCS_CANCEL_AFTER_SALE cancels an after-sale (AFS) contract with the MCS subscription management system. It is invoked after MCS_GET_PACKCODE confirms that a subscriber holds an active after-sale subscription (MCS_CANCEL_AFS=Y flag).

This FM is notably more complex than typical MCS FMs: it accepts ten XSLT parameters, applies multi-branch logic for MSISDN selection (old-MSISDN swap), offer name selection (Priceplan vs. contract offer), offer activity date selection (three-way), and subscriber ID mapping (three-way). Activity-level parameters (OFFER_NAME, MAP_OLD_SUB, MAP_PP_EXPIRE, USE_ROWID_CRM, oldMsisdnFlag) allow the same FM to be reused across different cancellation scenarios.

[MEDIUM] ParamName="TR_ORIG_CONTRACT_EXPIRE_DATE " — the trailing space in this XPath predicate may prevent the offer_expire_date field from ever being sent even when MAP_PP_EXPIRE=Y. Verify against actual stored parameter names in CCBS data.
[MEDIUM] ns:account_id is always emitted with an empty string value (<xsl:value-of select="''"/>) — this is a placeholder field never wired to actual data.

§9.6 — Core Payload / Multi-Branch Logic

ns:msisdn — Old-MSISDN swap (XPath if-then-else, always emitted):

if ($oldMsisdnFlag = 'Y') then
    $orderRequest/OrderData/Customer/ParentOU[ExtendedInfo[Name="SOURCE_OR_TARGET" and Value="TARGET"]]/Subscriber/MSISDN
else
    $subscriber/MSISDN

When oldMsisdnFlag=Y, the request targets the TARGET-flagged ParentOU's subscriber MSISDN rather than the current subscriber's MSISDN. This supports number-change scenarios.

ns:old_subscriber_id — Three-way xsl:choose on $mapOldSub:

$mapOldSub valueSource XPathCondition
SOURCE_SUBParentOU/Subscriber[$msisdn=MSISDN and ExtendedInfo[SOURCE_OR_TARGET=SOURCE]]/SubscriberIdConditional (xsl:if inside when)
TARGET_SUBParentOU/Subscriber[$msisdn=MSISDN and ExtendedInfo[SOURCE_OR_TARGET=TARGET]]/SubscriberIdConditional (xsl:if inside when)
RAW_SUB$subscriber/RawSubscriberIdConditional (xsl:if inside when)
any other valuenothing emittedNo xsl:otherwise

ns:offer_name — Two-way xsl:choose on $paramOfferName:

$paramOfferNameOffer Filter XPathCondition
PriceplanSubscriberOffers[ExtendedInfo[FE_OR_CCBS=FE] and ServiceType='80']/OfferNameConditional (xsl:if inside when)
any otherSubscriberOffers[contains(SocProperties,'TR_CONTRACT_IND=Y') and ExtendedInfo[FE_OR_CCBS=FE]]/OfferNameConditional (xsl:if inside otherwise)

ns:offer_activity_date — Three-way priority xsl:choose:

PriorityConditionValue
1 (highest)exists(SubscriberOffers[FE_OR_CCBS=FE and ServiceType=80 and ExtendedInfo[Name="OfferOriginalEffectiveDate"]/Value])concat(tib:parse-date("yyyy-MM-dd", OfferOriginalEffectiveDate), ' 00:00:00')
2exists(OrderData[ExtendedInfo[Name='CANCEL_TYPE' and Value='endbill']])concat(tib:parse-date("yyyy-MM-dd", $orderRequest/OrderData/EffectiveDate), ' 00:00:00')
3 (default)otherwiseconcat(tib:format-date('yyyy-MM-dd', current-date()), ' 00:00:00')
Priority 1 checks ServiceType=80 (Priceplan offer) regardless of whether paramOfferName is set to "Priceplan". This means a Priceplan offer date is always preferred over an endbill or current date, even in non-Priceplan cancellation scenarios. Verify this is intentional.

ns:offer_expire_date — Double conditional (MAP_PP_EXPIRE=Y):

if ($mapPPExpire = "Y") {
    // Look up ParameterInfo — NOTE trailing space in ParamName!
    SubscriberOffers[OfferName="RMVX00000000001" and ExtendedInfo[FE_OR_CCBS=FE]]
        /ParameterInfo[ParamName="TR_ORIG_CONTRACT_EXPIRE_DATE "]  // ← trailing space [MEDIUM BUG]
        /ValuesArray
}
[MEDIUM] The XPath predicate ParamName="TR_ORIG_CONTRACT_EXPIRE_DATE " contains a trailing space. If the actual stored ParamName value is "TR_ORIG_CONTRACT_EXPIRE_DATE" (no trailing space), this predicate will never match and offer_expire_date will never be emitted even when MAP_PP_EXPIRE=Y. This is a silent failure — no error, just a missing field. Verify against actual CCBS data before migration.

rule Rules.OMConsumers.OMXFM.Request.Request_MCS_CANCEL_AFTER_SALE {
    attribute { priority = 5; forwardChain = true; }
    declare {
        Concepts.OrderRequest.OrderRequest orderRequest;
        Concepts.OM.ProcessConfig.Activity orderCurrentActivity;
    }
    when {
        orderCurrentActivity@extId == orderRequest.ProcessFlow.NextActivityName;
        orderCurrentActivity.ActivityID == "MCS_CANCEL_AFTER_SALE";
        orderRequest.ProcessFlow.NextActivityID == "MCS_CANCEL_AFTER_SALE";
        orderCurrentActivity.Status == "WAITING";
    }
    then {
        boolean isActResub = (orderCurrentActivity.RequestCount > 0 && orderRequest.IsOrderResubmitted);
        try {
            Concepts.OM.ProcessConfig.Activity nextAct = Instance.getByExtIdByUri(...);
            int iPOULen = orderRequest.OrderData.Customer.ParentOU@length;
            String pouRefId = "";
            boolean isSkipped = true;

            for (int i=0; i<iPOULen; i++) { // ParentOU loop
                pouRefId = orderRequest.OrderData.Customer.ParentOU[i].RefId;
                int iSubscriberLen = orderRequest.OrderData.Customer.ParentOU[i].Subscriber@length;
                for (int j=0; j<iSubscriberLen; j++) {
                    Concepts.OrderRequest.OrderElements.Subscriber subscriber = ...;
                    String refId = subscriber.RefId;
                    // Resubmit skip check (CompletionStatus==2)
                    boolean reqSuccess = false;
                    for (int iResp=0; iResp<orderCurrentActivity.Response@length; iResp++)
                        if (String.equals(Response[iResp].ReferenceId, refId) && Response[iResp].CompletionStatus==2)
                            reqSuccess = true;
                    if (!reqSuccess) {
                        String chkRes = "true";
                        if (String.length(nextAct.PreExecCheck) > 0) {
                            String sXML = RuleFunctions.Helpers.GetXMLForSubscriber(orderRequest, refId);
                            chkRes = XPath.execute("/("+nextAct.PreExecCheck+")", sXML, "ns0=...");
                        }
                        if (String.equals(chkRes, "true")) {
                            // Activity param reads — note singular vs plural function names
                            String oldMsisdnFlag = RuleFunctions.Helpers.GetActivityParamValueFromKey(orderCurrentActivity, "oldMsisdnFlag");
                            boolean isShareplanMainNumber = XPath.evalAsBoolean("not(exists(subscriber/ExtendedInfo[Name='SHAREPLAN_MAIN_NUMBER' and Value!='']))");
                            String paramOfferName   = RuleFunctions.Helpers.GetActivityParameterValueFromKey(orderCurrentActivity, "OFFER_NAME");
                            String useRowIdCrmParam = RuleFunctions.Helpers.GetActivityParameterValueFromKey(orderCurrentActivity, "USE_ROWID_CRM");
                            String subIdCrm         = RuleFunctions.Helpers.MapSubscriberIdFromCRM(subscriber, useRowIdCrmParam);
                            String mapPPExpire      = RuleFunctions.Helpers.GetActivityParameterValueFromKey(orderCurrentActivity, "MAP_PP_EXPIRE");
                            String mapOldSub        = RuleFunctions.Helpers.GetActivityParameterValueFromKey(orderCurrentActivity, "MAP_OLD_SUB");
                            String msisdn           = subscriber.MSISDN;

                            /* Build ns:CancelAftersaleRequest event — see §9.8 for full XSLT:
                               10 params: orderRequest, refId, oldMsisdnFlag, subscriber, subIdCrm,
                               isShareplanMainNumber, mapOldSub, msisdn, paramOfferName, mapPPExpire
                               Key outputs: ns:msisdn (swap or direct), ns:old_msisdn (conditional),
                               ns:subscriber_id (conditional), ns:activity_reason, ns:account_id="",
                               ns:isShareplanMainNumber, ns:old_subscriber_id (3-way choose),
                               ns:offer_name (2-way choose), ns:offer_activity_date (3-way priority),
                               ns:order_type, ns:order_type_name, ns:offer_expire_date (trailing-space bug) */
                            Events.OMConsumers.OMXFM.Request.MCS_CANCEL_AFTER_SALE reqEvent =
                                Event.createEvent("xslt://{{/Events/OMConsumers/OMXFM/Request/MCS_CANCEL_AFTER_SALE}}...");
                            Event.Ext.sendEventImmediate(reqEvent);

                            long pid = System.nanoTime();
                            /* Audit logger: OPERATION_NAME="MCS_CANCEL_AFTER_SALE", PROCESS_ID=pid+"_REQ" */
                            Event.Ext.sendEventImmediate(Event.createEvent("xslt://{{/Events/OMConsumers/OMXESB/Logger}}..."));
                            if (!isActResub) orderCurrentActivity.RequestCount++;
                            isSkipped = false;
                        }
                    }
                }
                // ChildOU loop — identical logic; isShareplanMainNumber XPath uses i,p,q indices
            }
            if (!isSkipped) {
                orderCurrentActivity.Status = RuleFunctions.Helpers.GetActivityStatusString("1", false);
                RuleFunctions.Helpers.SendDataToDB(orderRequest);
            } else {
                RuleFunctions.Helpers.SkipActivity(orderRequest, orderCurrentActivity, "4");
            }
        } catch (Exception ae) {
            RuleFunctions.Helpers.HandleActivityException(orderRequest, orderCurrentActivity, ae, "");
        }
    }

§19 — Response Message Rule

§19.1 — Overview

Response_MCS_CANCEL_AFTER_SALE handles the MCS CancelAftersale response. It creates a ResponseBase record, appends it to the activity Response array, emits a response audit log, and evaluates the fan-in completion condition. Unlike MCS_GET_PACKCODE, this response handler performs no additional subscriber state enrichment — it simply records the result and drives completion.
