§1 — Process Overview

Prepaid change-of-ownership flow. First retrieves the SOURCE subscriber's current asset/component data from CRM, then checks whether the customer's identification has changed (OMX_SYNCE_IDENTIFICATION ★ writes the CHANGE_IDENTIFICATION flag). Then executes a two-step CRM order sequence: Disconnect the old owner (orderType=D, command=DisChangeOwnerShip) → upsert new customer account → update status → New ownership order (orderType=N, command=NewChangeOwnerShip). Finally, if identification changed, queries MCS for the new pack code and optionally cancels after-sale packages.

§3 — Conditional Execution Rules (PreExecCheck)
Step 8 — MCS_GET_PACKCODE  FM: MCS_GET_PACKCODE 
boolean(//Customer/ExtendedInfo[Name='CHANGE_IDENTIFICATION' and Value='Y'])

Only retrieves pack code from MCS when CHANGE_IDENTIFICATION=Y, written by step 3 (OMX_SYNCE_IDENTIFICATION ★). Skipped when identification has not changed.

Step 9 — MCS_CANCEL_AFTER_SALE  FM: MCS_CANCEL_AFTER_SALE 
boolean(//Subscriber[ExtendedInfo[Name='MCS_CANCEL_AFS' and Value='Y']])
and boolean(//Customer/ExtendedInfo[Name='CHANGE_IDENTIFICATION' and Value='Y'])

Cancels after-sale packages in MCS only when both conditions hold: subscriber has MCS_CANCEL_AFS=Y AND identification has changed. Parameter USE_ROWID_CRM=Y.
